## 3. 错误码字典（单一权威源）

### 3.1 文件位置

`apps/web-antd/src/views/ipd/_shared/ipd-error-text.ts`

### 3.2 结构

```
IPD_COMMON_CODE_TEXTS     # 13 个跨域通用错误码
IPD_DOMAIN_DEFAULTS       # 4 个域专属覆写（bid/project/portal/ai_document）
ipdErrorText()            # 主入口：错误对象 → 中文文案
withCodeTextOverrides()   # 页面级覆写工厂
isTransportError()        # 区分网络异常与业务拒绝
```

### 3.3 错误码扩展流程（必须遵循）

1. 后端 `ApiV1ErrorCode` 加新数字码 → 同步 `_shared/ipd-error-text.ts` 加 key + 默认文案
2. 页面级专属文案：调用 `withCodeTextOverrides({ code: '页面专属文案' })`
3. 域级覆写：在 `IPD_DOMAIN_DEFAULTS[<domain>][code]` 加 key（影响该域所有页面）
4. **禁止**在 `views/ipd/<domain>/<domain>-error.ts` 或 `api/ipd/*.ts` 自建新表（已有 bid-error/project-error 是 deprecated 薄壳，新代码不得引入新内联表）

## 4. API 客户端

### 4.1 命名规范（统一）

| 类别 | 规范 | 违反示例 |
|---|---|---|
| 列表查询 | `listXxx(keyword?, opts?)` 同步；分页用 `pageXxx(req)` 异步 | ❌ `getXxxList` / `xxxList` |
| 单条查询 | `getXxx(id)` | ❌ `fetchXxx` / `loadXxx` |
| 创建 | `createXxx(input)` | ❌ `addXxx` / `newXxx` |
| 更新 | `updateXxx(id, input)` 或 `changeXxxStatus(id, status)` 视操作粒度 | ❌ `editXxx` / `modifyXxx` |
| 删除 | `deleteXxx(id)` 或 `archiveXxx(id)`（软删） | ❌ `removeXxx` |

### 4.2 共享基类

`apps/web-antd/src/api/ipd/http.ts`（`ipdGet` / `ipdPost` / `ipdDelete` 封装）—— 强制走 `IpdRequestError`（在 `api/ipd/auth.ts` 声明）。禁止绕过基类直接 `fetch`。

### 4.3 双导出治理（drift #2 修法）

- 同端点 + 多类型导出 = **禁止**（曾是 product.ts vs product-group.ts 双导出 listProductGroups，9d15a96 修复为 product-group.ts 转 @deprecated re-export）
- 守护：同名函数 grep 自检 + 禁止 `export function listProductGroups` 出现在 `api/ipd/<非主域>.ts`

## 6. 一致性 CI 检查（建议实施）

### 6.1 自检脚本骨架（草稿）

```bash
#!/usr/bin/env bash
# scripts/check-ipd-frontend-drift.sh
# 检查禁止的内联 code→text 表

set -euo pipefail
ROOT="$(cd "$(dirname "$0")/.." && pwd)"
APP="$ROOT/apps/web-antd"

# 1. 检查禁止的内联 IPD_ERROR_TEXTS / *_CODE_TEXTS / *_ERROR_TEXT
echo "→ 检查内联错误码表..."
if grep -rn "IPD_ERROR_TEXTS\s*:\s*Record<number, string>\|PORTAL_ERROR_TEXT\s*:\s*Record<number, string>\|BID_CODE_TEXTS\s*:\s*Record<number, string>\|PROJECT_CODE_TEXTS\s*:\s*Record<number, string>" "$APP/src/views/ipd" "$APP/src/api/ipd"; then
  echo "❌ 发现内联错误码表，迁移到 _shared/ipd-error-text.ts"
  exit 1
fi

# 2. 检查 listProductGroups 双导出
echo "→ 检查 listProductGroups 唯一性..."
COUNT=$(grep -rln "export function listProductGroups" "$APP/src/api/ipd" | wc -l | tr -d ' ')
if [ "$COUNT" -ne 1 ]; then
  echo "❌ listProductGroups 应只导出 1 次（实际 $COUNT 次）"
  exit 1
fi

# 3. 检查 BackendPending 使用率（占位页必须有 meta）
echo "→ 检查占位页 BackendPending meta..."
PLACEHOLDER_PAGES=$(grep -rln "BackendPending\|占位\|TODO" "$APP/src/views/ipd" | wc -l | tr -d ' ')
if [ "$PLACEHOLDER_PAGES" -lt 10 ]; then
  echo "⚠️ BackendPending 引用 < 10 处，当前 $PLACEHOLDER_PAGES（drift #3 未根治）"
fi

echo "✅ 一致性自检通过"
```

### 6.2 TypeScript 规则

`apps/web-antd/tsconfig.json` 已启用 `strict: true`。新增约束：
- `noUncheckedIndexedAccess: true`（强制 code→text 查表返回 `string | undefined`，防止误用）
- `exactOptionalPropertyTypes: true`（防止 `codeTexts?: undefined` 绕过类型）
