## 4. G2/P10放行与G4结果门禁

同一项目的计划检查和上市结果检查必须有独立的业务阶段与证据状态，不能只保存一个跨阶段共用的`certificationComplete`布尔值。

1. **计划评审**：G2-6清单不齐或周期冲突可以继续，记录缺什么、责任人、补充/纠偏计划和跟踪期限；该记录不宣称证书已取得。
2. **计划→开发出口**：门禁扫描必须识别同一项目、同一P10规划缺口，不能因P10仍未完成、旧`isBlocking=Y`或同源遗留项而重新拒绝本次已允许的转换。不是把所有P10或全阶段门禁全局关闭；G2其他四项否决、有效PRD和里程碑要求仍逐项生效。
3. **后续过程**：G3按认证进度登记风险和跟踪，不把G2的规划遗留再转换成G3否决。普通有条件项仍有责任人/期限；G2-6规划遗留必须标识为当前阶段非阻断，不能自动套用“未关闭不准下个Gate”再次制造硬卡。
4. **上市前**：V02认证验证与G4-1/G4-6按目标市场的实际取得/通过结果评审；证书编号、通过日期和对应市场可追；不能将“清单已填”“有计划”“G2已过”当作实际结果。原轻管V02不要求额外强制证书扫描件，不趁本卡扩大附件规则。
5. **拒绝和恢复**：G4结果不足时保留项目阶段与全部既有业务记录，提示具体未满足结果；补足后重新评审，旧G2放行记录仍保留。不能删除旧缺口或改写历史记录制造合格。

G1生物特征合规、已知不可逾越认证障碍未被决策1取消。本条仅落实用户针对G2计划清单/周期的放行，不进行真实生产变更或外部法规判断。

## 5. 参数与配置快照语义

以下是待实现的工程数据合同，字段名称说明语义，不表示现有数据库已含这些字段。已有参数名保留；新业务字段由实现卡按本项目类型映射落地。

### 5.1 毛利门槛

- 逻辑键沿用`gate.grossMarginThreshold`；单位为**百分数**，`18.5`表示18.5%，不是0.185。金额/成本计算与百分比转换使用Decimal/BigDecimal，不用浮点等值或提前取整。
- `projectOverride`有效时优先；否则读取项目明确绑定的`defaultRef`，其来源是模板或产品线之一。两个默认来源并存时不得依查询顺序随机选；项目记录必须保存明确来源引用。新增项目也可直接配置项目值，不要求先编造全局默认。
- 每个可生效配置需有十进制值、单位、允许最小/最大值、适用项目/默认范围、版本、生效时点及操作审计。**允许范围由该配置的业务约束明确给出，本合同不擅定统一毛利上下限**；缺范围/值、非法数值或超出批准范围均不激活。模板/产品线没有初值时也不填40/30/25或0。
- G1-5和G2-4通过同一逻辑解析器读取项目值，评审发起时保存值及来源版本快照。新配置对生效后的新评审适用；既有在途/已归档评审不静默改值。确需更正按重新发起评审/配置审计保留新旧链，不能覆盖旧结论。
- **实际负毛利**仍触发G1-5已有否决，不因项目门槛被调低而消除该原因。G2-4低于门槛且无调整方案才命中该项否决；经评审的调整方案允许有条件处理，但缺门槛不能通过“先通过后补配置”绕开。

### 5.2 90日预警与其他阈值

- 90日回款预警可采用工程逻辑键`gate.g5.receiptWarningPercent`，默认`25`，单位百分数，允许有限且非负的十进制值；不把100当绝对上限，因为业务可配置超额目标。此键名为工程命名建议，不声称已落库。
- 分母为有效立项目标，分子为L08起90日实际回款；数据/分母缺失时待补充，不填0、不输出伪达成率。比较采用`rate < warningPercent`，**等于阈值不触发该预警**。低于线需原因与改进计划；不能由预警事件创建奖金资格取消、停产或奖金终算结果。
- 默认25来自本次决策4；其他既有数值（G1客户5/意向1、G3偏差5工作日/变更15与12/成本5、G4渠道60/培训80/客户10/P1上限3、G5覆盖50/偏差5个百分点）来自对应33行原文，应配置化并随评审快照；本合同没有替用户新增一组S/A/B毛利数值。
- G3连续两次P0未升级：按同项目、时间顺序的连续有效双周评审记录判断，重复扫描同一记录不算第二次；两次均有P0且都无升级记录才满足该触发。单次无P0或已升级打断该“连续未升级”条件。生成升级记录与双方组长待办，不能把升级结果写成Gate否决。
- Asia/Shanghai与中国大陆法定节假日/调休补班日历按决策15，由DOC-04/OPS-04落实；不在此另造日历或修改天数。

### 5.3 列席、签权与发起快照

- 项目维护其选择的列席人清单，可从销售/供应/售后/品质/合规模板挑选；不强制每项目固定五人或每类一人。评审快照保留被邀请人、身份、有效时间和参与范围。
- 列席者可提供意见，但不能因被添加而调用签署/代签。本人另有合法业务签权时，按该签权而非列席身份授权；不能通过列席赋予跨组访问或新增“评审上级”角色。
- 既定升级：第3轮起双方产品组长列席、第5轮超管介入，仍然生效；项目列席选择不能删除这些既定参与要求。介入不等于替代双PM签名；仲裁/终裁是独立有审计的事件。
- 按节点明确签署人、主导方与角色归属，在评审开始前检查配置并锁定。缺有效主导/签署配置保持待配置，不能以首位提交人作为默认主导。配置名称、访问控制与接口约定交由DOC-02/06实现。
