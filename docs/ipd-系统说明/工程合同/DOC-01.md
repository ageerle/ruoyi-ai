## 3. 数值、单位与来源合同

### 3.1 奖金计算输入

| 值 | 表示与单位 | 来源及约束 |
|---|---|---|
| 目标销售额 T | 精确十进制人民币元；500万表示 `5000000` | C08 立项目标，G1后锁定；算率时 T 必须 >0，不用实际回款替代基数 |
| 有效回款 R | 与 T 同币种同单位的精确金额 | 默认LC01实际回款及凭证，L08起6自然月；窗口内退款冲减、窗口外不追扣；预收例外依V3:787保留，不简化成仅按到账日过滤 |
| 回款比 q / 达成率 r | q=R/T；r=q×100，r 的单位为**百分数** | `q=0.70` 与 `r=70` 相同；入阶梯用 r，不能把0.70直接与70比较。计算不提前截两位 |
| 奖金池提取比例 p | 0～1比例；5%存 `0.05` | `bonus.poolRate`；本合同复算读取显式测试数据，不构成业务硬编码许可 |
| 差异化系数 d | 无量纲：S默认1.5/A固定1.0/B默认0.8 | `bonus.coefficient.*`；S允许[1.5,2.0]、B允许[0.6,0.8]，Q4确认后锁入项目 |
| 个人贡献比例 c | 运算比例0～1；展示百分数 | 市场40%–65%、研发35%–60%；精确相加=1；市场65%时研发35%，市场70%拒绝；五维25/25/20/20/10合计100% |
| 项目绩效分 s / 系数 f | s为0～100分；f为无量纲 | 每个PM独立评分与版本；默认 `PROJECT_SCORE`，映射95/85/70/60五档。f不用于津贴乘法 |

`P=T×p×d；D=P×tier(r)；B_market=D×c_market×f_market；B_rd=D×c_rd×f_rd`。

已知贡献度五维及范围不能推导出五维评分自动转换成最终贡献比例的唯一算法；原文规定联合评定，保留评定证据，不能发明自动换算。不得为“花完池子”重新归一化个人绩效后的金额：算例 A 的24万元个人合计与30万元可分配额不同，原文未规定剩余额再分配。

Java实现需使用 BigDecimal/compareTo、数据库DECIMAL；用户第10项已确认中间精确计算，最终个人金额到人民币分采用 `HALF_UP`（四舍五入）。不得先将回款率、奖金池、贡献金额或个人系数计算结果截成两位再连乘。不能有限表示的比值，比较时可用交叉相乘或精确有理数表示，不用浮点或已舍入展示值决定档位。非有限值、目标≤0、缺关键参数应拒绝；净负回款保留原金额及凭证，终算进入人工核定，不自动按最低档结清或发出负奖金。具体金额及尾差合同见§3.4。

### 3.2 六档的工程 JSON 表示

参数仍为 `bonus.achievementTiers`。下面是工程序列化格式，不改变产品区间；数值用十进制字符串避免消费者先转浮点；`null`表示无界，JSON 不使用 Infinity。`unit` 明确输入单位；`minInclusive/maxInclusive` 分别作用于本项自己的端点。实现检查所有区间，恰好一项命中后返回 multiplier；空匹配或多匹配视为无效配置并拒绝计算。

```json
{
  "unit": "PERCENT",
  "tiers": [
    {"min":"120","minInclusive":false,"max":null,"maxInclusive":false,"multiplier":"1.2"},
    {"min":"100","minInclusive":true,"max":"120","maxInclusive":true,"multiplier":"1.0"},
    {"min":"85","minInclusive":true,"max":"100","maxInclusive":false,"multiplier":"0.8"},
    {"min":"70","minInclusive":true,"max":"85","maxInclusive":false,"multiplier":"0.6"},
    {"min":"50","minInclusive":true,"max":"70","maxInclusive":false,"multiplier":"0.3"},
    {"min":null,"minInclusive":false,"max":"50","maxInclusive":false,"multiplier":"0"}
  ]
}
```

数学区间覆盖全部有限 r；业务终算在入档前单独检查净负回款并转人工核定，最后一档不授权自动结清。真实零回款在其他输入齐全时按0档计算。85%～99.99%的旧显示文字应解释成 `[85,100)`，因此99.999%也为0.8；不能把100.001%向两位取整后再比较。后续 P0-3.1/P3-4.3 应检验区间完整、顺序、开闭、重复及空配置；本文件未修改实际参数表。

### 3.4 最终个人金额、尾差与人工核定

## 4. KPI 数据来源字典与评分隔离

### 4.1 共担权重原分及功能评分

功能四项各占全体15%（合计60%）；共担15/10/10/5（合计40%），由产品组长录入复核，双PM共担同分。用户第8项明确直接按各项权重分计分。定义 `clamp(x,a,b)=min(b,max(a,x))`；r为实际回款达成**百分数**，h为渠道达成百分数，n为实际NPS，t为已配置NPS目标，v为场景实际数/目标数的比例：

| 项 | 精确公式 | 边界与算例 |
|---|---|---|
| W1，满分15 | r<50时为0；否则 `clamp(15−max(0,100−r)/5,0,15)` | r=80→11；97.5→14.5；50→5；49.999→0；超过100→15。<50的跳变是原定例外 |
| W2，满分10 | `clamp(10−max(0,100−h)/5,0,10)` | h=75→5；97.5→9.5；0→0；超过100→10 |
| W3，满分10 | `clamp(10−max(0,t−n)/5,0,10)` | **仅作显式测试输入**t=40、n=35→9；n=37.5→9.5；n=50→10。目标并非默认40，缺目标/有效样本<30均待补充 |
| W4，满分5 | `clamp(5×v,0,5)` | 3/4→3.75；覆盖超过目标→5；目标0/缺失不计分并待补充；负计数属于非法来源数据，不借限幅放行 |

不足5个百分点/5个NPS分按实际差额比例扣分，不向上/向下取整扣分次数。各项限幅0至满分，超目标不另加奖励。W1净负回款可保留原始值并按<50记0；这项KPI评分不使奖金终算绕过§3.4的人工核定。

四项有效功能评分各为0～100时，功能分类分 `F=(f1+f2+f3+f4)/4`；四项的全体权重贡献等价于 `Σfi×0.15`。共担原分 `W=W1+W2+W3+W4`，范围0～40；项目对应期间的综合分 `S=F×0.6+W`，范围0～100。仅在显示共担百分制时取 `W/0.4`；不得再将W乘0.4。当前合同按已确认60/40及15/10/10/5计算，实际配置仍须校验，不凭权重可配置就发明另一套扣分曲线。

例：F=80，r=80、h=75、NPS目标40/实际35/有效30份、场景3/4，则W=11+5+9+3.75=28.75，显示共担71.875，综合76.75。原AC-KPI-04的“功能80、共担70”是两个百分制分类分，等价W=28，综合仍为76。四项共担与功能均满分时结果100。

统一量表必须包含适用指标/期间、原始值与单位、证据要求、评分含义/范围、审批版本和生效范围。具体阈值/曲线未配置时可以提取原始值、生成待办及保存证据，不能自动填0、编造量表、重分配缺项权重或标记考核已完成。人工评分也必须通过量表版本、组长权限和证据检查；未批准曲线不启用自动评分。缺项为待补充不等于0分，也不等于免考。

## 8. 可重复的独立计算与验收

下面 Python 使用标准库：执行路径从本合同JSON解析配置，以 Decimal 比较；独立参考路径用 Fraction 的低到高分支和固定原文期望复算。它不调用任何业务实现，不证明 HTTP/DB/权限/发放已完成。JSON和下述代码可直接从本文提取运行；原始结果由协调批次保存到 `.codex/ruflo/swarm-20260905/doc01/`。

```python
import copy
import json
import re
from decimal import Decimal as D
from fractions import Fraction as F
from pathlib import Path

doc = Path('docs/ipd-系统说明/工程合同/DOC-01.md').read_text()
cfg = json.loads(re.search(r'```json\n(.*?)\n```', doc, re.S).group(1))
checks = []

def check(test_id, actual, expected):
    assert actual == expected, (test_id, actual, expected)
    checks.append({'id': test_id, 'actual': str(actual), 'expected': str(expected)})

def tier(raw, config=cfg):
    x = D(raw)
    if not x.is_finite() or config['unit'] != 'PERCENT':
        raise ValueError('non-finite input or wrong unit')
    matches = []
    for row in config['tiers']:
        lo, hi = row['min'], row['max']
        lower = lo is None or (x >= D(lo) if row['minInclusive'] else x > D(lo))
        upper = hi is None or (x <= D(hi) if row['maxInclusive'] else x < D(hi))
        if lower and upper:
            matches.append(D(row['multiplier']))
    if len(matches) != 1:
        raise ValueError('gap or overlap')
    return matches[0]

def reference_tier(raw):
    r = F(raw)
    if r < 50: return F(0)
    if r < 70: return F('0.3')
    if r < 85: return F('0.6')
    if r < 100: return F('0.8')
    if r <= 120: return F(1)
    return F('1.2')

def rejected(test_id, call):
    try:
        call()
    except ValueError:
        check(test_id, 'rejected', 'rejected')
    else:
        raise AssertionError((test_id, 'accepted unexpectedly'))

def rate(actual, target):
    a, t = D(actual), D(target)
    if not a.is_finite() or not t.is_finite() or t <= 0:
        raise ValueError('invalid rate input')
    return a / t * 100

fixtures = [
    ('T50-', '49.99', '0'), ('T50=', '50', '.3'), ('T50+', '50.01', '.3'),
    ('T70-', '69.99', '.3'), ('T70=', '70', '.6'), ('T70+', '70.01', '.6'),
    ('T85-', '84.99', '.6'), ('T85=', '85', '.8'), ('T85+', '85.01', '.8'),
    ('T100-', '99.99', '.8'), ('T100=', '100', '1'), ('T100+', '100.01', '1'),
    ('T120-', '119.99', '1'), ('T120=', '120', '1'), ('T120+', '120.01', '1.2'),
    ('T0', '0', '0'), ('T45', '45', '0'), ('T60', '60', '.3'),
    ('T75', '75', '.6'), ('T90', '90', '.8'), ('T110', '110', '1'),
    ('T120.1', '120.1', '1.2'), ('T130', '130', '1.2'), ('T99.999', '99.999', '.8')
]
for test_id, value, expected in fixtures:
    check(test_id, tier(value), D(expected))
    check(test_id + '-REFERENCE', F(tier(value)), reference_tier(value))
for i in range(0, 20001):
    value = str(D(i) / 100)
    assert F(tier(value)) == reference_tier(value), value
check('CFG-COVERAGE', '20001 points 0..200 step .01', '20001 points 0..200 step .01')
check('CFG-SERIALIZE', json.loads(json.dumps(cfg, allow_nan=False)), cfg)
gap, overlap = copy.deepcopy(cfg), copy.deepcopy(cfg)
gap['tiers'][1]['min'] = '101'
overlap['tiers'][0]['minInclusive'] = True
rejected('CFG-GAP', lambda: tier('100', gap))
rejected('CFG-OVERLAP', lambda: tier('120', overlap))
rejected('INPUT-NAN', lambda: tier('NaN'))
rejected('INPUT-INFINITY', lambda: tier('Infinity'))
rejected('DENOMINATOR-ZERO', lambda: rate('100', '0'))
rejected('DENOMINATOR-NEGATIVE', lambda: rate('100', '-1'))

legacy = [('Infinity','1.2'),('120','1'),('85','.8'),('70','.6'),('50','.3'),('0','0')]
for raw, wrong in [('100','.8'), ('130','1')]:
    found = next(D(m) for t, m in legacy if D(raw) >= D(t))
    check('CFG-LEGACY-' + raw, found, D(wrong))
    assert found != tier(raw)

pool = D('5000000') * D('.05') * D('1.5')
check('A-POOL', pool, D('375000'))
check('A-DISTRIBUTABLE', pool * tier('90'), D('300000'))
for test_id, r, contribution, performance, expected in [
    ('A-M','90','.55','.8','132000'), ('A-R','90','.45','.8','108000'),
    ('B-M','130','.55','1','247500'), ('D-120','120','.55','1','206250'),
    ('D-120.1','120.1','.55','1','247500')
]:
```
