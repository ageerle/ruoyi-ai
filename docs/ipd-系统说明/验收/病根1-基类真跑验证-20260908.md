## 3. 根因：4 条结构性障碍（静态取证 + 运行时实证一致）

| # | 障碍 | 实证 |
|---|---|---|
| 1 | **ruoyi-ipd test 域够不到 `@SpringBootConfiguration`** | `@SpringBootApplication` 只在 `ruoyi-admin/RuoYiAIApplication`（主 app）+ `ruoyi-extend/{monitor-admin,snailjob-server}`；`ruoyi-ipd/pom.xml` **不依赖 ruoyi-admin**（ipd 是 admin 的下游库），test classpath 里没有它 → Spring Boot 从 `org.ruoyi.ipd.integration` 逐级上搜找不到配置类 |
| 2 | **无 test 配置资源** | `ruoyi-ipd/src/test/resources/` **不存在**；`src/main/resources/` 只有 `db/`，无 `application*.yml` |
| 3 | **`ipd-local` profile 加载不到** | 真库配置 `application-ipd-local.yml` 只在 `.codex/ipd-dev/config/`（gitignored，**classpath 外**）→ `@ActiveProfiles({"ipd-local","dev"})` 在 test 里加载不到真库 datasource |
| 4 | **强依赖 Redis** | `ruoyi-ipd/pom.xml` 有 `ruoyi-common-redis`（Redisson + Sa-Token 会话存储）→ 起容器必连 Redis；`session.login()` 签 token 也依赖它 |

> 补充：整个 ruoyi-modules 里**只有 IpdIntegrationTestBase 一处真 `@SpringBootTest`**，其余全部显式回避（`Api01AcceptanceTest`「不需 @SpringBootTest」、`BuiltinToolRegistryTest`「ruoyi-chat 暂无 @SpringBootTest 范式」）。**本仓从未有过成功启动的 @SpringBootTest 先例可抄**。

## 4. 修复方向（3 选 1，待用户拍板；均超出「写个示例测试」范围，涉及共享构建 + 外部服务 + 凭据决策）

### 方向 A：在 ruoyi-ipd 内自建 test 基建
- 新建 `ruoyi-ipd/src/test/java/org/ruoyi/ipd/IpdIntegrationTestApplication.java`（`@SpringBootApplication` 扫 `org.ruoyi.ipd` + 靠 ruoyi-common-* 自动配置）
- 新建 `ruoyi-ipd/src/test/resources/application-ipd-local.yml`（datasource→13306/ipd_dev + Redis + Sa-Token；**凭据走 env / 外部 gitignored 配置，不硬编码入库**）
- **风险**：Sa-Token 配置、动态数据源、MyBatis-Plus、Jackson 包络等框架 bean 多在 `ruoyi-framework`/`ruoyi-admin`，ruoyi-ipd 不依赖 → 大概率要加 test-scope 框架依赖（**动 pom.xml = 兄弟会话风险 + 违反单一写入者**）；逐个补配置是多轮 whack-a-mole
- **成本**：高（本仓第一个 @SpringBootTest，无先例）

### 方向 B：把集成测试挪到 ruoyi-admin 模块（架构更正）
- `ruoyi-admin` 是 `RuoYiAIApplication` 所在、全量 bean 已接线的**应用模块**；full-app 真活集成测试天然属于这里，而非库模块 ruoyi-ipd
- 新建 `ruoyi-admin/src/test/`（当前**不存在**）+ 把 `IpdIntegrationTestBase` / `HandoverIntegrationTest` 迁过去 + test yml
- **风险**：同样需 Redis/真库运行态 + 凭据处理；需确认 ruoyi-admin test 域能加载 `.codex/ipd-dev/config/application-ipd-local.yml`（外部路径）
- **成本**：中高（但架构上最干净，一次接线后续所有 IPD 真活集成测试都复用）

### 方向 C：保持 @Disabled，登记为独立卡，本轮不建基建（推荐）
- 示例测试 + 本验证报告已把「基类不能真跑」的根因钉死，价值已交付
- 真活基建（A 或 B）是独立工程，涉及 pom / Redis / 凭据 / 单一写入者，应作为**受控范围的专卡**由主协调会话串行推进，不在本轮擅自扩大
- **成本**：低
