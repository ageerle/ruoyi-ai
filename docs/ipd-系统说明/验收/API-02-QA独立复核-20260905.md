## 四、风险评估

| 风险等级 | 描述 |
|---------|------|
| **高** | CertTemplateController.create() 直接接收原始 domain 对象，客户端可注入 id/tenantId/delFlag/createTime 等字段，违反 API-02 核心安全要求 |
| **中** | 4 个 DTO record 缺少 JSR-303 校验注解，依赖外部 IpdRequestValidation（**本仓不可核验**），校验逻辑不内聚，维护困难 |
| **低** | DtoWhitelistTest 覆盖范围有限（3 项），仅验证 @JsonIgnoreProperties 行为，未覆盖字段校验逻辑 |

## 五、结论

**判定**: **KEEP_PARTIAL**

**理由**:
1. 五控制器中仅 4 个完成 DTO 白名单化，CertTemplateController 仍未转换（高优先级 gap）
2. Api02AcceptanceTest 不在本仓，验证命令无法执行（本仓不可核验）
3. DTO 校验注解缺失，输入约束依赖非标准校验机制（IpdRequestValidation 本仓不存在）
4. 卡片自身注记亦承认「其他 4 控制器推广归后续卡」，当前 inreview 状态与实现进度相符

**建议后续动作**:
1. 为 CertTemplateController 补充 `CertTemplateCreateRequest.java` DTO（含 @JsonIgnoreProperties）

3. 将 Api02AcceptanceTest 合入本仓测试目录
4. 执行验证命令确认全量 PASS 后关闭此卡
