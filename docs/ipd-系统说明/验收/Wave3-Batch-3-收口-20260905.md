### 2 项失败根因与修复（commit 67b18014）

| 测试 | 根因 | 修复 |
|---|---|---|
| `ActuatorNarrowTest.parentIncludeNarrowed` | 父 yml line 359 **注释里**含字面 `include: '*'`（描述 dev 覆盖行为的说明文字），被 `doesNotContain` 断言误命中 | 注释改为「显式覆盖为通配全部端点」，消除误导字面量，断言语义不变 |

**教训**：静态 yml 守卫测试的 `doesNotContain` 断言会被「描述性注释里的同形字面量」误触发；写 yml 注释时避免复现被禁字面量。固定窗口切片在段变长后必然脆断，按结构分隔符提取才是稳定锚点。

## 4. 兄弟流覆盖实录（第二次，Batch-3 期间）

20:15 首轮修复注释后 20:18 mvn 全绿；20:18 后兄弟流把工作区 yml 覆盖回 HEAD 版，注释修复丢失。

**定位手段**（[[swarm-batch2-closeout-2026-09-05]] 三点验证法二度命中）：
- `git rev-parse HEAD:path` == `git hash-object path` → 工作区被同步回 HEAD
- `git log --find-object=<旧blob>` → 确认字面量版本来自我自己的 `cb805c5c`
- 结论：修复从未被 commit + 工作区被覆盖 → **重做后立即 commit**（`67b18014`）

**强化守则**：任何修复在验证通过后必须立即 commit，「验证过但未 commit」的状态在蜂群工作树下平均存活 < 5 分钟。
