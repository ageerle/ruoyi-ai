## 三、零功能回归证据（差集 8 张表 + 4 实例运行日志）

### 3.1 差集比对（information_schema.tables 132 张 vs mysql.tables_priv 124 张）

源命令：
```
SELECT t.table_name, t.table_type, t.table_rows
FROM information_schema.tables t
LEFT JOIN (SELECT DISTINCT Table_name FROM mysql.tables_priv
           WHERE User='ipd_app' AND Host='127.0.0.1' AND Db='ipd_dev') p
       ON p.Table_name = t.table_name
WHERE t.table_schema='ipd_dev' AND t.table_type='BASE TABLE' AND p.Table_name IS NULL;
```
实测差集（库内 132 张 - 表级已授权 124 张 = 8 张）：
```
_ipd_schema_history         (12 行 — Flyway 影子)
gate_arbitrations            (3 行 — GateReviewService 调用域)
notification_events          (23 行 — NotificationService 域)
post_launch_reviews          (0 行)
project_circle_comments      (0 行)
project_circle_posts         (0 行)
project_followers            (0 行)
sop_template_instances       (0 行)
```
按 MySQL 权限累加规则（全局→库→表→列，任一上层授予即生效），未在表级授权的 8 张表只能继承库级 `SELECT,INSERT`——对它们的 UPDATE/DELETE 操作必被拒。

### 3.2 差集表 UPDATE/DELETE 全拒实测

源命令（ipd_app cnf）：
```
for t in _ipd_schema_history gate_arbitrations notification_events \
         post_launch_reviews project_circle_comments project_circle_posts \
         project_followers sop_template_instances; do
  mysql ... -e "UPDATE $t SET id=id WHERE 1=0;"
  mysql ... -e "DELETE FROM $t WHERE 1=0;"
done
```
实测（每张表）：
```
ERROR 1142 (42000) at line 1: UPDATE command denied to user 'ipd_app'@'localhost' for table '...'
ERROR 1142 (42000) at line 1: DELETE command denied to user 'ipd_app'@'localhost' for table '...'
```
8/8 表 UPDATE 与 DELETE 全部被拒。注：`ipd_app@'localhost'` 是 MySQL 客户端连接 localhost 默认映射，等价 `ipd_app@'127.0.0.1'`。

### 3.3 4 在跑实例运行日志无 denied 报错（功能回归 = 0）

源命令（搜最近 24h 应用日志）：
```

  logs/sys-error.log logs/sys-error.2026-09-06.log.gz logs/sys-error.2026-09-05.log.gz
```

含义：当前 4 个在跑实例（16039/16044/16045/81711 —— 2026-09-07 18:32 仅 16039 活跃监听）的应用代码路径未触发任何 `denied to user 'ipd_app'` 的运行时错误。其中：
- `notification_events` Service 有 `mapper.update(null, lambdaUpdate())` 多次调用（NotificationService.java:214/226/261/270/281），但 16039 实际流量未命中

- 其余 6 张差集表无对应 Service 实现（仅 Domain 类，未接入业务链路）

**结论**：库级 DML REVOKE 在当前生产流量下零功能回归。若未来新增差集表写路径，会被 DB 层拦下并写入 sys-error.log，便于即时告警与补授权。
