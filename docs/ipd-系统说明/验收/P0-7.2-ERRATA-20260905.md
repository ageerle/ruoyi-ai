### 2.2 Controller 的 catch 块确实会执行

```

80:     Person person = session.currentPerson();

84:         // 失败审计独立事务落库（REQUIRES_NEW），不与业务事务耦合 → 不被回滚

87:                 AuditAttemptService.Outcome.FAILURE, "PASSWORD_CHANGE_REJECTED",

89:         }
90:         throw ex;
91:     }
92:     session.revokeAll(person.getId());
93:     return ApiV1Response.ok();
94: }
```

- catch 子句类型为 `IpdAuthInputException`，与第 112 行抛出类型**完全匹配**，**不是死代码**。
- 失败审计调用 `AuditAttemptService.record(...)`，传入 action = `"PASSWORD_CHANGE_REJECTED"`（grep 全仓唯一匹配位于 IpdAuthController.java:87）。

### 2.3 第 120 行 PASSWORD_CHANGE 审计的真实性

- `audit(personId, name, "PASSWORD_CHANGE")` 调用的是 `IpdAuthService.java:158` 的 `private void audit(Long, String, String)`（grep 结果：单一定义点）。
- 该方法走与 login 失败审计同一条 AuditLogService REQUIRES_NEW 路径（参见文件头注释 `* SEC-AUD-01：失败分支也写审计...`，且 120 行紧接 updateById 之后，事务提交前写入，与 controller 的 92 行 `session.revokeAll` 顺序在 @Transactional 内）。
- "PASSWORD_CHANGE" 字面量与"PASSWORD_CHANGE_REJECTED"是两个不同 action：前者由成功路径写，后者仅在 CURRENT_PASSWORD_INCORRECT 分支写。两者**不冲突**，不互为别名。
