## 1. AC 对照（卡面四条 + 入口校验）

| 卡面要求 | 实现 | 用例 |
|---|---|---|
| 批量移交 3 个项目 ⇒ 逐项目结果明确 | `HandoverService.batchHandover` 返回 `List<BatchHandoverResult>(projectId, status, reason)`，逐项目 COMPLETED/REJECTED/SKIPPED + 原因 | `batchAllCompletedThenDisabled`（3 项目全 COMPLETED + AC-HAND-04 历史零改写断言） |
| 失败项目保持原归属 | `handOverOne` 归属校验：在任绑定者 ≠ 指定原负责人 ⇒ REJECTED（"与指定原负责人不符，保持原归属"），零写库 | `batchPartialFailureKeepsOwnership`（P2 REJECTED、P1/P3 照常 COMPLETED、无禁用审计） |

| 入口校验 | 角色越界整批拒绝（HANDOVER_ROLES 白名单）；from=to 拒绝；空清单返回空结果零写库 | `batchIllegalRoleThrows`、`batchSelfHandoverThrows`、`batchEmptyScopeReturnsEmpty` |

AC-HAND-04 附加断言：`projectMapper` never `updateById`/`deleteById`——项目本体与绑定历史零删除零改写，历史审批/Gate/台账记录完整跟随。

## 2. 实现要点

- `HandoverService` 7 参构造（新增 `PlatformTransactionManager`）：`batchHandover` 方法级 `@Transactional(NOT_SUPPORTED)` 挂起类级事务 → `TransactionTemplate` 逐项目独立事务 → 内层 `initiateOnBehalf`（REQUIRED）加入；单项目异常标 rollback-only 由模板回滚该项目全部写入，批间互不影响。
- `HandoverController` 新增 `POST /batch`（`BatchRequest`/`BatchResultView` record），权限沿用 `requireLeaderOrAdmin` + SEC-REV-HANDOVER-01 同组校验。
- **disableIfAllCleared 缺陷修正（本会话发现并修正）**：兄弟会话 SEC-REV-HANDOVER-02 的原子 UPDATE 版方向反转——`updated>0` 才禁用导致"移交任一项目即提前退掉其余绑定并禁用"，违反 AC-HAND-01d 与本卡"不得提前禁用"。修正为 FOR UPDATE 锁行 selectList 计数版：保留 TOCTOU 防护意图，语义回归"仅计数=0 才 DISABLED"。
