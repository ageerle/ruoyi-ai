## 关键发现与遗留

### F-1（建议关注）entity↔真库表名 单复数差异

- 51 个 entity 类（单数：`gate`、`bonus_pool`、`audit_log`...）vs 真库表（复数：`gates`、`bonus_pools`、`audit_logs`...）
- **不是 schema 缺失**——是命名约定差异
- 影响：所有用 `@TableName("xxx")` 显式标注的代码 OK；自动推断（驼峰转下划线）的代码需 `MybatisPlus` 全局配置 `table-underline: true` 配合 `naming: snake_case` 兜底
- **建议**：后续 schema 一致性脚本按"单数 entity → 复数表名"规则集做归一

### F-2（真实状态）大部分业务表 0 行

- `gates / gate_reviews / kpi_records / bonus_pools / bonus_allocations / contributions / project_score_records / deletion_requests` 全部 0 行
- 兄弟流 ROOT-R 验证卡只跑了基础链路（projects、stages、stage_actions），未生成 Gate / KPI / 奖金池 / 删除请求
- **结论**：业务完整链路**端到端可走通**（API 都返回 200 + 正确 schema），但**业务数据完整度需后续业务流补齐**

### F-3（设计正确）AI generate 无配置即 50002

- `AiGenerationService` 第 110 行明确"无配置 → STATE_CONFLICT"——这是**正确业务行为**
- 当前 `ai_model_configs` 表 0 行，符合 P4-2.1「无生效模型则拒绝生成」约束
- **未在 dev 环境中预置任何 AI key**（与「演示模式 + 不可用 key」配套设计）

### F-4（踩坑沉淀）IPD 鉴权 5 雷区

1. 鉴权头必须 `Bearer` 前缀（与基线 `sys_user` 不一样）
2. 密码表是 `persons.password_hash`（不是 `sys_user.password`）
3. BCrypt 前缀需 `$2a$10$`（不是 `$2b$`——`hutool-crypto` 严格匹配）
4. Redis 限流键 `ipd-local:000000:pwd_err_cnt:<username>` 需手动清理
5. `/api/v1/bonus-pool/list` 等强制要求 `projectId` 必填 query

### F-5（与兄弟流协作）人话

- 兄弟流持续重置 `persons.password_hash`（可能用别的工作流）
- 兄弟流周期性 kill+restart 后端（PID 65503）
- 兄弟流（另有 ROOT-R agent）也在写 `ai_documents`
