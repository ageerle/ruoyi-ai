## 5. 缺陷详节

### DEF-1 Gate 评审要素创建 100% 失败：审计 after_data 非 JSON → 500 + 事务回滚（本轮独有新发现）

- **现象**：SUPER_ADMIN `POST /api/v1/gate-elements` 合法 body → HTTP 500/90001，**表中无任何新要素、audit_logs 无 GATE_ELEMENT 行**（累计=0）。即该接口上线以来从未成功写入过。
- **根因**：`GateElementService.create`（`GateElementService.java:51`）调用 `audit(...)`（`GateElementService.java:105`）把**纯文本**写入 `audit_logs.after_data`——该列是 **MySQL JSON 类型**，MySQL 拒绝非 JSON 字面量：

  ```
  MysqlDataTruncation: Data truncation: Invalid JSON text: "Invalid value." at position 0
    in value for column 'audit_logs.after_data'.
    at org.ruoyi.ipd.service.GateElementService.audit(GateElementService.java:105)
    at org.ruoyi.ipd.service.GateElementService.create(GateElementService.java:51)
  ```

  审计与业务同事务 → 抛出后 insert 一并回滚（这同时解释了为何该路径审计恒 0 行，与 mock 单测 Mock 掉 auditLogService 后全绿不矛盾——Mock 绿 ≠ HTTP 闭环）。
- **修复建议**：`GateElementService.audit` 改用 `JSON_OBJECT`/Jackson 序列化后写入（与 P0-5 审计 hash 链的 JSON 契约对齐）；并补一条真库 HTTP 正例测试（超管建要素 200 + audit_logs 落 1 行 JSON 可解析）。

### DEF-2 无凭据 + 非法体调 coefficient-change-requests → 500 而非 401

- NOAUTH `POST /api/v1/coefficient-change-requests` 空体 → 500/90001，应为 401/20001。
- 与 `7367cfd0` 缺陷 B2 同源：`@Valid` 参数校验/参数绑定先于鉴权 AOP 触发，且异常未落入 401 兜底。独立复现证据：`/tmp/qa03_result_v5.json` 矩阵末行。

### DEF-3 audit-log / system-config 权限异常 → 500 而非 403

- `NotPermissionException`（如 `ipd:system-config:list`）落 `IpdServiceExceptionAdvice` 兜底 500/90001，应为 403/30001。
- **与 `7367cfd0` 缺陷 A+B 完全同源**（Catalog 目录缺口 + `IpdPermissionExceptionHandler.assignableTypes` 白名单未含相关控制器），本轮独立复现互证；修复以该卡登记的缺陷 A/B 方案为准，不重复建卡。
