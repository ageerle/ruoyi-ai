## 4. 验收中发现并修复的缺陷

### 4.1 unbind 清字段失效（MyBatis-Plus updateById 忽略 null 字段）
- **现象**：probe step 9 解绑后再扫码仍能登录成功；SQL 查 `persons.wecom_user_id` 未清空
- **根因**：MP `updateById` 默认 FieldStrategy.NOT_NULL，`setWecomUserId(null)` 不进 UPDATE SQL；单测 mock `verify(updateById)` 测不出 SQL 层语义（假绿活教材：Mock 绿 ≠ 真库闭环）
- **修复**：改 `LambdaUpdateWrapper` 显式 `.set(null)`（与 `PersonSoftDeleteExecutor` 同款项目惯例）；单测断言同步改 `verify(update)` + `never(updateById)`
- **复验**：probe2 A1~A4 库内字段 NULL/NULL + 再扫码 400 拒绝 ✓；P074 重跑 14/14 绿

### 4.2 运维事件：dev 种子密码漂移（非本批代码缺陷）
- **现象**：三账号 Ipd@123456 全部 BAD_CREDENTIALS（审计 entity_id 非空 ⇒ person 查到、hash 不匹配）；两库 hash 与文档默认值均不匹配
- **处置**：用 hutool BCrypt（cost 10，与 IpdMockDataInitializer 同规格）生成新 hash，仅重置 900101/900103/900104 三行回文档默认密码 `Ipd@123456`；三账号登录恢复。**若有会话依赖旧密码请知悉此变更**

## 5. 遗留与移交

- **401/403 口径**：RD_PM 越权发起成员绑定返回 401（code 20001）而非 403——与 SEC-02 矩阵探针「403=DENY」口径不一致，疑似 IPD 异常 advice 把 IpdPermissionException 归并到认证失败。不阻断本卡（拒绝语义达成），建议 SEC-02/QA 复审时统一定调
- **G2/3/4/5 Gate 判定链路**：本卡只验 G1（17 要素）；其余 Gate 共享同一 service，要素数据由 P1-6.1 管理，随 P2-5.2 双签流转再覆盖
- **解锁效果**：P0-3.4（依赖 P2-4.1）与 P1-6.2（依赖 P2-5.1）的 BLOCKED_DEPENDENCY 可解除
- **造数清理**：验收造数 projects 9100000000000000001 / gates 9100000000000000002 已软删（del_flag='2'）；gate_element_results 17 判定行与审计链保留作证据；16040 专属实例已停
