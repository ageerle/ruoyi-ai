### 11.4 DEF-8 → **已修复并提交 `436262b0`**：归档区恒空（SQL 三值逻辑）

- **现象**：二跑「归档区列表可见该申请」FAIL。真库有 2 行 `status=DELETED` 且 `remark IS NULL`，但 `listArchive()` 返回空。
- **根因**：SQL 是**三值逻辑**——`NULL NOT LIKE '%x%'` 求值为 **NULL（非 TRUE）**，WHERE 不成立 → 行被整条排除。而 `remark` 默认 NULL（submit 与终审均不写 remark）→ **归档区恒空**，AC-DEL-02「数据移入归档区」可见性完全失效，purge 入口也永远拿不到候选。
- **真库对照**：`SUM(remark NOT LIKE '%PURGED%')=NULL`（0 行通过）vs `SUM(remark IS NULL OR remark NOT LIKE '%PURGED%')=2`。
- **修复**：`DeletionArchiveService.listArchive()` 改 NULL 安全 → `.and(w -> w.isNull(remark).or().notLike(remark, PURGED_MARK))`，生成 `(remark IS NULL OR remark NOT LIKE ?)`。
- **伴随假绿确证并收紧**：原 `P064AcceptanceTest` 只断言 `wrapper.getSqlSegment().contains("NOT LIKE")`——**Mockito 从不真执行 SQL**，语义缺陷完全隐形而用例全绿；测试名 `archiveListReturnsOnlyNonPurgedEntries` 宣称的契约远超其证明力。已改名为 `archiveListFilterIsNullSafeForUnpurgedRemark`，额外锁 `IS NULL` + `OR` 嵌套形状与参数值，并在 javadoc 明示「本用例只是**形状锁**，语义证据由真库脚本给出」。**10/10 绿、Skipped=0** @16:49:53（`mvn -o -pl ruoyi-modules/ruoyi-ipd`，错峰、无 `-am`、无 `clean`）。

  | 数组 | 元素**不**排序（`[3,1,2]` 原序） |
