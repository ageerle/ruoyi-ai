## 三、关键发现

### 业务规则边界
1. **同 id 重绑幂等**：当 `product.projectId == projectId` 且 `project.productId == productId` 时直接 return，不写二次审计——保证 AC-PROD-01 「1:1 关系建立后可重放操作」幂等语义。
2. **GUEST_OTHER 占位**：现有代码已禁绑（本卡维持原语义），新建项目走 `ProjectService.insertNewProject` 时也同步校验（108be858 同款守卫）。
3. **跨组守卫升级**：bind/unbind 改走 `IpdBusinessException(FORBIDDEN, 30001)` HTTP 403，区别于 create/update/changeStatus 的旧 `ServiceException`（5xxxx HTTP 500）——SEC-02 范畴内显式分离「横向越权」与「系统异常」。
4. **创建入口一致性**：ProjectService.insertNewProject 创建入口仍保留旧 `ServiceException` 语义（P111AcceptanceTest.createProjectWhenProductAlreadyHasProjectId / createProjectWhenProductTakenByOtherProject 测试已绿），未触动兄弟会话在途逻辑。

### 并发细节
- **三道防线**：① product 端 `LambdaUpdateWrapper.eq(id).isNull(projectId).set(projectId, ?)` 行锁 + 1:1 自洽守卫；② project 端 `LambdaUpdateWrapper.eq(id).isNull(productId).set(productId, ?)` 同样守卫；③ DB `uk_products_project` + `uk_projects_product` UNIQUE 兜底（Spring `DuplicateKeyException` 捕获）。
- **重读自洽终态**：bind/unbind 都对两端做 `selectById` 重读并断言 `product.projectId == projectId && project.productId == productId`（双向对称），不依赖 in-memory 对象的 setter 副作用——线上真实场景的「条件 UPDATE 抢到锁 → 重读一定一致」由 MySQL 行锁 + UNIQUE 保证。
- **事务回滚**：任一端条件 UPDATE 失败抛 `IpdBusinessException(STATE_CONFLICT)`，由 `@Transactional(rollbackFor = Exception.class)` 自动回滚——避免「product 端已写、project 端未写」的状态漂移。

### 是否复用既有模式
- ✅ **复用**：`assertSameGroup`（横向越权防护）、`AuditLog` 写入模式（`auditLogService.append`）、`@Transactional(rollbackFor = Exception.class)`、`LambdaUpdateWrapper` 条件 UPDATE（HandoverDisableConcurrencyTest / BonusPoolService 等已验证成熟模式）。
- ✅ **复用**：IpdBusinessException + ApiV1ErrorCode.STATE_CONFLICT（409）/FORBIDDEN（403）——不新增错误码（按卡面要求）。
- ❌ **不修改**：兄弟会话在途文件 `DefaultStateMachineGuard.java` / `AiChatClient.java`（边界遵守）。
- ❌ **不修改**：任何 pom.xml / settings.json / .claude/* / *Mapper.xml。

### Mockito strict stubbing 注意事项
- LambdaUpdateWrapper 需 `TableInfoHelper.initTableInfo(assistant, Product.class)` 初始化，否则 `can not find lambda cache for this entity` 报错——所有测试类 `@BeforeAll` 已加。
- 模拟「条件 UPDATE 真实 DB 写入」用 `doAnswer` 直接 mutate in-memory 对象，让重读自洽终态校验通过——参考 `HandoverDisableConcurrencyTest.disableIfAllCleared_concurrentGuard_noDuplicateAudit`。
