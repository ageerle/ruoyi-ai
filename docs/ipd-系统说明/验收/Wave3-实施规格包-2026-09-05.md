## 7. 风险登记（每批次 1-2 个最大风险 + 缓解）

### Batch-1 风险

- **R-1**（HIGH）：BCrypt cost 10 在 4 实例 × 40 池环境可能 P95 升至 800ms（实测 8.7s → 800ms 已实测约 90%↓），但 Hikari 同步收紧到 20 后**登录路径持池时间**会变长（cost=10 持池 80ms vs cost=4 持池 8ms）。
  - 缓解：Batch-1 复测门设「100 并发登录 P95 < 1s」+ 触发即回滚 cost=8（不推荐 4）。

- **R-2**（MED）：基座块 40→20 仅覆盖 dev/ipd-local，prod 仍 maxPoolSize=20；Batch-1 上线后**真正压测走 prod**需 Batch-5 commit 1 跟进。
  - 缓解：Batch-1 同步把 dev 改为 40（不依赖基座 20），基座块仅作兜底（maxPoolSize=20）；prod 留 Batch-5 处理。
  - **追认（2026-09-07）**：Batch-5 commit 1「prod Hikari maxPoolSize=60」已由 SEC-HIGH-1 (R9-BC-COST) BCrypt cost=10 同步路径偶然覆盖（实际产物 maxPoolSize=80，超原 spec 60；详见 application.yml:154 注释 + `ProdHikariConfigTest` 4 测守门），无需专项 fix commit。

### Batch-2 风险

- **R-3**（HIGH）：DEF-6 方案 A（json→longtext）会丢 DEF-1 fail-fast 护栏；若 AuditEventData.requireJson 漏配则脏载荷进 hash 链。
  - 缓解：方案 A 上线必须**同步强化 requireJson** + `AuditPayloadJsonGuardTest` 锁住位置（不允许 retry 内调）+ 异常消息「DEF-6 应用层护栏」标签 alert 化。

- **R-4**（HIGH）：`audit_log_chain_heads` 锚表是新建表 → 与兄弟流 4 个 untracked SQL（audit-payload-longtext 在内）可能有 schema 冲突。
  - 缓解：Batch-2 上线前在隔离库 ipd_audit_v2 跑 schema 冲突检查 + 与兄弟流 `GateEngine.java` WIP 错峰排期。

### Batch-3 风险

- **R-5**（HIGH）：线上 ipd_dev 加 6 幻影列（QA-04-D2 裁决 1）可能与兄弟流 schema WIP 撞车（兄弟流 4 个 untracked SQL 也在动 schema）。
  - 缓解：**严格错峰**——本批次加列窗口与兄弟流 schema 窗口间隔 ≥ 2 小时，加列前后 SHOW CREATE TABLE 对比；如冲突立即回滚 ALTER。

- **R-6**（MED）：uk_projects_product 方案 A 实施需 ProjectService 同步修改（软删时 product_id=NULL）—— 跨服务改动。
  - 缓解：方案 B 备选同步评审（编译通过即可切），减少切换成本。

### Batch-5 风险

- **R-7**（HIGH）：prod Hikari + RSA env 注入 + JWT secret fail-fast 等多项配置同步改 → 任一配置错误即启动失败。
  - 缓解：**灰度发布**——Batch-5 commit 1-4 合并为单一 release 门，单实例启动验证后再推全。

- **R-8**（MED）：logback-spring.xml 引入 springProfile 节点可能影响 dev 环境日志输出（logback-plus 当前全局 INFO）。
  - 缓解：dev 环境保留 logback-plus.xml 不切（springProfile 仅作用于 prod），降低切换风险。

## 10. 执行纪律清单

### 10.1 派 agent 调度规则（按改动范围触发）

| 触发条件 | 派 agent | 范围 |
|---|---|---|
| 改 1-2 行（Batch-5 commit 4-12） | 不派 agent（成本不划算） | — |
| 改 controller 写操作（Batch-1 commit 3 / Batch-2 commit 1 / Batch-5 commit 2） | `security-reviewer` + `code-reviewer` | 2 个并发 |
| 改 AuditLogService（Batch-2 commit 1/2/3/4）| `security-reviewer` + `code-reviewer` + `performance-analyzer` | 3 个并发（互锁核心） |
| 改 DDL（Batch-3 commit 1/8/9）| `code-reviewer` + `performance-analyzer` + `db-migration` skill | 2 agent + 1 skill |
| 改 service N+1（Batch-3 commit 2/3/4/5/6/7）| `performance-analyzer` | 1 个 |
| 改 prod 配置（Batch-5 commit 1/3/4/7）| `security-reviewer`（需用户授权确认） | 1 个 |
| 模块级重构（Batch-2 全批）| 2-3 agent 并发 | 烧 token 但值 |

### 10.2 commit 时机纪律

1. **单卡单 commit**：每张子卡对应 1 个 commit（除 Batch-1 commit 1/2 同卡双 commit 因 BCrypt+Hikari 互锁）
2. **owner 决策未拍板不 commit**：G-07/G-08/G-11/G-06 等 4 项裁决未拍板前不开相关 commit
3. **隔离库复测通过才 commit**：Batch-2 走 ipd_audit_v2、Batch-3 走 ipd_qa04d2v2、Batch-5 走 prod 灰度
4. **不抢兄弟流在途文件**：89 文件 WIP 不 add / 不 restore / 不 checkout
5. **Commit message 格式**：`fix|feat|perf|docs(ipd|security|ddl|ops,<CARD-ID>): <一句话>`

### 10.3 卡面 evidence 挂载模式

- **执行者**（committer）：commit 后挂证据段到对应卡面 description，**不翻 status**（保留 todo/inreview）
- **QA 终审**（第二方 QA 蜂群）：执行者挂证据后，第二方 QA 静态正交 + 动态 scoped + 错峰全量回归三轨并发 → 翻 inreview→done
- **owner 决策卡**（DEF-5/6/9、QA-04-D2 裁决 4 项）：维持 todo，decision 落地后挂 evidence + 翻 done
- **BLOCKED_DEPENDENCY**（P0-3.4 / P1-6.2 / SEC-04）：不动 status，依赖上游 P2-4.1 / P2-5.1 / P4-1.4

### 10.4 凭证纪律

- **零明文**：报告 / commit / 卡面 description / 卡面 evidence 路径均**不写入**任何密码 / JWT secret / RSA 私钥
- **引用占位**：凭据一律以「本地配置 `.codex/ipd-dev/config/xxx`」形式指代
- **扫描门**：每批 commit 前对 git diff 跑 `grep -E "password|secret|key|token"`，命中字符串长度 ≥ 16 且非占位符即阻断
- **gitleaks CI**（Batch-5 commit 4 落地）：仓库级 secret 扫描

### 10.5 蜂群纪律（沿用 round6 legacy closeout）

- **共享单一工作树模式**：主线程 + 兄弟流 + 外部 QA agent 共存，所有 commit 前必须 `git status --short` 确认无冲突文件
- **执行者只挂证据段，不翻 status**：避免 QA 终审回退拉锯
- **swarm-parallel-regression-guard 监控守卫模式**：本波全程在线，commit 后跑 222/222 全量回归基线
- **修改兄弟流在途 89 文件 = 零容忍**：本波所有 commit 必须 `git status --short` 仅显示本卡修改 + 不变项
- **任何撤回 / 重链 / 池修复** 都需 3 个独立窗口：(a) 静态分析 (b) 隔离库验证 (c) 真库复测
