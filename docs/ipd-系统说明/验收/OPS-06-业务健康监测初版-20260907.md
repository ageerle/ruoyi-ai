## 2. 最小版监控治理框架（仅规范层，不写代码）

### 2.1 三层监测结构

| 层 | 监测对象 | 监测手段 | 当前实现 | 缺口 |
|---|---|---|---|---|
| L1 业务健康 | handover 超期 / 人员离职升级 / 项目停滞 | 调度器每日扫描 + 计数 | HandoverOverdueScanner 注释掉 | **缺调度启用 + 计数打点** |
| L2 审计故障 | 审计链 chain_ok | 定时 verify_chain + 异常通知 | AC-AUD-02 已有 verify | **缺调度启用 + 异常通知** |
| L3 任务失败 | snailjob 失败任务 | 任务执行回调 + 重试 + 告警 | 无 IPD 任务注册 | **缺任务注册 + 失败告警** |

### 2.2 推荐最小落地方案（下一步 owner 决策）

**L1 业务健康（最小化）**：
- 在 `application.yml` 加 `ipd.health.scan.handover-overdue.enabled=true`
- 解注释两处 `@Scheduled(cron = "0 0 9 * * ?")`
- 在 `RuoYiAIApplication` 加 `@EnableScheduling`
- 扫描结果发 NotificationEvent（已存在 dedup_key + escalated_at 幂等双层守卫）

**L2 审计故障（最小化）**：
- 复用 L1 调度，每日跑 `AuditLogService.verifyChain()`（已存在）
- chain_ok=false 时发 `NotificationEvent` 给 SUPER_ADMIN
- 写一条独立审计（`AUDIT_HEALTH_ALERT`，type=ALERT）

**L3 任务失败（最小化）**：
- 在 `ruoyi-snailjob-server` 注册 1 个 IPD 探针 job（每日 09:30 跑）
- job 内容：扫 3 张关键表（`audit_log_chain_heads` / `projects` / `bonus_pool`）的 N 分钟内无写入即告警
- 失败重试：snailjob 默认 3 次
- 告警发 NotificationEvent
