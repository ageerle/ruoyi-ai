## 2. 关键发现（探针阶段）

### 2.1 配置读取架构（双服务并存）

- `SystemConfigService`（`system_configs` 表）：单 JVM `ConcurrentHashMap` 缓存 + 写穿透失效（PERF-02 用户裁决）。`getValue()` 用 `computeIfAbsent`，空结果也缓存防穿透。`update()` 在同一事务内调 `invalidate(key)`。
- `BusinessConfigService`（`ipd_business_config` 表）：同型 ConcurrentHashMap 缓存，`update()` 同事务 invalidate。
- 两服务都满足「立即生效」语义：写后下一次读即新值，无 TTL 窗口。

### 2.2 Gate 双签期限消费者路径

- `GateReviewService.resolveSignDeadlineDays()`（line 311-320）：
  - 优先 `businessConfigService.getInt(SIGN_DEADLINE_KEY)`（即 `gate.signDeadlineDays`）
  - 回退 `systemConfigService.getIntValue(SIGN_DEADLINE_KEY, 3)`
- `GateReviewService.reopen()`（line 361-362）：调 `resolveSignDeadlineDays()` 算新 `signDueAt`，**这是唯一真正消费 config 的 Gate 写入路径**。
- `GateReviewService.dueAtFrom()`（line 297-306）：仅当 `gate.signDueAt` 为 null 时回退到 config；正常 Gate 创建时已写 signDueAt。

### 2.3 津贴消费者路径

- `ProjectMemberService.bindMember()`（line 120）：
  ```java
  int amount = systemConfigService.getIntValue("allowance." + level, -1);
  ```
  读 `allowance.L1..L5`，写 `ProjectMember.lockedAmount` 快照。
- 锁生效：`lockedLevel/lockedAmount` 随绑定原子写入，HR 升 L 后**不回溯**已绑定项目（AC-HR-03 / AC-INC-02）。

### 2.4 奖金池消费者路径（关键发现）

- `BonusPoolService.compute(projectId, actualReceipts, ...)`：`actualReceipts` **由调用方传参**，不读 `bonus.salesSource`。
- `BonusPoolService.readActivePoolRate()`：读 `bonus.poolRate`（生效）。
- `BusinessConfigKeys` 无 `BONUS_SALES_SOURCE` 常量；`bonus.salesSource` 仅在 `SystemConfig.java` 注释里出现（"如 bonus.salesSource / allowance.L3 / gate.signDeadlineDays"），**无 Service 实际消费者**。
- 这是 AC-GLB-10 正例无法真正验证的根因——历史快照不被静默覆盖（负例）是真实安全保证，正例需 owner 决策补 consumer 后才能真验证。
