## 3. 验收线 3：并发约束真实 DB 验证（隔离库 ipd_qa04）

测试：`ruoyi-modules/ruoyi-ipd/src/test/java/org/ruoyi/ipd/qa/Qa04MysqlConcurrencyTest.java`（`@Tag("dev")` + `@EnabledIfSystemProperty(ipd.scope.mysql.enabled)` 显式启用，纯 JDBC + 与生产一致的 MyBatis-Plus 映射层，4 用例全过）

### 3.1 唯一约束并发（uk_projects_code）

`duplicateCodeRaceProducesExactlyOneWinnerAndLoserRetrySucceeds`：5 轮 × 双线程 `CountDownLatch` 同时插同一 `code`（各自独立 product），**每轮恰好 1 胜 + 1 个 1062 DuplicateKey**；败者换号重试立即成功——与 `ProjectService.create` 的 `CODE_CONFLICT_MAX_RETRY=8`（ProjectService.java:61/80）SQL 层语义一致。**PASS**

### 3.2 乐观锁（stage_actions @Version）

`concurrentVersionUpdateOnlyOneWins`：种子 version=0 → 两线程各自 openSession → selectById → 栅栏 → 分别迁往 IN_PROGRESS / DELAYED → `updateById`（OptimisticLockerInnerInterceptor 与生产 `MybatisPlusConfig` 同款）：**恰好一方 rows=1，另一方 rows=0；行 version 终值 = 1**。**PASS**

（调试注记：MP 拦截器会在 update 后把新 version 回写实体，测试日志里 `getVersion()==1` 是"更新后值"而非"载入值"，首次实现把断言写成了 CAS 首结果制，若败者先跑会误记 0——已修正为统计 rows==1 的线程数恰为 1。）

### 3.3 事务回滚（业务+审计同事务）

`auditWriteFailureRollsBackBusinessInsertWithZeroResidue`：`autocommit=false` 事务内 insert projects + insert audit_logs（after_data 塞非法 JSON，MySQL json 列拒绝）→ 审计失败 → rollback → **独立连接验证 projects / audit_logs 零残留**；阳性对照（合法 JSON + COMMIT）两表均可见，排除权限/连接伪象。**PASS**
