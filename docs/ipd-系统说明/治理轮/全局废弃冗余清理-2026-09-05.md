## 九、落地过程与竞态实录（为何一度看似失败）

会话期间 HEAD 仍续前移 **6 次**（`2266fd09` → `2a15d79c` → `151c5b98` → `52355947` → `e92c2be7`/`fa1c6e10` → `bbf0ff49`/`d321ab8f` → `536b4b48` → **`62ef2c34`（本清理）** → `ab594e79`），dirty 峰得 80→95。两个坑（后继会话必须避开）：

1. **`git rm --cached` 单独暂存会被兄弟扫描吃掉**：它只改索引不改工作树，而 `git add -A && git commit` 会按 **HEAD 中仍存在**把这些路径重新拉回索引 → 实测本轮被重置 **2 次**（第一次 117 项全丢，第二次局部）。结论：在此仓做索引层清理，**必须“摘除 + 提交”写在同一条 shell 命令里同秒完成**；提交后立即用 V10–V12 复核是否复吸。

3. **归属被动披露**：本轮 `.gitignore` 修复未随自己的提交，而是被兄弟 `bbf0ff49`（`git add -A` 扫描）顺带入库；本台账与 `README.md` 修改则在 `62ef2c34` 内。提交前已校验 `git diff --cached --name-only` 不含他人路径，提交后 V6/V10 均净。
