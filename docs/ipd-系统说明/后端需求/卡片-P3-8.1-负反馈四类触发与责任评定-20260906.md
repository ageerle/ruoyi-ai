## 1. 业务规则映射（ZK-IPD §X）

### 1.1 与 P3-8.2 的边界

| 维度 | P3-8.2（已落） | P3-8.1（本卡） |
|---|---|---|
| 核心职责 | 状态机（create/submit/decide/lift）+ 通知联动 | **检测引擎**（基于项目数据判定触发情形）+ **责任推荐**（建议 mainRole / relatedRole） |
| 输入 | 人工录入触发情形 + 月份 | 项目 KPI / 返工率 / 质量事故 / SPEC 复杂度 / 上市节奏 |
| 输出 | 落库状态机迁移 | 返回 `DetectionResult` 列表（不改库，preview 模式） |
| 联动 | 调用 NotificationService 发通知 | 调用 NegativeFeedbackService.create() 落库 |
| 表变更 | `negative_feedbacks` 已 ALTER | **无 DDL 变更**（检测数据从既有 KPI/Cert/Project 域读） |

### 1.2 四类触发的检测算法

| 触发情形 | 检测数据源 | 阈值 |
|---|---|---|
| REWORK_EXCEEDED 返工超标 | `stage_action_records` + `deliverable`（不合格数 / 总数） | reworkRate > 0.30 → REWORK_EXCEEDED |
| QUALITY_ACCIDENT 质量事故 | `gate_review` + `gate_review_elements`（致命/严重缺陷 ≥1） | hasCriticalDefect=true → QUALITY_ACCIDENT |
| SPEC_PILE_COPY 参数堆砌 | `requirement` + `cert_template_item`（参数堆砌率 > 0.5） | pileCopyRate > 0.50 → SPEC_PILE_COPY |
| MISSED_MARKET_WINDOW 错过市场窗口 | `project` + `launch_date_change`（延迟天数 > 30） | delayDays > 30 → MISSED_MARKET_WINDOW |

### 1.3 责任推荐规则

复用 P3-8.2 的静态映射：

| triggerType | mainRole | mainExecution | relatedRole | relatedExecution |
|---|---|---|---|---|
| REWORK_EXCEEDED | MARKET_PM | STOP_ALLOWANCE | RD_PM | HALVE_ALLOWANCE |
| QUALITY_ACCIDENT | RD_PM | STOP_ALLOWANCE | MARKET_PM | HALVE_ALLOWANCE |
| SPEC_PILE_COPY | RD_PM | STOP_ALLOWANCE | MARKET_PM | HALVE_ALLOWANCE |
| MISSED_MARKET_WINDOW | BOTH | STOP_ALLOWANCE × 2 | — | — |

**调整建议**：当项目无对应主责 PM 时，推荐降级（例：无 MARKET_PM 时 REWORK_EXCEEDED 推荐 RD_PM 主责，MARKET_PM 连带降为 NONE）

### 1.4 引用 BR / AC

- **BR-INC-10**：负反馈四类触发与责任分配（与 P3-8.2 共用）
- **AC-INC-36a**（本卡新增）：检测引擎输出包含 triggerType + 阈值实测值 + 责任推荐 + 阈值依据
- **AC-INC-36c**（本卡新增）：检测结果须可追溯（reportJson 含 evidence 字段）

## 2. API 契约

### 2.1 路径

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/negative-feedbacks/detect/{projectId}` | 检测项目可能的负反馈情形（不改库；返回 DetectionResult 列表） |
| GET | `/api/v1/negative-feedbacks/detect/{projectId}/preview` | 同上 + 包含触发证据 evidence |
| POST | `/api/v1/negative-feedbacks/detect/{projectId}/commit` | 检测 + 自动落库（调用 NegativeFeedbackService.create） |
| GET | `/api/v1/negative-feedbacks/detect/config` | 获取当前检测阈值配置（reworkRateThreshold / pileCopyRateThreshold / marketWindowDelayThreshold） |

## 3. 数据库变更

**无 DDL 变更**。原因：

1. **检测结果** — 不落库（preview 模式仅返回）；commit 时通过 NegativeFeedbackService.create 落库
2. **审计** — 检测动作（commit 时）复用 `audit_logs`（action = `NF_DETECTION_COMMIT`）
3. **配置** — 阈值由 `system_config` 表统一管理（key = `nf.detect.reworkRateThreshold` 等）

## 4. 测试矩阵（6 维度）

| 维度 | 测例 |
|---|---|
| 1. 检测 REWORK | `detect_reworkExceeded_returnsTrigger` —— reworkRate=0.40 触发 REWORK_EXCEEDED |
| 2. 检测 QUALITY | `detect_qualityAccident_returnsTrigger` —— hasCriticalDefect=true 触发 QUALITY_ACCIDENT |
| 3. 检测 MISSED | `detect_missedWindow_returnsTrigger` —— delayDays=45 触发 MISSED_MARKET_WINDOW |
| 4. 责任推荐降级 | `detect_noMarketPm_downgradesAttribution` —— 无 MARKET_PM 时推荐 RD_PM 主责 + NONE 连带 |
| 5. 责任推荐降级 | `detect_noRdPm_returnsError` —— MARKET_PM 和 RD_PM 都无 → 报 NF_NOT_PM |
| 6. commit 联动 | `detect_commit_callsNegativeFeedbackCreate` —— commit 调用 NegativeFeedbackService.create 落库 |

## 5. 安全审查点

1. `detect` / `preview` 端点要求 `requireInternal`（业务角色可读）
2. `commit` 端点要求 `requireInternal`（与 P3-8.2 create 一致）
3. 检测结果不影响既有数据隔离（基于已有 query，无跨表越权）
4. 责任推荐必须包含 evidence 字段（防止"猜"主责）

## 6. 联动路径

- 与 P3-8.2 `NegativeFeedbackService.create`：commit 时直接调用，传入 triggerType + attribution
- 与 P3-3.1 `AllowanceLedgerService`：检测到 STOP_ALLOWANCE 后次月津贴自动停发
- 与 P3-4.4 `BonusPoolService`：检测到 bonusDisqualify=1 后该 PM 不参与奖金分配

## 7. 不实现范围

- 不做"批量检测全项目"（单项目调用，超管批量留 P4 治理卡）
- 不做"检测阈值动态调优"（留 P4 治理卡，本期用默认常量）
- 不做"检测历史快照"（每次 detect 实时计算，不缓存）
