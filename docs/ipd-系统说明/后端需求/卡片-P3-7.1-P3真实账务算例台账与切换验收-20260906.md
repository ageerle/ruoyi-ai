## 1. 业务规则映射（ZK-IPD §X）

### 1.1 业务背景

P3 阶段上线的全部账务相关模块（KPI、Allowance、BonusPool、NegativeFeedback、Contribution）在真实数据上需要：
1. **对账** — 跨表交叉一致性校验（例：AllowanceLedger 与 ProjectMember 锁定额一致；BonusPool 个人分配与 Contribution 五维度一致）
2. **算例验证** — 给定测试月份的"样本项目"，全链计算并比对预期值
3. **切换验收** — 月度锁定后，禁止再修改该月任何账务记录（防止跨月改账）

### 1.2 引用 BR / AC

- **BR-INC-12**：P3 阶段账务切换须经对账通过 + 超管确认
- **AC-INC-50**（本卡新增）：对账差异率 < 1% 才允许锁定
- **AC-INC-51**（本卡新增）：锁定月份所有账务写操作返回 SWITCHING_LOCKED 错误

### 1.3 复用基座

- `BonusPoolService`（P3-4.4）—— 奖金池算例
- `AllowanceLedgerService`（P3-3.1）+ `AllowanceService`（P3-3.1/3.2/3.3）—— 津贴台账
- `KpiRecordService`（P3-1.1/1.2/1.3）—— KPI 聚合
- `NegativeFeedbackService`（P3-8.2）—— 负反馈台账
- `ContributionService`（P3-6.2）—— 贡献度评定
- `AuditLogService` —— 切换审计

## 2. API 契约

### 2.1 路径

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/switching-acceptance/{month}/run` | 运行对账（month=YYYY-MM）；返回 ReconciliationReport |
| GET | `/api/v1/switching-acceptance/{month}` | 获取对账报告（已 run 过则直接返回） |
| POST | `/api/v1/switching-acceptance/{month}/lock` | 月度锁定（仅超管；锁定后所有账务写操作拒） |
| POST | `/api/v1/switching-acceptance/{month}/unlock` | 月度解锁（仅超管；事故恢复用，需附 reason） |
| GET | `/api/v1/switching-acceptance` | 列出已 run 月份的对账报告（按月倒序） |

### 2.3 错误码

| 错误码 | HTTP | 场景 |
|---|---|---|
| `SWITCHING_LOCKED` (50014) | 409 | 已锁定的月份上写入账务记录 |
| `SWITCHING_DIFF_TOO_LARGE` (50015) | 409 | 对账差异率 ≥ 1% 时尝试 lock |
| `SWITCHING_NOT_RUN` (50016) | 409 | lock 调用时未先 run |
| `PARAM_INVALID` (10001) | 400 | month 格式错（YYYY-MM） |

## 4. 测试矩阵

| 维度 | 测例 |
|---|---|
| 1. run 正例 | `run_cleanMonth_allChecksPassed` —— 5 类校验全过，diffRate=0 |
| 2. run 异常 | `run_invalidMonth_throws` —— month="2026-9" 抛 PARAM_INVALID |
| 3. lock 正例 | `lock_passedReport_success` —— passed=true 后 lock 成功 |
| 4. lock 异常 | `lock_failedReport_throws` —— passed=false 抛 SWITCHING_DIFF_TOO_LARGE |
| 5. lock 异常 | `lock_notRun_throws` —— 未 run 直接 lock 抛 SWITCHING_NOT_RUN |
| 6. unlock 正例 | `unlock_withReason_success` —— 超管解锁并附 reason |
| 7. 联动：locked 月写入 | `writeToLockedMonth_blocked` —— 写 AllowanceLedger 到 locked 月抛 SWITCHING_LOCKED |

## 5. 安全审查点

1. `run` 端点要求 `requireInternal`（业务角色都可触发对账）
2. `lock` / `unlock` 端点要求 `requireAdmin`（仅超管可锁/解锁）
3. `get` / `list` 端点要求 `requireInternal`
4. 联动写入拦截：在 AllowanceLedgerService / BonusPoolService 中检查月份是否 locked

## 6. 联动路径

- 与 P3-3.1 `AllowanceLedgerService`：locked 月拒绝写入
- 与 P3-4.4 `BonusPoolService`：locked 月拒绝写入
- 与 P3-8.2 `NegativeFeedbackService`：trigger_month == locked 时拒绝写入
- 与 P3-6.2 `ContributionService`：归档动作必须先有 lock 才能执行

## 7. 不实现范围

- 不做"跨月批量回滚"（超出本卡范围，留 P4 治理卡）
- 不做"对账失败自动告警"（超管跑 run 主动检查）
- 不做"历史对账趋势分析"（P4 阶段聚合接口）
