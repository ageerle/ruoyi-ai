## 2. API 契约

### 2.1 路径

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/contributions/{projectId}/form-template` | 获取评定表模板（五维度初始建议值；不动库） |
| POST | `/api/v1/contributions/{projectId}/peer-review` | 双 PM 互审（MARKET_PM 评 RD 维度 / RD_PM 评 MARKET 维度） |
| GET | `/api/v1/contributions/{projectId}/history` | 历史版本（按 id desc，包含 CONFIRMED 归档版本） |
| POST | `/api/v1/contributions/{projectId}/archive` | 归档当前 CONFIRMED 版本（落 archive_at 审计标记 + isArchived 视图字段） |

### 2.3 错误码

| 错误码 | HTTP | 场景 |
|---|---|---|
| `CONTRIB_NOT_G5_STAGE` (50007) | 409 | 项目不在 G5 阶段 |
| `CONTRIB_NOT_AUTHORIZED` (50008) | 403 | peer-review 角色不匹配（非双 PM） |
| `STATE_CONFLICT` (50002) | 409 | archive 调用时状态非 CONFIRMED |
| `PARAM_INVALID` (10001) | 400 | role / agreed / peerOpinion 校验失败 |

## 3. 数据库变更

**无 DDL 变更**。原因：

1. **peer-review 留痕** — 复用 `audit_logs` 表（action = `CONTRIBUTION_PEER_REVIEW`）
2. **archive 标记** — 复用 `audit_logs` 表（action = `CONTRIBUTION_ARCHIVE`）；视图层 isArchived 由是否落审计推导
3. **历史版本** — `contributions` 表已支持多版本（按 id 排序），CONFIRMED 状态下被锁定，删除走软删除 `del_flag`

## 4. 测试矩阵（6 维度）

| 维度 | 测例 |
|---|---|
| 1. 表模板 | `formTemplate_returns5Dimensions` —— 返回 weights / marketShareRange / kpiHints |
| 2. 表模板异常 | `formTemplate_nonG5Stage_throws` —— 非 LIFECYCLE/POST_LAUNCH 抛 CONTRIB_NOT_G5_STAGE |
| 3. 互审正例 | `peerReview_marketReviewsRd_agree` —— MARKET_PM 提交 agreed=true，audit 落 CONTRIBUTION_PEER_REVIEW |
| 4. 互审异常 | `peerReview_roleMismatchActor_throws` —— actor=RD_PM 但 req.role=MARKET_PM 抛 CONTRIB_NOT_AUTHORIZED |
| 5. 历史 | `history_multipleVersions` —— 返回所有版本（含 CONFIRMED） |
| 6. 归档正例 | `archive_confirmed_success` —— CONFIRMED 状态可归档，落 archive 审计 |
| 7. 归档异常 | `archive_notConfirmed_throws` —— 非 CONFIRMED 抛 STATE_CONFLICT |

## 5. 安全审查点

1. `form-template` 端点要求 `requireInternal`（内部全员可读模板，不动库安全）
2. `peer-review` 端点要求 actor.role() == req.role()（同 P3-6.2 save 校验）
3. `archive` 端点要求 `requireLeaderOrAdmin`（与 confirm 一致；防止双 PM 自行归档）
4. `history` 端点要求 `requireInternal`

## 6. 联动路径

- 与 P3-6.2 `ContributionService.confirm()`：归档前必须先 confirm
