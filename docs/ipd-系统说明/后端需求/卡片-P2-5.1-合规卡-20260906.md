# P2-5.1 合规卡（2026-09-06）

## 接口设计

| 方法 | 路径 | 权限码 | 说明 |
|---|---|---|---|
| GET | `/api/v1/compliance/data-retention-rules` | `ipd:compliance:read` | 数据保留期规则清单（个保法/GDPR-like） |
| POST | `/api/v1/compliance/data-deletion-request` | `ipd:compliance:write` | 创建数据删除请求（30 天内必处理） |
| GET | `/api/v1/compliance/audit-trail/{resourceType}/{resourceId}` | `ipd:compliance:read` | 资源审计链（基于 AuditLogService.listByOperatorIds 已具备 + scope 过滤） |
| GET | `/api/v1/compliance/permission-separation/{userId}` | `ipd:compliance:read` | 用户 R/W 权限分离判定（防「同用户持 R+W」越权） |

## 字段定义

- **data-retention-rules**：List of
  - `resourceType` 资源类型（projects / requirements / persons / audit_logs / …）
  - `retentionDays` 保留天数
  - `deletionPolicy` 删除策略（HARD_DELETE / SOFT_DELETE / ARCHIVE）
  - `legalBasis` 法律依据（DSL-个保法 / GDPR-Art17 / 内部留存）
- **data-deletion-request** (POST body)：
  - `resourceType` String 必填
  - `resourceId` Long 必填
  - `reason` String 必填
  - `requesterId` Long（服务端从 actor 推导，禁止透传）
- 返回 DataDeletionRequest VO，含 `deadlineAt = now + 30 days`
- **audit-trail**：返回 Page<AuditEntryVO>，每条 = actor / action / before / after / timestamp（来自 AuditLog）
- **permission-separation**：返回 PermissionSeparationVO
  - `userId` Long
  - `hasReadRole` Boolean
  - `hasWriteRole` Boolean
  - `conflict` Boolean（true = 同时持 R+W，存在越权风险）
  - `roleList` List<String>

## AC 引用

- AC-COMP-01 数据保留规则可查询（DSL 个保法/GDPR）
- AC-COMP-02 删除请求 30 天内必处理（deadline 强制计算）
- AC-COMP-03 删除请求必写审计（不可绕过 AuditLogService）
- AC-COMP-04 审计链查询支持 resourceType+resourceId 范围
- AC-COMP-05 R/W 权限分离：同用户不能同时持 `ipd:compliance:read` 与 `ipd:compliance:write`
- BR-COMP-R/W 分权
- BR-COMP-AUDIT 写操作必审计
- ZK-IPD §九 合规（数据保留期 / 删除请求处理时长 / 角色权限分离）

## 合规约束

- **个保法要求**：数据删除请求 30 天内处理，`deadlineAt = now + 30 * 86400_000ms`
- **审计**：所有写操作（POST）必落 AuditLog（不可绕过 AuditLogService.append）
- **角色**：写权限 ≠ 读权限（同用户不能同时持）

## 数据来源

- 保留规则：sys_config 表 key=`compliance.retention.<resourceType>`（value=JSON: retentionDays/deletionPolicy/legalBasis）
  - 默认兜底：保留 7 年（2557 天），策略 SOFT_DELETE，法律依据「内部留存」
- 审计链：复用 `AuditLogService.listByOperatorIds(operatorIds, pageNo, pageSize)` 已具备
- R/W 检测：基于 Person.personType + IPD 角色 → 权限码映射表（编码层面）：
  - SUPER_ADMIN → 持 R + W（**违反** AC-COMP-05 给出 conflict=true 警告，但本身超管是「治理角色」豁免）
  - GROUP_LEADER → 持 R + W（**违反**，警告）
  - MARKET_PM / RD_PM → 仅持 R（**不冲突**）
  - 检测口径：MARKET_PM/RD_PM 是合规卡的合法 R 持有者；SUPER_ADMIN/GROUP_LEADER 持 W 时 R 视为不可分，应报 conflict
  - 接口语义：「对同一 resourceType 是否 R 与 W 同源」

## 复用清单

| 能力 | 复用方式 |
|---|---|
| 软删除 | 通过现有 DeletionRequestService（不重写） |
| 多租户过滤 | BaseEntity 自带 tenantId |
| 审计日志 | AuditLogService.append（写） / listByOperatorIds（读） |
| 权限校验 | IpdPermission.requireInternal / requireAdmin / requireLeaderOrAdmin |
| 角色权限码 | IpdPermissionCode 新增 COMPLIANCE_READ / COMPLIANCE_WRITE |
| 业务异常 | IpdBusinessException(ApiV1ErrorCode.FORBIDDEN) |
| 错误码 | ApiV1ErrorCode.FORBIDDEN / NOT_FOUND / PARAM_INVALID |
| API V1 响应包络 | ApiV1Response<T> |
| 当前登录人 | IpdAuthSession.currentPerson() |
| IPD Actor 投影 | new IpdActor(id, name, role, groupId) |
