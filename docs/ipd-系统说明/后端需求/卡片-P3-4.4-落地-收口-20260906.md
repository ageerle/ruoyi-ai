## 业务空实现 → 实质实现要点

- **之前是**：`BonusPoolService` 仅有公式段（§三.2.1/§三.2.4/§三.2.5 完整闭环），**BonusPoolController 完全缺失**——前端 P0-10.34 激励管理-奖金池核算页只能查不能算。
- **现在是**：
  1. `compute(projectId, actualReceipts, achievementRate, personalCoefficient, poolRate)` — 按项目 + 回款 + 达成率 + 个人绩效计算并落 DRAFT
  2. `freeze(id, reason, actor)` — DRAFT → CONFIRMED，幂等；落 audit_log
  3. `distribute(id, marketShare, rdShare, actor)` — DRAFT/CONFIRMED → DISTRIBUTED，§三.2.4 比例校验 + 分摊；落 audit_log
  4. `getById(id)` / `listByProject(projectId)` — 详情 + 列表（沿用既有 listByProject）
  5. **状态机**：DRAFT → CONFIRMED → DISTRIBUTED（终态）；幂等转换不重写审计
  6. **审计**：freeze/distribute 各落 1 条 v3 TS-08 hash 链审计（entityType=bonus_pools, action=BONUS_POOL_FREEZE/BONUS_POOL_DISTRIBUTE）
  7. **权限梯度**：compute/query/list 走 `ipd:bonus-pool:compute|query`（MARKET_PM/RD_PM/GROUP_LEADER/SUPER_ADMIN）；freeze/distribute 走 `ipd:bonus-pool:freeze|distribute`（GROUP_LEADER/SUPER_ADMIN 涉钱审批）
  8. **公式段 0 改动**：仅复用既有 `buildPoolFromProjectWithAchievement` / `calculateBonusPoolByZkFormulaWithModifiers` / `calculateDistribution` / `applyDistribution` 4 个方法

## 安全审查点

| 项 | 措施 |
|---|---|
| 横向越权 | compute/query/list → `requireInternal()`；freeze/distribute → `requireLeaderOrAdmin()` |
| SQL 注入 | 仅用 `LambdaQueryWrapper.eq()` / `selectById()`，无字符串拼 |
| 多租户 | `BaseEntity` 自带 tenantId 过滤；项目域绑定，跨组由 `canAccessGroup` 兜底 |
| 审计 | freeze/distribute 写动作必落 1 条 audit_log（v3 TS-08 hash 链） |
| 状态机 | DISTRIBUTED 是终态；CONFIRMED → DISTRIBUTED 单向；DRAFT → CONFIRMED/DISTRIBUTED 单向 |
