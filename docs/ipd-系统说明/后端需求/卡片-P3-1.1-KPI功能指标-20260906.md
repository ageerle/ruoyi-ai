# 卡片 P3-1.1 — 功能 KPI 指标来源与计算（2026-09-06）

> **单写者模式落地卡**：49 页卡矩阵中 P0-10.29 KPI 考核-功能 KPI 后端空实现补齐。
> **范围**：基于既有 `KpiRecordService`（P3-1.1 字段校验与算法已就绪）+ `KpiScoreCalculator`（纯函数）+ `ProjectScoreService`（P3-2.1 加权汇总）+ `AllowanceLedgerService`（P3-3.1 锁定评级+封顶），聚合输出 3 类数据源的 KPI 指标。

## 2. API 契约

### 2.1 端点：`GET /api/v1/kpi/functional`

| 项 | 值 |
|---|---|
| 路径 | `/api/v1/kpi/functional` |
| 权限码 | `ipd:kpi:query`（内部角色 MARKET_PM / RD_PM / GROUP_LEADER / SUPER_ADMIN） |
| 入参 | `period`（YYYY-MM，必填） |
| 出参 | `ApiV1Response<List<KpiSourceItem>>` |

### 2.2 响应：`KpiSourceItem`

```java
public record KpiSourceItem(
    String source,           // 来源枚举：PROJECT_SCORE / KPI_CALCULATOR / ALLOWANCE_LEDGER
    BigDecimal value,        // 该来源 KPI 数值（0~100）
    BigDecimal weight,       // 在总 KPI 中的权重（0~1）
    BigDecimal contribution  // value × weight（保留 2 位小数）
) { }
```

### 2.3 数据源（3 路聚合）

| 来源 | 取数 | 权重 | 说明 |
|---|---|---|---|
| `PROJECT_SCORE` | `project_scores` 表中 actor 当期 `weightedScore` | 0.4 | P3-2.1 加权汇总；缺则 0 |
| `KPI_CALCULATOR` | `KpiScoreCalculator.comprehensive(functionalAvg, sharedAvg, 0.6)` | 0.4 | 纯函数，无 DB 依赖；缺值则跳过 |
| `ALLOWANCE_LEDGER` | `allowance_ledgers` 中 actor 当期 `finalAmount` 经 L1~L5 系数归一化 | 0.2 | 津贴 ≥ 0 但需归一到 0~100 |

> **权重合计 = 1.0**：综合得分 = Σ contribution；前端可直接渲染柱图。

### 2.4 错误码

| 场景 | 错误码 | HTTP |
|---|---|---|
| period 格式错 | `PARAM_INVALID` | 400 |
| 权限不足 | `FORBIDDEN` | 403 |
| 未登录 | `UNAUTHORIZED` | 401 |

## 6. 安全审查点

| 项 | 措施 |
|---|---|
| 横向越权 | 必须 `requireInternal()`；不允许跨人查 |
| SQL 注入 | 仅用 `LambdaQueryWrapper.eq(personId, actor.id)`，无字符串拼 |
| 多租户 | `actor.groupId` 隐式过滤（如未来分产品组数据隔离，本卡不写） |
| 审计 | 暂不落（P3-1.2 接管），但 Controller 写操作仅限查询，无写入 |
| 限流 | `@RateLimiter` 不上（KPI 是月度查询，频率极低） |
