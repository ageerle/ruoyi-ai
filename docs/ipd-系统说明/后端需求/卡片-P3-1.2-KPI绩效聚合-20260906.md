# 卡片 P3-1.2 — 共担 KPI 归集与绩效分级聚合（2026-09-06）

> **单写者模式落地卡**：49 页卡矩阵中 P0-10.30 KPI 考核-共担 KPI 归集后端空实现补齐。
> **范围**：基于既有 `AllowanceLedgerService`（P3-3.1 锁定评级+封顶）+ `BonusPoolService`（P3-4.2/4.3 阶梯系数）+ `ProjectScoreService`（P3-2.1 加权汇总），按 KpiLevel（L1~L5 + 综合）6 个桶聚合输出。
> **新增端点**：`/api/v1/kpi/performance`

## 1. 业务规则映射

| 业务规则 | 来源 | 实现位置 |
|---|---|---|
| BR-KPI-08 双 PM 各自独立评分 | ZK-IPD §三.2.1 | `ProjectScoreService.PM_ROLES` |
| BR-INC-04~09 奖金池阶梯系数 | ZK-IPD §三.2.1 | `BonusPoolService.tierCoefficientOf` |
| AC-KPI-22 等级 vs 绩效不互相推导 | 验收清单 §KPI | `ProjectScoreService.assertNoAbilityInference` |
| AC-KPI-16b 20/40/40 权重 | 验收清单 §KPI | `ProjectScoreService.WEIGHT_*` |
| AC-KPI-17~21 阶梯系数 6 档 | 验收清单 §KPI | `BonusPoolService.DEFAULT_THRESHOLDS` |

## 2. API 契约

### 2.1 端点：`GET /api/v1/kpi/performance`

| 项 | 值 |
|---|---|
| 路径 | `/api/v1/kpi/performance` |
| 权限码 | `ipd:kpi:query`（MARKET_PM / RD_PM / GROUP_LEADER / SUPER_ADMIN） |
| 入参 | `period`（YYYY-MM，必填） |
| 出参 | `ApiV1Response<Map<String, BigDecimal>>`（key = KpiLevel，value = 聚合值） |

### 2.2 响应：`Map<KpiLevel, BigDecimal>`

KpiLevel 枚举（6 桶）：

| KpiLevel | 数据源 | 聚合口径 |
|---|---|---|
| `L1` | `allowance_ledgers` 中 `lockedLevel='L1'` 的 `finalAmount` 之和 | 津贴总额 |
| `L2` | 同上 `lockedLevel='L2'` | 同上 |
| `L3` | 同上 `lockedLevel='L3'` | 同上 |
| `L4` | 同上 `lockedLevel='L4'` | 同上 |
| `L5` | 同上 `lockedLevel='L5'` | 同上 |
| `COMPREHENSIVE` | `project_scores` 当期 `weightedScore` 经 `BonusPoolService.tierCoefficientOf` 映射（0~1.2 系数 → 0~100 分） | 加权汇总×100 |

### 2.3 数据流

```text
input: actor + period
  ├─ AllowanceLedgerService ──── LambdaQueryWrapper(personId=actor.id, month=period)
  │                              └─ 按 lockedLevel 分桶求和 finalAmount
  ├─ ProjectScoreService ────── LambdaQueryWrapper(personId=actor.id, period=period)
  │                              └─ 加权汇总 → 0~100
  └─ BonusPoolService ────────── tierCoefficientOf(achievementRate)
                                  └─ 0/0.3/0.6/0.8/1.0/1.2
output: Map { L1, L2, L3, L4, L5, COMPREHENSIVE }
```

### 2.4 错误码

| 场景 | 错误码 | HTTP |
|---|---|---|
| period 错 | `PARAM_INVALID` | 400 |
| 权限不足 | `FORBIDDEN` | 403 |

## 3. 数据库变更

**无新增 DDL**：`allowance_ledgers` / `project_scores` / `bonus_pools` 既有表满足。

## 4. 复用清单

- `AllowanceLedgerService.calcFinalAmount`（P3-3.1 封顶计算） → L1~L5
- `ProjectScoreService.weighted`（P3-2.1 加权汇总） → COMPREHENSIVE
- `BonusPoolService.tierCoefficientOf`（P3-4.2 阶梯系数） → COMPREHENSIVE 系数映射
- `LambdaQueryWrapper.eq(personId, ...)` → 横向越权防护
- `Map.entry / Collectors.groupingBy` → 分桶聚合

## 5. 测试矩阵（6 维度）

| 维度 | 用例 |
|---|---|
| 正常路径 | 三源齐备 → Map 6 桶均有非零值 |
| 边界 | actor 当期无任何记录 → Map 6 桶均为 BigDecimal.ZERO |
| 异常 | period="abc" → 抛 `IpdBusinessException` |
| 权限 | 非内部角色 → 抛 `IpdPermissionException` |
| 审计 | 落审计日志（`AuditLogService.append`，`bizType="KPI_PERFORMANCE"`） |
| 幂等 | 多次调用 Map 内容稳定（不重复落审计） |

## 6. 安全审查点

| 项 | 措施 |
|---|---|
| 横向越权 | LambdaQueryWrapper 必须含 `personId=actor.id` |
| 审计 | 仅查询操作，不落审计；查询频率低，不需要 `@RateLimiter` |
| 多租户 | 当前阶段同租户共享，本卡不写 `tenantId` 过滤 |
| SQL 注入 | 全 LambdaQueryWrapper |

## 7. 与 P3-1.1 的关系

P3-1.1 计算「功能 KPI 来源」（按数据源拆解），P3-1.2 计算「绩效 KPI 聚合」（按等级分桶）；两者输入相同 `actor + period`，但视角不同：
- P3-1.1 给前端看「这个 KPI 是怎么算出来的」（来源+权重+贡献）
- P3-1.2 给前端看「这个 KPI 落在哪个等级」（L1~L5 + 综合）

两者数据源有交集（ProjectScore），但 P3-1.1 取 weightedScore，P3-1.2 经 BonusPool 系数再乘 100。
