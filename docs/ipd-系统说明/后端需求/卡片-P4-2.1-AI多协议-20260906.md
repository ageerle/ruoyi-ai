## 1. 接口设计

### 1.1 抽象接口（`service/ai/AiProviderTester.java`）

```java
public interface AiProviderTester {
    /** 主 provider 名（用于审计 / 默认匹配） */
    String provider();

    /** 该 tester 兼容的 provider 集合（大小写不敏感）。 */
    Set<String> aliases();

    /** 探测连接是否可用——失败消息不得含 apiKey/密文片段。 */
    AiTestResult test(AiTestConfig cfg);
}
```

### 1.2 数据载体

| 类型 | 字段 |
|---|---|
| `AiTestConfig` | `provider, baseUrl, apiKey, modelName, timeoutMs` |
| `AiTestResult` | `success(boolean), latencyMs(long), errorCode(String), errorMessage(String)` |

### 1.3 派发器（`service/ai/ProviderRegistry.java`）

```java
public final class ProviderRegistry {
    private final List<AiProviderTester> testers;
    public ProviderRegistry(List<AiProviderTester> testers) { ... }
    public AiProviderTester find(String provider) { /* 按 aliases 大小写不敏感匹配；null/空 → DefaultTester */ }
    public List<AiProviderTester> all() { return List.copyOf(testers); }
}
```

### 1.4 各 Provider 实现

| Tester | provider() | aliases | 协议要点 |
|---|---|---|---|
| `OpenAiCompatibleTester` | `openai` | openai / deepseek / qwen / moonshot / MiniMax | POST `{base}/chat/completions`，`Authorization: Bearer {key}`，`{"model":"...","messages":[{"role":"user","content":"."}],"max_tokens":1}`；HTTP 2xx 成功 |
| `ZhipuTester` | `zhipu` | zhipu / glm | POST `{base}/api/paas/v4/chat/completions`，`Authorization: Bearer {key}`，body 同 OpenAI |
| `BaiduTester` | `baidu` | baidu / qianfan | POST `{base}/oauth/2.0/token`（grant_type=client_credentials&client_id={key}&client_secret=…），HTTP 2xx 成功 |
| `OllamaTester` | `ollama` | ollama | GET `{base}/api/tags`，无 auth，2xx 成功 |
| `DefaultTester` | `default` | （永远 fallback） | GET `{base}`，无 auth，2xx 成功（保留 SSRF 防护） |

> **JDK 自带 `java.net.http.HttpClient` 实现**——无新依赖。

## 2. 业务规则

| BR 编码 | 规则 | 落点 |
|---|---|---|
| BR-AI-PROV-01 | provider 字段大小写不敏感；未匹配任何 tester 时走 `DefaultTester`（不阻断） | `ProviderRegistry.find` |
| BR-AI-PROV-02 | apiKey **绝不**出现在 `errorMessage`（含 stacktrace 类名截断）或日志 | `AiModelConfigService.testConnect` 落 message 前 mask + Tester 内部不得拼接 key |
| BR-AI-PROV-03 | SSRF 防护仍由 `AiModelConfigService.testConnect` 在分发前完成（host 解析黑名单与现有逻辑保持一致） | `service.probe` SSRF 段 |
| BR-AI-PROV-04 | 探测超时统一 5 秒（connect + read），与现有约定一致 | `AiTestConfig.timeoutMs` 默认 5000 |
| BR-AI-PROV-05 | 失败消息白名单化：仅含 `host` + 失败类别（UNREACHABLE / TIMEOUT / AUTH_FAILED / HTTP_<code> / UNSUPPORTED_PROTOCOL） | `AiTestResult.errorCode` |
| BR-AI-PROV-06 | 测试结果只回 `AiModelView`，不回 `AiTestResult` 原文——前端契约不变 | controller 层 |
| BR-AI-PROV-07 | 审计 `TEST_CONNECT` 不变：afterData 仍为 maskedKey/provider/model/enabled | `service.audit` |

## 6. 安全审查点

| 风险 | 校验 | 落点 |
|---|---|---|
| apiKey 泄露到日志/异常消息 | Tester 内部禁止字符串拼接 key；Service 落 message 前 mask | `AiTestResult.errorMessage` / `AiModelView.maskedKey` |
| SSRF | 已有 ssrfBlockReason 拦截 loopback/私网 | `service.probe` 前置 |
| 越权 | testConnect 仍只允超管 | controller 既有 `@SaCheckPermission("ipd:ai-model:edit")` |
| 注入 | Tester 构造请求用 `HttpRequest.BodyPublishers.ofString(json)` 序列化，无字符串拼接 URL | Tester 实现 |
