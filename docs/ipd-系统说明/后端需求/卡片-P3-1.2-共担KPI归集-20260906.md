| 规则 | 口径 | 实现 |

## 2. API 契约

### 2.1 POST `/api/v1/kpi/shared`

- 登录类型：`IpdAuthSession.LOGIN_TYPE`
- 对象级权限：服务层重新获取当前会话人，要求 `GROUP_LEADER|SUPER_ADMIN`；超管可跨组。
- 请求体：

```json
{
  "projectId": 1,
  "period": "2026-08",
  "actualSales": "400",
  "targetSales": "500",
  "actualChannels": "60",
  "targetChannels": 80,
  "promoters": 50,
  "detractors": 15,
  "npsSampleSize": 29,
  "landedScenarios": 3,
  "plannedScenarios": 4
}
```

- 响应：`ApiV1Response<SharedKpiCollectView>`
- `sharedScore`：有效指标得分按 `0.15/0.10/0.10/0.05` 加权后归一到 100 分。
- 任一指标 `included=false` 时不进入分子和分母；这保证缺失指标不伪造也不隐性折算。

### 2.2 明细字段

| 指标 | 来源 | 目标/实际口径 |
|---|---|---|
| K01 | `FINANCE_OR_ERP` | 实际销售额 / 项目目标销售额 |
| K02 | `CHANNEL_CRM` | 实际签约渠道 / 项目目标渠道 |
| K03 | `NPS_SURVEY` | (推荐者-贬损者) / 项目 NPS 目标；样本不足排除 |
| K04 | `SALES_ACCEPTANCE` | 落地场景 / 规划场景 |

## 6. 安全审查点

- 横向越权：PM 不能写；组长只能访问项目主组或其双 PM 所在组。
- 审计身份：禁用实体请求透传 `scoredBy`，由 `actor.id()` 绑定。
- 审计载荷：只写来源、版本、指标和参与人白名单。
- 金额：只读 `DECIMAL(18,2)` 字段，Java 使用 `BigDecimal`，不使用 `float`。
- 幂等：双 PM 在同一事务内写入；版本由数据库唯一索引兜底。
