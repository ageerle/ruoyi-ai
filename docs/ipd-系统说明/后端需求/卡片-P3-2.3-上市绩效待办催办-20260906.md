# 卡片 P3-2.3 — 上市 30 日项目绩效待办与逾期催办（2026-09-06）

> 目标：项目在 L08 上市日期后生成双 PM 自评和双产品组长评定的 30/90 日待办；日期变更不重复建单。

## 1. 业务规则映射

| 规则 | 口径 | 实现 |
|---|---|---|
| BR-KPI-08 | 上市后 30 日内完成项目绩效评定 | `SELF_SCORING` due=launch+30 |
| BR-INC-07 | 最迟不晚于上市后 90 日复盘 | `LEADER_REVIEW` due=launch+90 |
| AC-KPI-17 | 上市后 30 日内生成两 PM 评分待办 | `scanLaunchedProjects` 双 PM 任务 |
| AC-KPI-18 | 双 PM 自评 + 各自产品组长评定 | 任务目标与 `ProjectScoreArchiveService` 身份校验 |
| 逾期提醒 | 逾期日通知责任人 | `NotificationService` ACTION outbox |
| 日期更正 | 新上市日期更新旧任务截止日，不新增任务行 | 唯一键 + `updateById` 重排 |
| 不自动关闭 | 扫描只提醒，不改 PENDING 状态 | 无状态自动变更 |

## 2. API 契约

### `POST /api/v1/project-score-tasks/scan`

- 仅超管可手动触发；`LocalDate.now()` 作为扫描日期。
- 返回 `ScheduleScanResult(createdTasks,selfTasks,leaderTasks,reminders,escalations,updatedTasks)`。
- OPS-04 调度器可调用同一 Service 方法；扫描不要求业务写权限。

## 3. 数据模型

迁移：`docs/script/sql/update/2026-09-06-ipd-p323-project-score-tasks.sql`

表 `project_score_tasks` 唯一键 `(project_id,person_id,target_type,tenant_id)`，保证日期重排只更新既有行。任务保留 `launch_date_snapshot`，用于审计和重算原因追踪。

## 4. 复用清单

- `Project.launchDate`（L08 锚点）。
- `ProjectMemberMapper`、`PersonMapper`、`ProductGroupMapper` 获取双 PM 和产品组 leader。
- `NotificationService.publish` 复用 receiver 级 `dedup_key`，重复扫描不产生新事件。
- `AuditLogService.append` 记录创建、重排、提醒、升级。
- `ProjectScoreArchiveService` 后续提交目标组件；待办扫描不伪造评分。
- MyBatis-Plus `LambdaQueryWrapper`、`@TableLogic` 软删除，无新 ORM/认证。

## 6. 安全审查点

- 组长目标：只从 `product_groups.leader_person_id` 读取，不接受请求中的 leaderId。
- 横向越权：扫描只读项目/成员；没有代评/改分通道。
- 幂等：唯一键约束，重复扫描不新增任务；通知使用 outbox 幂等键。
- 日期安全：只处理 `launchDate != null`，更正只改变 `due_at` 并写审计。
- 状态：不自动关闭、删除或改变 `PENDING`。
