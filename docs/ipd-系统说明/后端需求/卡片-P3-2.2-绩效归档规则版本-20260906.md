## 2. API 契约

### 2.1 `POST /api/v1/project-scores`

请求：

```json
{
  "projectId": 1,
  "personId": 101,
  "componentType": "MARKET_LEADER",
  "score": 90,
  "reason": "市场侧组长评定"
}
```

`componentType`：`SELF|MARKET_LEADER|RD_LEADER`。

- `SELF`：`actor.id == personId` 且 actor 角色与被评 PM 角色一致。
- `MARKET_LEADER/RD_LEADER`：仅 `GROUP_LEADER`，且必须是该 PM 所在 `product_groups.leader_person_id`；超管只做监督，不代评。
- 分数范围 `[0,100]`，统一 `DECIMAL(5,2)`。

### 2.2 `GET /api/v1/project-scores/{projectId}/{personId}`

返回当前最高共同版本的 `ProjectScoreView`；未凑齐三组件时 `settled=false`，不伪造综合分。

### 2.3 `GET /api/v1/project-scores/{projectId}/{personId}/settle`

要求三组件已全部归档，否则 `STATE_CONFLICT`；返回的 `versionNo/ruleVersion/ruleSnapshot` 不可由当前配置覆盖。

## 6. 安全审查点

- 角色：禁止 `ADMIN`、`REVIEW_LEADER` 等不存在角色；组长身份只认产品组 leader。
- 横向越权：组长不能评另一组 PM；自评不能替别人。
- 审计身份：不接受请求携带 authorId；由当前 actor 绑定。
- 历史一致性：结算不读当前 `SystemConfigService`，只读归档规则快照。
- 金额/评分：BigDecimal + 0~100 范围，不使用浮点。
- 并发：组件版本查询带 `LIMIT 1 FOR UPDATE`；唯一键兜底。
