# 卡片 P3-1.3 — KPI 历史趋势（项目详情-KPI 考核）（2026-09-06）

> **单写者模式落地卡**：49 页卡矩阵中 P0-10.32 项目详情-KPI 考核后端空实现补齐。
> **范围**：基于既有 `kpi_records` 表（`KpiRecord` 域已落地），按月回看 actor 的综合得分趋势。
> **新增端点**：`/api/v1/kpi/trend`

## 1. 业务规则映射

| 业务规则 | 来源 | 实现位置 |
|---|---|---|
| BR-KPI-04 综合得分存于 `kpi_records.comprehensive_score` | ZK-IPD §三.2.1 | `KpiRecord.comprehensiveScore` |
| AC-KPI-22 等级 vs 绩效不互相推导 | 验收清单 §KPI | `KpiRecord.comprehensiveScore` 来自 `kpi_records.comprehensive_score` 列，与 `persons.level` 独立 |
| AC-DASH-01~03 趋势图按月回看 | ZK-IPD §三.3 | 本卡响应 `List<TrendPoint>` 长度 = `periods`（默认 12） |

## 2. API 契约

### 2.1 端点：`GET /api/v1/kpi/trend`

| 项 | 值 |
|---|---|
| 路径 | `/api/v1/kpi/trend` |
| 权限码 | `ipd:kpi:query`（MARKET_PM / RD_PM / GROUP_LEADER / SUPER_ADMIN） |
| 入参 | `personId`（可选；缺省 = actor.id，PM 只能查自己，组长/超管可指定）<br>`periods`（可选；缺省 = 12；上限 36） |
| 出参 | `ApiV1Response<List<TrendPoint>>` |

### 2.2 响应：`TrendPoint`

```java
public record TrendPoint(
    String period,         // YYYY-MM
    BigDecimal value,      // 综合得分（0~100）；缺数 = 0
    String source,         // DATA | MISSING
    Long recordId          // kpi_records.id；缺数 = null
) { }
```

### 2.3 数据流

```text
input: actor + periods
  ├─ 计算起始月 = today.minusMonths(periods - 1)
  ├─ LambdaQueryWrapper(personId=actor.id, period>=start, period<=today)
  ├─ 按 period 升序
  └─ 缺失月补 0（DATA→MISSING）
output: List<TrendPoint>，长度 = periods
```

### 2.4 错误码

| 场景 | 错误码 | HTTP |
|---|---|---|
| personId 不属于 actor 范围 | `FORBIDDEN` | 403 |
| periods 越界（< 1 或 > 36） | `PARAM_INVALID` | 400 |

## 3. 数据库变更

**无新增 DDL**：`kpi_records` 表 + `comprehensive_score` 列已存在（`2026-09-04-ipd-p0-tables.sql` L511-533）。

## 4. 复用清单

- `KpiRecordMapper.selectList(LambdaQueryWrapper)` → DB 查询
- `LambdaQueryWrapper.between(period, start, end)` → 月份范围
- `IpdPermission.requireInternal` → 权限校验
- 自定义 `canQueryPerson(actor, personId)` → 横向越权防护（PM 只能查自己）

## 5. 测试矩阵（6 维度）

| 维度 | 用例 |
|---|---|
| 正常路径 | 6 条记录 → 返回 12 个 TrendPoint（含 6 缺失月补 0） |
| 边界 | actor 无任何记录 → 返回 periods 个 TrendPoint（value=0/source=MISSING） |
| 异常 | periods=0 / periods=100 → 抛 `IpdBusinessException` |
| 权限 | MARKET_PM 试图查 RD_PM 的 personId → 抛 `IpdPermissionException` |
| 审计 | 仅查询，不落审计 |
| 幂等 | 多次调用顺序与值稳定 |

## 6. 安全审查点

| 项 | 措施 |
|---|---|
| 横向越权 | PM 仅查自己；组长/超管可指定 personId |
| SQL 注入 | 全 LambdaQueryWrapper |
| 时序 | period 升序，避免前端倒序展示错位 |
| 缓存 | 命中率低（月度查询），本卡不引入 Redis 缓存 |
| 缺数处理 | 缺失月补 MISSING 点，前端可绘制虚线 / 跳过 |
