## 2. 命名与编码规范（必须一致）

### 2.1 Java 编码

| 项 | 规范 | 反例 |
|---|---|---|
| 包名 | `org.ruoyi.ipd.<layer>.<domain>` | `com.xxx` |
| 类名 | 大驼峰，业务前缀+语义 | `ProjectService` 而非 `ProjectSvc` |
| 方法名 | 小驼峰，动词开头 | `findById` 而非 `query` |
| Service 方法 | `xxx / xxxOnBehalf / accept / inbox` 公开 + 私有 `_helper` | 公开方法精简 |
| Controller | `@RestController` + `@RequestMapping("/api/v1/<resource>")` | 不混 `@Controller` 返回视图 |
| 路径变量 | `@PathVariable Long id` | 不用 String id |
| 时间字段 | `new Date()` 或 `LocalDateTime.now()`，DB 列 DATETIME | 不用 String |
| 枚举 | 大写常量值；新增枚举在 `ApiV1ErrorCode` 登记 | 字符串魔法值散落 |
| 软删除列 | `del_flag='0'`（有效） / `'1'`（删除） | 不用 boolean |
| 多租户列 | 实体继承 `BaseEntity` 自带 `tenantId` | 不手动加 |
| 审计四字段 | `BaseEntity` 自带 `createBy/createTime/updateBy/updateTime` | 不手动加 |
| Lombok | `@Data @Builder @RequiredArgsConstructor` | 不写 getter/setter |
| MapStruct-Plus | `IConvert` 接口 + `Impl` 后缀实现类 | 不用手写 mapper |

### 2.2 注释规范

| 项 | 规范 |
|---|---|
| 类注释 | 简述 + AC/BR 锚点 + 与卡号挂钩（如 `P3-1.1`） |
| 方法注释 | 入参/出参/抛错 + 业务规则（如 `BR-PROD-01`） |
| 行内注释 | 仅解释"为什么"，不重复"做了什么" |
| TODO | 严禁遗留未处理 TODO；如需 TODO 必带卡号 |
| FIXME | 同上；并须登记看板 |

### 2.3 SQL/DDL 规范

| 项 | 规范 | 证据 |
|---|---|---|
| 表名前缀 | `projects` / `person` / `handover` 等单数或业务前缀；不混 snake+Pascal | DB migration 已铺 |
| 软删除列 | `del_flag CHAR(1) DEFAULT '0'` | 全部 SoftDeletable 实体 |
| 时间列 | `create_time` / `update_time` DATETIME DEFAULT CURRENT_TIMESTAMP | BaseEntity 自带 |
| 审计列 | `create_by` / `update_by` BIGINT | BaseEntity 自带 |
| 索引 | `uk_xxx` 唯一 / `idx_xxx` 普通；命名小写 | DDL 已铺 |
| 字段注释 | COMMENT 必填，含 ZK-IPD §X.X.X 锚点 | DDL 已铺 |
| 迁移脚本 | `docs/script/sql/update/2026-09-06-ipd-<card>-<topic>.sql` | 已有 12+ 范本 |
| 租户共享表 | 父 `application.yml` `tenant.excludes` 登记 | 已铺 `trace_run/trace_node` |

### 2.4 API 契约规范

| 项 | 规范 | 证据 |
|---|---|---|
| 路径前缀 | `/api/v1/<resource>` 全部走 v1 | 31 个控制器一致 |
| HTTP 语义 | GET 查 / POST 增改 / DELETE 删 / PUT 仅个别更新 | 全仓遵守 |
| 请求体 | `@RequestBody @Valid` + DTO（驼峰命名） | 普遍 |
| 响应包络 | `ApiV1Response<T>` 含 `code/msg/data` | 文档 §2.2 |
| 错误码 | `ApiV1ErrorCode` 枚举值 | 集中登记 |
| 分页 | 入参 `PageQuery`（pageNum/pageSize）；出参 `TableDataInfo` | 既有 |
| 列表/详情 | 列表 `R` 类；详情 `View` 类（脱敏/组装） | 普遍 |
| 批量操作 | 接受 `List<Long>` 或 `IDS`，返回受影响行数 | 普遍 |
| 审计响应 | 写操作必返 `entityId`，前端可深链 | 普遍 |

### 2.5 测试规范

| 项 | 规范 |
|---|---|
| 包路径 | `src/test/java/org/ruoyi/ipd/<与main一致>/` |
| Tag | `@Tag("dev")` 必加（surefire `groups=${profiles.active}` 过滤） |
| 排除 | `@Tag("exclude")` 永不跑 |
| 单测框架 | JUnit 5 + Mockito + AssertJ |
| 覆盖维度 | 6 维度：正常路径 / 边界 / 异常 / 并发 / 权限 / 审计 |
| 真库验收 | `mvn test -pl ruoyi-modules/ruoyi-ipd -Dtest=XxxAcceptanceTest` |
| HTTP 端到端 | `@SpringBootTest(webEnvironment=RANDOM_PORT)` + TestRestTemplate |
| 不要 | 不要在测试里 `Thread.sleep` 做"等异步"——用 `Awaitility` |

## 3. 与项目"四套已就绪"的协作

### 3.1 与 4 个 agent 的边界（CLAUDE.md 已定义）

| Agent | 触发 | 范围 |
|---|---|---|
| `code-reviewer` | 改 Java 文件 | 架构 / 可读性 / 并发 / Spring 用法 |
| `langchain4j-agent-reviewer` | 改 `ruoyi-chat` / `ruoyi-aiflow` | prompt / token / MCP / RAG |
| `security-reviewer` | 改 controller / service / config / yml | 多租户 / Sa-Token / 加解密 / XSS / SQL 注入 |
| `performance-analyzer` | 改 mapper / service / AI | SQL / Redis / 连接池 / token 成本 |

> 本仓 `Ipd` 模块改任何文件，**至少 `code-reviewer + security-reviewer` 双审**，
> 改 Langchain4j 模块加 `langchain4j-agent-reviewer`，改 mapper/service 加 `performance-analyzer`。

### 3.2 与 4 个 skill 的入口

| Skill | 调用时机 |
|---|---|
| `/ai-module-add` | 加 Langchain4j agent / tool / workflow 节点 |
| `/gen-test` | 按 `@Tag("dev")` 规范生成 Service/Controller 单测 |
| `/api-contract` | 改 controller/DTO 后生成 OpenAPI 增量 diff |
| `/db-migration` | 加表 / 加字段 / 加索引 / 登记租户共享表 |

### 3.3 与 5 个 hook 的硬约束

| Hook | 类型 | 触发 | 行为 |
|---|---|---|---|
| `sensitive-field-guard.cjs` | PreToolUse | Write/Edit/MultiEdit | 阻断 `.env*`/`application-prod.yml`/PEM 私钥 |
| `pom-edit-hint.cjs` | PostToolUse | pom.xml | 5 类同步项提示 |
| `block-dangerous-git.sh` | PreToolUse | Bash | 阻断 `git push`/`reset --hard`/clean -f 等 |
| `pre-java-yml-write.sh` | PreToolUse | Write/Edit/MultiEdit | OPS-09 并发写守卫（`SKIP_CONCURRENT_WRITE=1` 绕过） |
| `post-java-yml-write.sh` | PostToolUse | Write/Edit/MultiEdit | 审计日志登记 |

> 本仓所有 P3/P4 卡片落地**必须**经过这 5 道 hook；不许 `git push`（owner 红线）。

## 4. 卡落地模板（按本规范）

> 每张 P3/P4 卡执行时，按下列顺序产出：

```
1. docs/ipd-系统说明/后端需求/<card>-<topic>-20260906.md
   ├── 业务规则映射（ZK-IPD §X）
   ├── API 契约（路径/入参/出参/错误码）
   ├── 数据库变更（DDL + 回滚）
   ├── 复用清单（用 §1.3 哪几项）
   ├── 测试矩阵（6 维度）
   └── 安全审查点（横向越权/SQL 注入/XSS/审计/限流）

2. 代码实现
   ├── domain (若新表)
   ├── mapper
   ├── service（私有方法 + 公开方法）
   ├── controller（DTO/View）
   └── test（@Tag("dev")）

3. 迁移脚本 docs/script/sql/update/2026-09-06-ipd-<card>-<topic>.sql

4. 看板更新（U0 卡 → 子卡 done → 父卡 inreview）

5. commit（fix/perf/refactor 之一；owner 红线：不写半成品）
```
