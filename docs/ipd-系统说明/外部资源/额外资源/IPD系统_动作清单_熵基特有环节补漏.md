# IPD 动作清单 — 熵基特有环节补漏审查表

> 日期：2026-09-02
> 配套文件：`IPD系统_六阶段标准动作清单_v2.md`（现有 64 个动作）
> **用途**：现有动作清单是按通用 IPD 框架 + 硬件/软件/解决方案三类产品拟的。这一份专门列**熵基特有、但通用框架里不会有**的环节，请你逐条判定要不要做成建制动作。

---

## 我的整体判断

现有 64 个动作里，**技术侧只做到了"研发PM 完成到哪一步"的粗粒度登记**，这对通用产品够用，但对熵基有两个问题：

1. **BioCV 算法是熵基最核心的技术资产**，但在整个清单里几乎不可见——只在 C05「技术可行性预研」里一笔带过。算法训练、评测、跨人种适配这些真正决定产品成败的环节，目前没有任何落脚点。
2. **生物特征数据的合规风险是红线级**，不是"有则更好"。GDPR 把生物特征列为特殊类别数据，国内《人脸识别技术应用安全管理办法》和个保法也有硬约束，一旦出问题不是流程问题而是法律问题。现在只有 V02 认证送检里顺带提了一句 GDPR。

下面 10 项按「不做的后果」排序。

## 六、两个需要你顺带确认的改进点

| #      | 改进点                          | 说明                                                                                                                                                               | 你的意见        |
| ------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| **M1** | **V02 认证送检应改为「按目标市场配置认证清单」** | 现在写死成"CE/FCC/CCC/等保/GDPR"不够用——沙特要 SABER、巴西要 ANATEL、印度要 BIS、韩国要 KC、北美要 UL。建议做成**国别认证清单模板库**，项目选了目标区域就自动带出对应认证项（CE/FCC/UL/RoHS/REACH/SABER/ANATEL/BIS/KC…），超管可后台维护 | 写出常用的+其他补充； |
| **M2** | **C05 技术可行性预研建议升级为深管**       | 现在是轻管。但对熵基来说，BioCV 算法可行性（识别率能否达标、算力够不够、成本能否接受）往往**决定项目生死**。建议改为深管，强制上传预研结论。或者：不整体升级，而是**当项目涉及 BioCV 算法时自动升级为深管**（与 Z06 同样的条件触发机制）                                | 继续轻管        |

## 七、如果全部采纳，清单会变成什么样

| 项                | 当前          | 采纳后                                        |
| ---------------- | ----------- | ------------------------------------------ |
| 动作总数             | 64          | **71**（新增 Z01–Z07 共 7 个）                   |
| 深管               | 39          | **44**（Z02/Z03/Z05 深管 + Z09 升级 + M2 可能 +1） |
| 轻管               | 25          | **27**（Z01/Z04/Z07）                        |
| 条件触发动作           | 0           | **2**（Z06 BCI、Z07 海外制造）                    |
| 全等级阻断（S/A/B 均阻断） | 仅 Gate 与认证类 | +2（Z03 生物特征合规、Z06 BCI 合规）                  |

**对研发PM 的负担影响**：新增 7 个动作里只有 3 个是轻管（Z01/Z04/Z07），且都是"登记结论"级别，不强制传文件。Z06/Z07 是条件触发，大多数项目不会遇到。**不会破坏你定的"研发阶段轻管"原则**。
