# IPD 产品经理管理系统 — AI 开发主 Prompt v2

> **用法**：将本文件整体作为上下文投喂给 AI Coding 工具（Cursor / Claude Code / Codex 等），按第 8 节的 P0–P4 阶段顺序推进，**每阶段结束必须跑通验证后再进入下一阶段**。
> **业务依据**：《双产品经理绩效考核制度 V3.1》（熵基科技·全球市场及产品共享中心·2026.08.13 执行稿）+ 决策表已确认项。
> **配套文件**：`IPD系统_六阶段标准动作清单_v2.md`（64 个动作定义，本文件第 3.4 节引用，开发时必须一并读取）。
> **定位**：面向市场PM 的产品流程管理工具。市场PM 主战场（概念/需求定义/发布/生命周期）深度管理，研发PM 主战场（开发/验证）轻量登记。

## 0. 全局硬约束（最高优先级）

**G-01 业务闭环**：所有流程必须有发起、处理、审核、结果、记录、归档六个环节。禁止存在无出口的流程节点。
**G-02 权限隔离**：三层角色（超级管理员 / 产品组长 / 普通PM）权限严格隔离。编辑可自主，**删除必须走申请审核**，任何人无直接删除权限。
**G-03 审计留痕**：所有新增、编辑、审核、驳回、删除、移交、参数修改、人员同步、登录凭证变更全部写入审计日志。日志只追加、不可修改、不可删除。
**G-04 制度优先**：本文件参数与源需求文档冲突时，**以本文件（对齐 V3.1）为准**。冲突清单见第 9 节。
**G-05 参数可配置**：所有系数、阈值、期限、额度必须落库为后台可配置参数表，**禁止硬编码在业务逻辑中**。
**G-06 无绝对化承诺**：不要生成"100%闭环""无遗留疑问"这类文案。未知状态显式展示为"待补充""未配置"。
**G-07 中文界面**：全中文。所有文案抽离为 i18n 资源文件，数据库文本字段预留多语言 JSONB 扩展位，一期只填 `zh-CN`。
**G-08 待裁决项必须可切换**：第 9.2 节的 6 项（奖金池基数、销售额口径、绩效系数取值、系数定值主体、池分摊方式、上市锚点）当前存在制度歧义未最终裁定。**必须实现为配置开关，切换口径只改配置不改代码**。相关公式一律走参数服务取值，不得在代码中出现字面量。

### TS-03 编码规范

- 前后端全量 TypeScript，**禁止 any**（确需时用 `unknown` + 类型守卫）
- 后端分层：Controller 只做参数校验与转发 → Service 承载业务逻辑 → Prisma 做数据访问。**业务逻辑不得写在 Controller**
- 所有写操作通过 `@Audit()` 装饰器自动记录审计日志（切面实现，不在业务代码里手写日志）
- 所有列表接口支持分页（page/size）+ 排序 + 筛选，返回统一结构 `{ list, total, page, size }`
- 所有接口返回统一包装：`{ code, message, data, timestamp, traceId }`，业务错误码见 TS-09
- 数据库所有表含 `id`(uuid) / `created_at` / `updated_at` / `deleted_at`（软删除）/ `created_by` / `updated_by`
- 金额字段用 `DECIMAL(18,2)`，**禁止用 float**
- 日期字段统一 `TIMESTAMPTZ`，前端展示转本地时区
- 枚举值全部落库为字典表或 PG enum，前端从字典接口取，不硬编码

### TS-07 状态机

| 实体 | 状态流转 |
|---|---|
| 项目 | DRAFT → TEAMING → ACTIVE →（SUSPENDED）→ ARCHIVED |
| 招标单 | OPEN →（SELECTED / EXPIRED / CLOSED） |
| Gate 评审 | PENDING →（APPROVED / REJECTED / ABSTAINED_TIMEOUT） |
| 删除申请 | DRAFT → LEADER_REVIEW →（ADMIN_REVIEW → DELETED / REJECTED） |
| 需求 | SUBMITTED → ACCEPTED → EVALUATING → SCHEDULED → PROCESSING → CLOSED / ARCHIVED |
| 移交 | DRAFT → CONFIRMED → COMPLETED |

### TS-08 审计日志防篡改

- 每条日志计算 `currHash = SHA256(prevHash + JSON(本条内容))`
- 提供 `/api/v1/audit-logs/verify` 接口做全链校验，返回断裂点
- 日志表**不开放 UPDATE/DELETE 权限**（PG 层 revoke），仅 INSERT

## 3. 业务规则规格

### 3.0 术语表（开发必须遵守，避免概念混用）

| 术语 | 定义 |
|---|---|
| **产品** | 一个可售卖的产品/产品线，是项目与需求的上层实体。一个产品下可有多个项目（改款/迭代/区域定制） |
| **项目** | 一次具体的研发过程实例，挂在一个产品下，绑定一对双PM |
| **双PM** | 市场PM + 研发PM 的固定组合，绑定项目全生命周期 |
| **市场PM** | 市场与客户代言人。决策"做什么产品、为哪个场景做、目标客户是谁、何时上市" |
| **研发PM** | 技术与可行性代言人。决策"技术路线、架构设计、创新方向、开发排期" |
| **深管动作** | 市场PM 主责动作，需完整管理（状态/记录/强制交付物/门禁阻断） |
| **轻管动作** | 研发PM 主责动作，仅登记完成状态 + 完成日期 + 备注 |
| **阻断性动作** | 未完成则禁止跳转到下一 IPD 阶段 |
| **评审上级** | 双PM 的共同直接上级，负责贡献度三方评定与仲裁终裁 |
| **需求** | 来自需求池的外部/内部输入 |
| **需求变更单** | 需求进入项目后触发的变更流程对象，走双签否决 |
| **主组 / 协同组** | 项目主组 = 市场PM 所在产品组；协同组 = 研发PM 所在产品组 |

### 3.1 组织与权限（BR-ORG）

**BR-ORG-01 跨组组队归属**：项目主组 = 市场PM 所在产品组；协同组 = 研发PM 所在产品组。两组组长均可查看该项目；删除初审由**主组组长**负责，协同组组长自动知会。

**BR-ORG-02 人员归属**：一个产品经理仅归属一个产品组。

**BR-ORG-03 组长兼任**：产品组长可以同时是项目的市场PM/研发PM，需超管单独授权，同样受 ≥3 项目校验约束。

**BR-ORG-04 组长来源**：产品组长由超管在后台手动维护，**不随第三方 API 同步**。支持设置"代理组长"（休假/出差期间代审），代理期可配置。

**BR-ORG-05 组长项目数**：组长不受"≥3 项目需评级委员会备案"约束；但绑定项目数 > 5 个时提醒超管备案。

**BR-ORG-06 三层权限矩阵**

| 能力 | 游客 | 普通PM | 产品组长 | 超级管理员 |
|---|---|---|---|---|
| 提交需求 | ✅ | ✅ | ✅ | ✅ |
| 查看项目 | — | 仅本人负责 | 本组全部 | 全部 |
| 编辑项目 | — | 仅本人负责 | 仅本人名下 | 全部 |
| 发起删除申请 | — | ✅ | ✅ | ✅ |
| 删除初审 | — | — | ✅（本组） | — |
| 删除终审 | — | — | — | ✅ |
| 调用 AI | — | ✅ | ✅ | ✅ |
| 配置系统参数 | — | — | — | ✅ |
| 导出审计日志 | — | 仅本人相关 | 本组 | 全局 |
| 人员维护 | — | — | — | ✅ |

**BR-ORG-07 游客权限**：仅可免登录提交需求 + 凭查询码查询进度。无任何审计、查看项目、导出权限。

### 3.2 人员与认证（BR-USER）

**BR-USER-01 人员来源**：市场PM/研发PM **禁止在系统页面手动新增**。数据源为第三方 HR API（一期：本地文件批量导入 + Mock 接口；二期：真实 API）。

**BR-USER-02 同步任务**：每月 1 日 02:00 执行定时 check，拉取新增人员、属性变更、离职状态。同步结果写入审计日志。

**BR-USER-03 同步字段**：姓名、工号、所属产品组、PM 类型、L1–L5 等级、在职/离职状态。

**BR-USER-04 登录方式一（账号密码）**：用户名 = 姓名。初始化分配默认密码，**无密码过期时间，但强制首次登录修改默认密码**，未修改前默认密码持续有效。密码修改写审计。

**BR-USER-05 登录方式二（企微扫码）**：一期 Mock（模拟授权页），保留标准 OAuth 接口位。企微账号须与系统内人员绑定后方可登录。

**BR-USER-06 离职处理（关键闭环）**：API 识别离职 → 自动解绑企微 + 禁止登录 + 在**该员所属产品组长**名下生成「待移交任务」+ 站内信/企微通知。组长须在 **15 个自然日**内完成项目移交，逾期自动升级超管告警。移交完成前项目保持只读可查、不可编辑。全部动作写审计。

**BR-USER-07 等级维护**：API 同步提供 L1–L5 初值，超管可覆盖调整（`levelSource = MANUAL_OVERRIDE`），每次调整写审计。

**BR-USER-08 角色兼任**：人员有主角色（API 同步），允许跨项目承担另一角色，需超管授权，写审计。

**BR-USER-09 游客查询码**：需求提交成功生成 8 位查询码，游客凭码在门户查询处理进度与结果（不登录、不可改）。

### 3.3 产品与项目（BR-PROD）

**BR-PROD-01 产品主数据（新增实体）**：系统必须提供产品 CRUD。产品是项目与需求的上层，一个产品下可有多个项目。需求挂在产品上，**按产品的负责双PM 路由**（这是源文档需求自动通知规则的实现前提）。

**BR-PROD-02 项目模板**：新建项目选择模板类型（硬件 / 软件 / 解决方案），自动挂载对应动作清单。

**BR-PROD-03 存量导入**：有权限人员导入在研项目 → 补录当前 IPD 阶段、历史资料、指定双PM → 接入完整流程。已过节点标记「历史缺失」并允许上传替代佐证，缺失项在审计日志中标记，**不阻断后续流程**。

**BR-PROD-04 在研项目适配（V3.1 §5.4）**
- 决策权：已过节点不追溯，未过节点双PM 接管
- 三个立即生效切入点：需求变更双签、上市节奏决策、上市后联合复盘
- 市场PM 补入后 **2 周内**必须完成「场景定义复核」，系统自动生成待办并倒计时；发现偏差走需求变更流程
- 功能KPI 补入前不追溯，补入后全量考核
- **共担市场结果 KPI 不分段、不打折，全量共担**
- 月度津贴从双PM 补入**次月**起按评级固定额发放
- 成功奖金与新建项目同一公式

**BR-PROD-05 项目归档**：生命周期阶段标记停产后归档，归档后仅允许查看、导出全部资料，禁止编辑、新增、修改、删除。

### 3.4 IPD 流程与动作（BR-IPD）

**BR-IPD-01 六阶段固化**：概念 / 计划 / 开发 / 验证 / 发布 / 生命周期运维。阶段固定不可删除，超管可后台自定义各阶段细则。

**BR-IPD-02 动作清单**：完整动作定义见配套文件 `IPD系统_六阶段标准动作清单_v2.md`（64 个动作）。开发时须将全部动作 seed 进数据库。

**BR-IPD-03 深管动作（市场PM 主责，35+4 个）**
- 状态流转：未开始 → 进行中 → 已完成 / 延期
- 强制上传至少 1 个交付物方可标记"已完成"
- 强制展示绑定的 SOP 富文本
- 阻断性动作未完成则禁止跳阶
- 到期前 3 天 / 逾期每天提醒主责人

**BR-IPD-04 轻管动作（研发PM 主责，25 个）— 界面只保留三字段**
- 完成状态（未开始 / 进行中 / 已完成 / 不适用）
- 实际完成日期（状态为"已完成"时必填）
- 备注（≤200 字，选填）
- **禁止实现**：强制交付物上传、强制 SOP 展示、执行记录富文本、阶段门禁阻断
- 附件上传保留入口但为可选，且不做任何校验

**BR-IPD-05 轻管例外**：涉及法规认证的轻管动作（P10 认证规划、V02 认证送检）保留阻断性，但同样不强制上传证书扫描件，只需登记「已通过 + 通过日期 + 证书编号（文本）」。

**BR-IPD-06 阶段门禁**：当前阶段阻断性动作未完成 → 禁止跳转下一阶段。阻断分级：S 级全阻断（37 个）、A 级约 24 个、B 级约 12 个（仅 Gate 关联 + 认证类）。分级规则后台可配置。

**BR-IPD-07 SOP 绑定**：每个深管动作绑定一份 SOP（富文本 + 附件上传入口），支持超管后台编辑，修改后新项目用新版本，在研项目保持原版本。

**BR-IPD-08 上市日期（关键锚点）**：发布阶段 L08 动作录入的 `launchDate` 是全部后置指标的起算原点——6 个月销售/回款统计窗口、90 天复盘、共担 KPI 评估。**该字段录入后不可随意修改，修改需双签 + 审计。**

**BR-IPD-09 阶段视图**：提供可视化流程视图（横向阶段条 + 动作清单），深管动作与轻管动作**视觉上必须可区分**（深管卡片式带交付物图标，轻管行式仅显示状态与日期）。

### 3.5 双PM 组队与招标（BR-TEAM）

**BR-TEAM-01 招标发起**：市场PM 发起新项目 → 发起研发PM 招标。两种模式：
- ① 一对一邀标：定向邀标指定研发PM，**仅限被邀本人应标，不可转发**
- ② 公开招标：面向全部研发PM

**BR-TEAM-02 招标有效期**：每个项目独立设置有效期。市场PM 可在有效期内修改招标条件、手动关闭招标单，操作写审计。

**BR-TEAM-03 拒绝应标**：研发PM 可拒绝应标，**拒绝行为不留系统痕迹**（不记录、不通知）。

**BR-TEAM-04 邀标转公开**：一对一邀标被拒后，市场PM 可手动改为公开招标，操作写审计。

**BR-TEAM-05 遴选与通知**：研发PM 应标后由市场PM 最终遴选。遴选完成须向**未中标者**发送站内信 + 企微通知告知结果，通知记录留痕。

**BR-TEAM-06 到期未遴选**：到期前 3 天提醒市场PM；到期自动进入「待遴选」挂起；挂起 7 日未操作，升级至其产品组长提醒。

**BR-TEAM-07 无人应标**：招标单自动关闭，项目转「待组队」挂起，允许市场PM 无限次重新发起；**挂起超 30 日，超管可直接指派研发PM**，指派记录写审计。

**BR-TEAM-08 角色互斥**：市场PM 不允许兼任本项目的研发PM。

**BR-TEAM-09 项目数校验**：同一 PM 绑定项目数 ≥ 3 时弹窗校验，须录入评级委员会审批备案记录，否则禁止绑定第 3 个及以上项目。

**BR-TEAM-10 组队完成**：确定双PM 后生成项目，自动挂载完整 IPD 流程与 Gate 机制，记录评级快照。

### 3.6 五大 Gate 与双签（BR-GATE）

**BR-GATE-01 五大联合 Gate**

| Gate | 名称 | 所在阶段 | 双签否决 |
|---|---|---|---|
| G1 | 立项 Go/No-Go | 概念阶段末（C11） | ✅ |
| G2 | 差异化确认 | 计划阶段末（P13） | — |
| G3 | 开发双周评审 | 开发阶段（D05，每两周） | — |
| G4 | GTM 就绪 | 发布阶段（L07） | — |
| G5 | 上市后 90 天复盘 | 生命周期（LC02） | ✅ |

**BR-GATE-02 强制附件**：Gate 评审附件（会议纪要、评审材料）为强制交付物，未上传则 Gate 无法闭环。

**BR-GATE-03 双签否决范围**：立项 Go/No-Go、需求变更审批、上市后复盘三项执行双签否决，任一方否决即驳回。其余按 RACI 分工，一方主导、一方参与咨询或知会备案。

**BR-GATE-04 并行签署与超时**：双签**并行**——双方独立提交，在双方都提交前**互不可见对方结论**。签署期限默认 **7 个自然日**（后台可配），到期前 1 天提醒；超期视为**弃权**，按主导方意见执行并记入审计日志。

**BR-GATE-05 否决后重新发起**：否决后需手动重新发起评审，**不限次数**；但第 3 轮起需双方产品组长列席。

**BR-GATE-06 冲突仲裁**：双PM 意见冲突无法一致 → 升级双方各自产品组长仲裁 → **两组仍不一致则升级超级管理员终裁**。仲裁/终裁结果写入项目审计日志永久归档。

**BR-GATE-07 需求变更路径**：需求池需求经 PM 评估 → 生成《需求变更单》→ 关联项目与 IPD 节点 → 走双签否决 → 通过后回写需求池状态为「已采纳」。**未闭环的变更单阻断所在阶段出口。**

**BR-GATE-08 RACI 矩阵（V3.1 §1.2）**

| 决策事项 | 市场PM | 研发PM | 上级/委员会 |
|---|---|---|---|
| 市场机会判断 | A/R | C | I |
| 产品定位与场景定义 | A/R | R | I |
| 技术路线选型 | C | A/R | I |
| 差异化创新方向 | R | A/R | I |
| 立项 Go/No-Go | A | A | I |
| 开发排期与里程碑 | C | A/R | I |
| 需求变更审批 | A | A | I |
| 上市节奏决策 | A/R | R | I |
| 上市后复盘 | A | A | I |

> 上级/委员会不介入双PM 决策，仅知情备案，保证双PM 决策权完整。

### 3.7 项目移交（BR-HAND）

**BR-HAND-01 移交范围**：支持单项目 / 批量一键移交，支持市场PM、研发PM 独立移交或同时移交。

**BR-HAND-02 数据跟随**：移交后全部历史审批记录、Gate 评审记录、决策日志、文档资料、奖金池台账完整跟随项目移交至新PM。新PM 继承全部权限，接续推进未完成流程。

**BR-HAND-03 津贴与奖金处理（V3.1 §4.2 / §5.4）**
- 月度津贴跟随新接手PM，**按接手时该PM 自身等级锁定额度**；已过去阶段不追溯重算
- 在研项目额度锁定不变，期间原PM 升级不上调
- 奖金池沿用项目立项既定规则，系统支持人工补充登记特殊分配备注，留痕归档

**BR-HAND-04 审计**：全程生成审计日志永久留存。

### 3.8 KPI 考核（BR-KPI）— 源文档遗漏，V3.1 要求，必须实现

> **为什么必须有这个模块**：源文档多处引用"当月综合考核分数 <60 分停发津贴""个人绩效系数"，但源文档只做了津贴与奖金台账，**没有打分体系**。V3.1 §3 定义了完整 KPI 结构，是这两个数值的唯一来源。

**BR-KPI-01 考核结构**：功能KPI **60%** + 共担市场结果 KPI **40%**。共担比例不可低于 30%。

**BR-KPI-02 市场PM 功能KPI（60%，四项各 15%）**

| 指标 | 操作化定义 | 达标线 |
|---|---|---|
| 需求准确率 | 上市后需求变更率 = 变更单数 ÷ 总需求数 | ≤ 15% |
| 市场窗口命中率 | 实际上市时间 vs 计划窗口偏差 | ≤ 30 天 |
| 场景方案竞争力 | 上市后客户验证 + 竞品对比打分 | 评分制 |
| 竞品情报质量 | 情报覆盖度与时效性 | 评分制 |

**BR-KPI-03 研发PM 功能KPI（60%，四项各 15%）**

| 指标 | 操作化定义 | 达标线 |
|---|---|---|
| 上市准时率 | 实际交付 vs 承诺时间偏差 | ≤ 15 天 |
| 质量缺陷率 | PPM | 达标制 |
| 技术创新度 | 差异化专利/方案/架构创新数量与质量 | 评分制 |
| 需求一次性实现率 | 开发过程需求返工率 | ≤ 20% |

**BR-KPI-04 共担市场结果 KPI（40%，双PM 同分同担）**

| 指标 | 权重 | 定义 | 数据来源 | 评分规则 |
|---|---|---|---|---|
| 销量/出货量达成率 | 15% | 上市后 6 个月实际销售额 ÷ 立项目标销售额 | 财务/ERP 出库数据（一期手动录入+凭证） | ≥100% 满分，每低 5 个百分点扣 1 分，<50% 计 0 分 |
| 渠道商覆盖达成率 | 10% | 实际签约渠道/集成商数 ÷ 立项目标渠道商数 | 渠道签约台账 / CRM（一期手动） | 达标满分，每低 5 个百分点扣 1 分 |
| 客户 NPS | 10% | 净推荐值 = 推荐者占比 − 贬损者占比（9-10 推荐者 / 7-8 中立 / 0-6 贬损） | 问卷调研，有效样本 ≥ 30 份 | 达标满分，每低 5 分扣 1 分 |
| 场景覆盖率 | 5% | 实际落地场景数 ÷ 立项规划场景数 | 销售报备 + 交付验收记录 | 按覆盖率比例计分 |

**BR-KPI-05 归集节奏**：四项共担指标由产品共享中心**按月归集、季度对账，上市后 6 个月终算**。系统提供 K01–K04 四个归集动作与月度归集台账。

**BR-KPI-06 综合得分计算**：`综合得分 = 功能KPI 得分 × 60% + 共担KPI 得分 × 40%`。得分用于绩效系数映射与 <60 分判定。

**BR-KPI-07 在研项目分段**：功能KPI 补入前不追溯、补入后全量考核；共担 KPI **不分段、不打折，全量共担**。

**BR-KPI-08 评级评审（V3.1 §5.2）**：季度或半年度评审一次（半年度常规、季度设破格升级通道）。多源评价权重：**自评 20% + 直接上级评 30% + 技术委员会评 50%**。系统提供评审流程与打分录入。

### 3.9 双轨激励（BR-INC）

**BR-INC-01 双轨独立**：月度津贴（评级固定制，保底线）+ 成功奖金（5% 奖金池，盯结果）。两轨独立运作，考核同一套体系。

**BR-INC-02 月度津贴标准与锁定**

| 级别 | 职级名称 | 月度津贴 |
|---|---|---|
| L5 | 首席产品经理 | ¥3,000 |
| L4 | 高级产品经理 | ¥2,500 |
| L3 | 产品经理 | ¥2,000 |
| L2 | 初级产品经理 | ¥1,500 |
| L1 | 助理产品经理 | ¥1,000 |

- **评级锁定**：额度随项目启动时评级锁定，期间升级不上调该项目额度；新项目按最新评级执行
- **不乘绩效系数**
- 当月综合考核 < 60 分 → 当月停发
- 准入：经评级委员会评定级别，从评定通过**次月**起享受津贴

**BR-INC-03 多项目叠加与封顶**：各项目津贴按各自评级额度**全额叠加**（不设边际折扣）；月津贴总额 ≤ 个人当前评级额度的 **2 倍**封顶，超限按 2 倍发放。

**BR-INC-04 奖金池计算（⚠️ 采用 V3.1 口径）**

```
奖金池 = 立项时录入的目标销售额 × 5% × 差异化系数
```

> **与源需求文档冲突**：源文档写"以实际回款金额为基数"。V3.1 **全文无"回款"概念**（检索 0 次），只用「销售额/出货量」。**以 V3.1 为准**，回款口径作废。
>
> **⚠️ V3.1 内部口径不一致（待 Gavin 拍板，见配套《冲突裁决与最终待确认清单》Q1）**：
> - §4.1 核心设计："前 6 个月**目标**销售额 × 5% × 差异化系数"
> - §4.3 表格算例："以**目标**销售 ¥500 万为例 → ¥500万 × 5% × 1.5~2.0 = ¥37.5万~¥50万" ← **唯一有算例**
> - §5.5 核心规则速查："前 6 个月销售额 × 5% × 差异化系数"（无"目标"二字）
>
> **当前按「目标销售额」实现**（依据：唯一给出算例的 §4.3 + §4.1 明确带"目标"）。
> **开发要求**：基数口径必须做成配置开关 `bonus.poolBase = TARGET_SALES | ACTUAL_SALES`，**禁止硬编码**。切换口径只改配置，不改代码。
>
> 按"目标销售额"的代价：超额完成不额外激励（阶梯最高 1.0 封顶，目标 500 万实卖 1500 万，奖金仍按 25 万池算）。按"实际销售额"则上限不封顶，但会诱导 PM 压低立项目标以抬高达成率。

**BR-INC-05 差异化系数（区间制，立项时录入具体值）**

| 项目等级 | 系数区间 | 适用范围 |
|---|---|---|
| S 级 | **1.5 – 2.0** | 新场景方案、新技术方向、沙特基地首发产品 |
| A 级 | **1.0**（固定） | 门禁/考勤/安检/智能锁/充电桩核心产品线新一代开发 |
| B 级 | **0.6 – 0.8** | 区域定制、功能升级、衍生型号 |

> S 级与 B 级是**区间**，立项时须在区间内录入具体系数值并说明理由，写审计。等级中期修改写审计。

**BR-INC-06 销售达成率阶梯**

| 达成率 | 阶梯系数 | 判定 | 发放 |
|---|---|---|---|
| ≥ 100% | 1.0 | 产品成功 | 奖金池 × 1.0 |
| 85% – 99% | 0.8 | 基本成功 | 奖金池 × 0.8 |
| 70% – 84% | 0.6 | 部分达成 | 奖金池 × 0.6 |
| 50% – 69% | 0.3 | 未达成 | 奖金池 × 0.3，触发复盘检讨 |
| < 50% | 0 | 产品失败 | 不发放；月度津贴已发不追回 |

**BR-INC-07 绩效系数映射（仅成功奖金适用，V3.1 §4.5）**

| 综合得分 | 绩效系数 | 含义 |
|---|---|---|
| ≥ 95 | 1.0 | 优秀 |
| 85 – 94 | 0.8 | 良好 |
| 70 – 84 | 0.6 | 合格 |
| 60 – 69 | 0.3 | 不合格，触发改进约谈 |
| < 60 | 0 | 严重不合格，取消奖金资格，启动角色调整 |

> **⚠️ V3.1 未定义取数时点（待 Gavin 拍板，见裁决清单 Q3）**：§4.5 只说"绩效系数按**季度**考核综合得分确定"，但 6 个月窗口跨 2–3 个季度，取哪一个未说明。
> **当前默认实现**：取 6 个月窗口内所覆盖各季度综合得分的**按月份加权平均**（不足整季按实际覆盖月份计权）。
> **开发要求**：取值策略做成配置项 `bonus.performanceScoreStrategy = WEIGHTED_AVG | LAST_QUARTER | REVIEW_QUARTER`，**禁止硬编码**。

**BR-INC-08 成功奖金公式**

```
每人成功奖金 = 奖金池 × 达成率阶梯系数 × 贡献度比例 × 绩效系数
```

**BR-INC-09 贡献度评定（五维度）**

| 维度 | 权重 | 偏市场PM 依据 | 偏研发PM 依据 |
|---|---|---|---|
| 立项主导贡献 | 25% | 市场洞察驱动立项、场景定义领先 | 技术前瞻驱动立项、创新方向引领 |
| 差异化创新贡献 | 25% | 提出差异化方向、竞品对标精准 | 技术突破实现差异化、专利产出 |
| 上市节奏把控 | 20% | 窗口判断准、GTM 推动有力 | 交付提速显著、质量稳定 |
| 市场结果贡献 | 20% | 渠道赋能、场景拓展贡献大 | 技术稳定性支撑客户口碑 |
| 协同领导力 | 10% | 主动拉通研发、推动决策 | 主动拉通市场、技术透明 |

- 市场PM 浮动区间 **40% – 65%**，研发PM **35% – 60%**，**两者之和恒为 100%**（前端联动校验）
- 由**双PM + 直接上级三方**在**上市后 90 天复盘**时联合评定
- 按贡献分，不按职位分

**BR-INC-10 负反馈机制（V3.1 §5.1）**

> 对月度津贴和成功奖金**同时适用**。津贴模式：主责方津贴**停发**、连带方津贴**减半**；奖金模式：贡献度系数降低或取消分配资格。

| 触发情形 | 主责方 | 连带方 |
|---|---|---|
| 错过市场窗口 | 双PM 共同 | — |
| 需求返工率超标 | 市场PM | 研发PM |
| 参数堆砌 / 对标抄袭 | 研发PM | 市场PM |
| 质量事故 | 研发PM | 市场PM |

**BR-INC-11 停发规则（⚠️ 采用 V3.1 口径）**：附加项目连续 **2 个月无实质产出** → **停发该项目津贴**。

> **与源需求文档冲突**：源文档写"仅提醒，不自动停发"，V3.1 §4.2 明确"停发该项目津贴"。**以 V3.1 为准**。
> **实现建议**：系统每月 1 日扫描 → 命中则生成「待确认停发单」→ 管理员确认后执行停发 → 全程审计。保留人工确认环节，不做全自动停发。
> **"实质产出"可执行判定**：连续 60 个自然日内，该项目无「动作状态变更 ∪ 交付物上传 ∪ 执行记录填写 ∪ Gate 评审提交」任一行为。

**BR-INC-12 退出机制**：调离双PM 项目 / 主动退出 / 连续两期考核 < 60 分 → 从**退出次月**停发津贴，**同时放弃成功奖金资格**（`bonusEligible = false`）。

**BR-INC-13 升降级**：升级后新项目按新级别、在研项目额度锁定不变；常规降级新项目按新级别、在研不变；**重大失误即时降级：次月起按新级别执行**。

**BR-INC-14 退款不回溯**：上市 6 个月结束后发生的退款，不做奖金回溯扣减（该场景不处理）。

**BR-INC-15 台账定位**：系统只输出津贴台账与奖金台账记录，**不生成财务正式结算单据**，不对接薪资系统。支持报表导出归档。

### 3.10 需求管理（BR-REQ）

**BR-REQ-01 免登录门户**：外部/内部人员无需登录即可提交需求。

**BR-REQ-02 提交字段**：选择**产品**（BR-PROD-01）、提交人、联系方式、需求描述、附件上传。
> **修正**：源文档的"负责人"字段由游客填写不合理，改为系统根据所选产品自动路由到负责双PM。

**BR-REQ-03 查询码**：提交成功生成 8 位查询码，游客凭码查询进度。游客无修改、撤回权限。

**BR-REQ-04 自动路由**：需求汇入需求池，按产品自动通知对应双PM（站内信 + 企微）。

**BR-REQ-05 生命周期**：SUBMITTED → ACCEPTED（收录/驳回）→ EVALUATING → SCHEDULED → PROCESSING → CLOSED → ARCHIVED。PM 可做评估、排期、处理、更新状态、关联项目 IPD 节点、完结归档。

**BR-REQ-06 删除**：需求池记录删除属重大数据，强制双层审核（BR-DEL-01）。

### 3.11 AI 文档模块（BR-AI）

**BR-AI-01 模型配置**：后台可配置大模型参数（provider / endpoint / apiKey / model / temperature / maxTokens）、开关、超时与重试策略、月度 token 预算与限流。

**BR-AI-02 生成流程**：PM 录入原始资料 → AI 润色/补齐/标准化生成 → **PM 人工审核确认后方可保存归档**。未审核的内容标记「待审核」，不得作为正式交付物。

**BR-AI-03 版本链**：保存完整版本链——AI 原始输出为 v1，后续每次人工修改为 v2/v3…，支持版本对比与回溯查看。

**BR-AI-04 不做敏感过滤**：系统不做内容过滤，直接透传模型返回结果，由 PM 人工把控内容风险。UI 上须有明确风险提示。

**BR-AI-05 调用权限**：普通PM 与产品组长权限对等，均可调用。调用记录（含 token 消耗）写审计。

**BR-AI-06 关联**：AI 生成内容可关联到具体项目 / 阶段 / 动作 / 交付物。

### 3.12 差异化删除审核（BR-DEL）

**BR-DEL-01 双层审核（重大数据）**：Gate 记录、立项关键信息、核心交付物、需求池需求记录 → 删除申请 → **产品组长初审** → **超级管理员终审**。两级全部通过方可删除。

**BR-DEL-02 一级审核（普通业务数据）**：归属市场PM 或研发PM 独立负责的普通业务信息 → 删除申请 → **对应产品组长初审**。

**BR-DEL-03 逻辑删除**：审核通过后执行**软删除 + 移入归档区**（`deletedAt` 置位），审计链完整保留。超管可在归档区做二次确认的彻底清除，**清除动作本身再写一条审计**。

**BR-DEL-04 时限与撤回**：组长初审 5 个工作日、超管终审 5 个工作日（后台可配）；逾期自动提醒并升级；申请提交后 **24 小时内申请人可撤回**，撤回写审计。

**BR-DEL-05 驳回**：驳回时系统通知申请人，完整保存驳回记录与理由。

**BR-DEL-06 无直接删除**：任何人无直接删除权限，全部走申请审核流程。

### 3.13 审计日志（BR-AUD）

**BR-AUD-01 覆盖范围**：招标修改/关闭、仲裁决议、项目等级与系数修改、删除申请审核、项目移交、超管移交、API 人员同步、密码修改、企微绑定/解绑、登录登出、参数修改、AI 调用、KPI 打分与修改、津贴/奖金核算。

**BR-AUD-02 只追加**：无 UPDATE/DELETE 权限，hash 链防篡改（TS-08），提供全链校验接口。

**BR-AUD-03 分层导出**：普通PM 仅本人相关 / 产品组长本组 / 超管全局。**游客无审计权限**。

**BR-AUD-04 留存**：默认永久保留，超管可配置归档策略（如 3 年后转冷存储）。

### 3.14 超级管理员移交（BR-ADM）

**BR-ADM-01 超管权限**：系统参数配置、AI 模型配置、组织架构管理、账号权限开通、L1–L5 等级与津贴配置、重大删除终审、全局数据管理。独立账号，不使用 PM 姓名作为用户名。

**BR-ADM-02 移交闭环**：内置「超管权限一键移交」，将全部最高权限、后台配置、AI 配置、审核权限、数据管理权限完整迁移至新超管账号。需二次确认，全程日志留痕。

**BR-ADM-03 移交后**：旧超管账号**禁止登录、作废不可使用**。系统保留完整移交记录，新超管可查看历史移交信息与原超管身份。

## 8. 分阶段构建指令

> **严格按顺序执行。每阶段结束后必须：启动服务 → 执行该阶段验证清单 → 全部通过后再进入下一阶段。禁止跳阶段、禁止一次性生成全部代码。**

### P0 底座

1. 初始化 monorepo（pnpm workspace）+ Docker Compose（postgres / redis / minio / api / web / nginx）
2. Prisma schema 全量表定义 + migration + seed（产品组、超管账号、系统参数表默认值、系统管理员角色）
3. 后端基础框架：统一响应、异常过滤、JWT 认证、RBAC 守卫、`@Audit()` 审计切面、参数校验管道、字典接口
4. 前端基础框架：布局（侧边导航 + 顶栏）、路由、权限路由守卫、请求封装、i18n 骨架、字典缓存
5. 认证：账号密码登录、首次登录强制改密、企微 Mock 登录、登出
6. **通用删除审核引擎**（BR-DEL，先做成可复用的通用组件，后续模块直接接入）
7. 审计日志查询页 + hash 链校验接口

**P0 验证**：能启动 → 超管登录 → 创建 PM 账号 → PM 登录被强制改密 → 发起一条删除申请走完两级审核 → 审计日志可查且 hash 链校验通过。

### P1 IPD 主干

1. 产品 CRUD（BR-PROD-01）
2. 项目 CRUD + 新建项目选模板（硬件/软件/解决方案）
3. **Seed 全部 64 个动作**（读配套动作清单 v2），自动生成 `stage_actions` 实例
4. 阶段/动作列表与详情接口，**深管与轻管的字段校验逻辑分离**（BR-IPD-03/04）
5. SOP 模板管理 + 深管动作 SOP 展示
6. 交付物上传（MinIO）+ 深管动作强制校验
7. **IPD 流程可视化页**（深管卡片 / 轻管行式，视觉可区分）
8. 阶段门禁校验（BR-IPD-06，含 S/A/B 分级）+ 阶段跳转
9. 存量项目导入（BR-PROD-03）

**P1 验证**：新建硬件项目 → 六阶段与 64 动作自动挂载 → 深管动作不传交付物无法完成 → 轻管动作只填三字段即可完成 → 阻断动作未完成时跳阶被拒 → 流程页视觉能区分深管/轻管。

### P2 双PM 机制

1. 组织架构：产品组、组长、代理组长
2. 人员管理：文件批量导入、Mock API 同步任务、离职处理闭环（BR-USER-06）
3. 招标组队全流程（BR-TEAM-01 ~ 10）：发起、邀标/公开、应标、拒绝不留痕、邀标转公开、遴选、未中标通知、到期挂起、超管指派
4. 双PM 绑定 + 评级快照 + ≥3 项目校验
5. 五大 Gate 与双签（BR-GATE）：并行签署、意见互不可见、7 天超时弃权、强制附件、否决重发、第 3 轮升级、仲裁→终裁
6. 需求变更单与双签（BR-GATE-07）
7. 项目移交（BR-HAND）：单项目/批量、角色独立移交、数据跟随、离职待移交任务
8. 超管权限移交（BR-ADM）

**P2 验证**：市场PM 发起招标 → 研发PM 应标 → 遴选后未中标者收到通知 → 组队成功 → G1 双签：一方否决即驳回 → 双方意见在都提交前互不可见 → 超期弃权按主导方执行 → 冲突升级仲裁 → 项目移交后历史数据完整。

### P3 绩效与激励

1. KPI 模块（BR-KPI）：功能KPI 打分（市场/研发各四项）、共担 KPI 四项归集（K01–K04）、综合得分计算、在研分段规则
2. 评级评审流程（BR-KPI-08）：自评 20% / 上级 30% / 委员会 50%
3. 月度津贴台账（BR-INC-02/03）：评级锁定、多项目叠加、2 倍封顶、<60 停发、无产出停发工单
4. 奖金池（BR-INC-04 ~ 09）：目标销售额 × 5% × 系数区间值 → 达成率阶梯 → 贡献度五维评定（双PM+上级三方）→ 绩效系数 → 个人奖金
5. 负反馈执行（BR-INC-10）：主责停发 / 连带减半
6. 退出与升降级（BR-INC-12/13）
7. 台账报表导出（Excel）

**P3 验证**：录入 KPI 打分 → 综合得分正确 → 津贴台账叠加与封顶正确 → 用 ¥500 万目标 / S 级 1.5 系数 / 达成率 90% / 市场贡献 55% / 绩效 0.8 算一遍，人工核对公式结果 → 负反馈主责停发连带减半 → 报表可导出。

### P4 外围闭环

1. 需求门户（BR-REQ）：免登录提交、产品选择、查询码、进度查询、需求池全流程、产品路由通知
2. AI 文档助手（BR-AI）：模型配置、生成、人工审核、版本链与对比、token 统计
3. 工作台：待办聚合、逾期预警、KPI 与激励概览卡片
4. 全局报表与导出
5. 权限矩阵全量回归测试
6. 审计日志全量覆盖检查（对照 BR-AUD-01 逐条确认）

**P4 验证**：游客免登录提交需求 → 按产品路由到双PM → 凭查询码查进度 → 需求转变更单走双签 → AI 生成文档 → 未审核不可归档 → 版本链可回溯 → 三类角色权限边界逐一验证无越权。
