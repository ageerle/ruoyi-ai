## 管理深度定义（开发必须实现）

### 深管动作 — 完整管理

| 能力 | 说明 |
|---|---|
| 状态流转 | 未开始 → 进行中 → 已完成 / 延期，每次变更写操作记录 |
| 执行记录 | 富文本，支持多次追加 |
| 交付物 | **强制上传**，至少 1 个附件方可标记"已完成" |
| SOP | 强制展示该动作绑定的 SOP 富文本说明 |
| 门禁 | 阻断性动作未完成时，禁止跳转到下一阶段 |
| 提醒 | 到期前 3 天 / 逾期每天提醒主责人 |

### 轻管动作 — 三要素登记

**界面只需三个字段，不要做过载设计（Gavin 已确认：合适，无附件上传）：**

| 字段 | 类型 | 必填 |
|---|---|---|
| 完成状态 | 枚举：未开始 / 进行中 / 已完成 / 不适用 | 是 |
| 实际完成日期 | 日期 | 状态为"已完成"时必填 |
| 备注 | 文本，≤200 字 | 否 |

**轻管动作明确不做的事：**

- ❌ 不强制上传交付物（可选上传，但不校验）
- ❌ 不强制展示 SOP
- ❌ 不阻断阶段流转（法规认证类除外）
- ❌ 不做执行记录富文本

**例外一（法规认证）**：涉及法规认证的轻管动作 **P10 认证与法规清单确认、V02 认证测试送检** 保留阻断性（Gavin 已确认：认可）——认证缺失导致产品无法上市销售。但同样**不强制上传证书扫描件**，只需登记"已通过 + 通过日期 + 证书编号（文本）"。

**例外二（BioCV 算法）**：**Z01 为轻管，但必须登记实测 FAR/FRR 指标**（数值字段，不走附件）。这是熵基技术底盘的最小可见性要求。

**例外三（条件深管）**：**Z04 平台兼容性验证**在「解决方案」模板下自动升级为深管（集成方案是交付主体），硬件/软件模板下维持轻管。

**深管集中在市场PM 主战场**：概念 11 + 计划 4 + 发布 7 + 生命周期 8 + KPI 4 = **34 个**，占深管总数 81%。
**研发PM 主战场（开发+验证）** 23 个动作中仅 8 个深管（双周评审、需求变更、量产准入、Beta试用、包装说明书、试点交付、跨人种适配、海外本地化），其余 15 个只需登记完成时间。

> 验证阶段新增的 V10/V12 虽属验证阶段，但主责是**市场PM**（目标市场人种构成、本地化差异都是市场输入），不违背"研发阶段轻管"原则。
>
> 三个"深管但不阻断"的动作（C10 知识产权预检、V11 平台兼容性验证在硬件/软件模板下、LC05 客户反馈处理）是刻意设计：重要但不该卡住流程，改为强制留痕 + 逾期提醒。
