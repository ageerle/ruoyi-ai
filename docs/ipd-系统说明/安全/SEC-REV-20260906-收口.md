## 6 项发现逐项审计

### SEC-REV-01: GateReviewService IDOR

- **目标文件**（已被并发会话 `rm untracked` 删除）：
  `ruoyi-modules/ruoyi-ipd/src/main/java/org/ruoyi/ipd/service/GateReviewService.java`
- **漏洞点（基于会话开始时的 WIP 版本）**：
  - `sign(gateId, decision, opinion, actor)` 仅 `requireInternal()` 后即 `requireGate(gateId)` +
    `requireAuthorized(gateCode, actor)` + `requireNotSigned(...)`，**未校验 actor.groupId 与
    gate.projectId 所属产品组 groupId 是否一致**。
  - `view(gateId, actor)` 同上，未做范围过滤。
- **真实可利用性**：P1
  - IPD 虽为单企业私有部署，但产品组（groupId）维度有隔离语义（SEC-02 `canReadProject` /
    `canAccessGroup` 已设计但**全代码库无任何调用点**）。
  - 跨组 PM 可读他人 Gate 评审结论/意见（盲签保持性失效），可签他人 Gate（虽角色门禁生效，
    但跨组属权被无视）。
- **修复方案**（曾写测试 + 改 service，因文件被删未能落库）：
  1. 注入 `ProjectMapper` + `ProductMapper` + `IpdPermission`
  2. `sign()` / `view()` 入口新增 `requireProjectAccess(gate, actor)`：
     - `projectMapper.selectById(gate.getProjectId())` →
     - `productMapper.selectById(project.getProductId())` → `product.getGroupId()` →
     - `permission.canReadProject(actor.role(), actor.groupId(), productGroupId)` 失败抛 403。
- **状态**：**未修复**——目标文件不存在。

### SEC-REV-03: ProjectMemberController 跨租户数据暴露

- **目标文件**（已被删除）：
  `ruoyi-modules/ruoyi-ipd/src/main/java/org/ruoyi/ipd/controller/ProjectMemberController.java`
- **漏洞点（基于 WIP 版本）**：
  - `GET /api/v1/projects/{projectId}/members`：`requireInternal()`——任意内部角色可列任意项目成员。

- **修复方案**：在 controller 加 `requireProjectGroupAccess(projectId, actor)` 或下沉到
  `ProjectMemberService.listActiveMembers` 与 `bindMember` 入口。
- **状态**：**未修复**——目标文件不存在。

### SEC-REV-04: AiModelConfigService SSRF

- **目标文件**（已被删除）：
  `ruoyi-modules/ruoyi-ipd/src/main/java/org/ruoyi/ipd/service/AiModelConfigService.java`
- **漏洞点（基于 WIP 版本）**：
  `probe(endpoint)` 仅做 `URL` 解析 + `HttpURLConnection.openConnection()` + `connect/read 5s`，
  **未对 host 做 IP 范围判定**——攻击向量：
  - `endpoint = "http://127.0.0.1:9999/admin"` → 内网端口扫描
  - `endpoint = "http://169.254.169.254/latest/meta-data/"` → AWS metadata
  - `endpoint = "http://10.x.x.x/internal"` → RFC1918 内网
  - `endpoint = "http://localhost/..."` → 域名解析到 127.0.0.1 同样越界
- **真实可利用性**：MEDIUM
  - 触发面仅 SUPER_ADMIN（`requireAdmin()` 守卫），但 admin 自身不构成威胁模型正确性，
    SSRF 仍会让 admin 误配端点后被攻击者探活，且云环境 metadata 直接透出 IAM 凭据。
- **修复方案**（已写、被删）：
  ```java
  // 新增 ssrfBlockReason(host)：
  // 1) InetAddress.getAllByName(host) 任一 IP 落入 isLoopbackAddress / isLinkLocalAddress
  //    / isAnyLocalAddress / isMulticastAddress / isSiteLocalAddress（RFC1918）→ 阻断
  // 2) IPv4 100.64.0.0/10（CGN）字面比对 → 阻断
  // 3) 解析失败 → 返回 null 让外层 catch 报"域名不可达"
  // probe() 内调用：blocked != null 即返回 "connect: fail(SSRF拦截:xxx)"
  ```
- **状态**：**未修复**——目标文件不存在；修复片段随文件被删。

### SEC-REV-05: PublicPortalController 限流旁路 / IP 伪造

- **目标文件**（已被删除）：
  `ruoyi-modules/ruoyi-ipd/src/main/java/org/ruoyi/ipd/controller/PublicPortalController.java`
- **漏洞点**：`clientIp(http)` 直接信任 `X-Forwarded-For` 首段作为真实 IP：
  ```java
  String fwd = http.getHeader("X-Forwarded-For");
  if (fwd != null && !fwd.isBlank()) return fwd.split(",")[0].trim();
  return http.getRemoteAddr();
  ```
- **真实可利用性**：P1
  - IPD 公开端点 `/api/v1/public/demands` 位于单企业私有部署，**前面没有反向代理**
    可信 XFF。任何客户端可伪造 `X-Forwarded-For: <new-ip>` 绕过 GuestDemandService 的
    "同 IP 1 小时 10 次"限流（`InMemoryHourRateLimiter` 按 `ipHash` 计数）。
  - 攻击者可无限提交需求/触发 honeypot 绕过审计（`audit` 落哈希后的伪 IP）。
- **修复方案**（已写、被删）：
  ```java
  // 单企业私有部署无反向代理 → 不信任 XFF，统一只取 servlet 远端地址。
  // 未来若挂网关白名单：应新增专用 token 头或 mTLS 标识，绝不直接信 XFF。
  private static String clientIp(HttpServletRequest http) {
      return http.getRemoteAddr();
  }
  ```
- **状态**：**未修复**——目标文件不存在；修复片段随文件被删。

### SEC-REV-06: GuestDemandService 访问码熵不足

- **目标文件**（已被删除）：
  `ruoyi-modules/ruoyi-ipd/src/main/java/org/ruoyi/ipd/service/GuestDemandService.java`
- **审查结论**：**假阳性（已防护）**
  - `randomCode()` 用 `SecureRandom.nextLong() % 36^8`，熵 = 41.4 bit（≥ 40 bit NIST 推荐）。
  - 同 IP 1 小时 10 次限流 + uk_req_query_code 唯一键兜底 + 返回仅 8 位查询码（无内部 ID），
    暴力穷举需 `36^8 / 10 / 365 / 24 ≈ 3.6×10^7` 年——不构成攻击面。
  - 审计 `ipAddress` 落 `sha256Short(clientIp)` 哈希而非原始 IP，进一步压缩定位能力。
- **状态**：**无需修复**——附 SEC-REV-04 限流旁路修复后此码更安全。
