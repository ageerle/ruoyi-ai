## 2. 根因详述

**直接引用勘察卡 §2 R1 原文（≤200 字）**：

> 业务规则参数（如奖金池基数 5%、KPI 阈值 60 分、删项冷静期 3 天、Gate 双签人数 ≥3）目前以**字面量 / 注释形式散落在 Service 层与 PRD 中**，无独立 Config 表或枚举固化。**跨漏洞**：同一参数在不同 Service 用不同字面量（奖金池 Q2 口径回款 vs 合同）；演示模式与生产模式无代码级隔离（demo.enabled=false 但语料含演示）；业务规则调整需改代码 + 重新部署，**无法热更新**。**根治**：1) 新增 `ipd_business_config` 表（key / value / scope / enabled / version），迁移 8 类参数；2) 新增 `BusinessConfigService`（带缓存，与 SystemConfig 解耦）；3) 字面量替换为 `BusinessConfigKeys` 常量类。

**典型现场**（勘察卡附证）：

- `BonusPoolService.java:210` 注释明写「硬编码默认 0.0500（SystemConfigService 接入由 P0-3.3 完成后接管）」→ 即 R1 根因的活样本
- `GateElementResultService.java:259` 引用 `GateReviewService.SIGN_DEADLINE_KEY = 3`（双签/否决项相关魔数）→ 同源
- `GateEngine / DeletionRequestService / ComplianceService / KpiSharedCollectionService / ProjectScoreArchiveService / GateElementResultService` 6 个 Service 均直接依赖 `SystemConfigService`，但「演示/生产隔离」「热更新」诉求 SystemConfig 不满足

## 4. 根治方案 4 步骤详述

### 步骤 1：DDL Schema（`ipd_business_config` 表）

```sql
-- 文件路径建议：
-- ruoyi-modules/ruoyi-ipd/src/main/resources/db/migration/V002__ipd_business_config.sql
-- （与 V001__project_product_unique.sql 同目录）

CREATE TABLE IF NOT EXISTS ipd_business_config (
    id              BIGINT          NOT NULL AUTO_INCREMENT COMMENT 'PK',
    config_key      VARCHAR(128)    NOT NULL                COMMENT '业务参数键，格式 namespace.action，例 bonus_pool.base_rate',
    config_value    JSON            NOT NULL                COMMENT '参数值（JSON，可存数字/字符串/数组/对象）',
    value_type      VARCHAR(16)     NOT NULL DEFAULT 'string'
                                                    COMMENT 'string | number | boolean | json | enum',
    scope           VARCHAR(32)     NOT NULL DEFAULT 'global'
                                                    COMMENT 'global | demo | prod | tenant:<id>',
    enabled         TINYINT(1)      NOT NULL DEFAULT 1     COMMENT '是否启用 0/1',
    version         INT             NOT NULL DEFAULT 1     COMMENT '乐观锁版本号，热更新必备',
    notes           VARCHAR(512)    DEFAULT NULL           COMMENT '备注，例：ZK-IPD 口径对齐说明',
    created_at      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_config_key_scope (config_key, scope),
    KEY idx_enabled (enabled)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='IPD 业务参数配置表（可热更新）';

-- 初始 seed 数据（迁移脚本同事务）
INSERT INTO ipd_business_config (config_key, config_value, value_type, scope, notes) VALUES
('bonus_pool.base_rate',           JSON_OBJECT('value', 0.0500),                    'json',    'global', 'ZK-IPD 口径=回款（commit 5fb4fd42 锁定）'),
('bonus_pool.tier_coefficients',   JSON_ARRAY(JSON_OBJECT('tier','S','c',1.5),
                                                JSON_OBJECT('tier','A','c',1.2),
                                                JSON_OBJECT('tier','B','c',1.0),
                                                JSON_OBJECT('tier','C','c',0.8),
                                                JSON_OBJECT('tier','D','c',0.6)),   'json',    'global', 'ZK-14 五档系数（与本仓库三档对齐中）'),
('kpi.payout_score_threshold',     JSON_OBJECT('value', 60),                       'number',  'global', '<60 分停发（勘察卡 §1 R1）'),
('kpi.idle_days_stop_payout',      JSON_OBJECT('value', 60),                       'number',  'global', '60 天无产出停发（ZK-03 双维度：月度/季度）'),
('deletion.cooling_days',          JSON_OBJECT('value', 3),                        'number',  'global', '删项冷静期 3 天（ZK-17 vs 7 天，待评审确认）'),
('gate.review_min_signers',        JSON_OBJECT('value', 3),                        'number',  'global', 'Gate 双签人数 ≥3（ZK-07 vs ≥5，待评审确认）'),

```

**schema 设计要点**：

1. `JSON` 列存值（MySQL 5.7+ / 8.0 原生支持；PG 用 `JSONB` 需方言分支）
2. `(config_key, scope)` 唯一键 → 同 key 不同 scope 可并存（demo/prod/tenant）
3. `version` 字段 + MyBatis-Plus `@Version` 注解 → 热更新乐观锁
4. `enabled` 字段 → 灰度开关（紧急止血用，绕开缓存）
5. `notes` 字段 → 业务口径说明（ZK-IPD 一致性红线卡 §3 要求「决策可追溯」）

### 步骤 2：Service 接口（`BusinessConfigService`）

```java
// 文件路径建议：ruoyi-modules/ruoyi-ipd/src/main/java/org/ruoyi/ipd/service/BusinessConfigService.java
// （与 SystemConfigService 同包，互不干扰）

public interface BusinessConfigService {
    /** 读 String，缺值回退默认值 */
    String getString(String key, String defaultValue);
    /** 读 String，scope=tenant:<id> 优先 */
    String getString(String key, String defaultValue, String scope);

    BigDecimal getNumber(String key, BigDecimal defaultValue);
    boolean    getBoolean(String key, boolean defaultValue);
    <T> T      getJson(String key, TypeReference<T> type, T defaultValue);

    /** 热更新入口（带乐观锁） */
    boolean update(String key, Object newValue, int expectedVersion);
    /** 灰度开关 */
    boolean setEnabled(String key, boolean enabled);

    /** 缓存失效（手动触发，运维用） */
    void evictCache(String key);
}
```

**实现要点**：

- **Redis 缓存键**：`ipd:business_config:<scope>:<key>`，TTL 30 分钟
- **读穿透**：先查 Redis → 未命中查 DB → 写回 Redis
- **写穿透**：`update()` 成功后 `evictCache(key)`，下次读穿透重建
- **降级策略**：Redis 不可用时直接走 DB（容灾优先，`ruoyi-common-redis` 已有的 `RedissonClient` 注入兜底）
- **演示/生产隔离**：`scope=demo` 仅当 `demo.enabled=true` 时参与读路径，否则强制走 `scope=global`

### 步骤 3：`BusinessConfigKeys` 常量类

```java
// 文件路径建议：ruoyi-modules/ruoyi-ipd/src/main/java/org/ruoyi/ipd/common/BusinessConfigKeys.java
// （与 IpdBusinessException 同包）

public final class BusinessConfigKeys {
    private BusinessConfigKeys() {}

    public static final String BONUS_POOL_BASE_RATE          = "bonus_pool.base_rate";
    public static final String BONUS_POOL_TIER_COEFFICIENTS  = "bonus_pool.tier_coefficients";
    public static final String KPI_PAYOUT_SCORE_THRESHOLD    = "kpi.payout_score_threshold";
    public static final String KPI_IDLE_DAYS_STOP_PAYOUT     = "kpi.idle_days_stop_payout";
    public static final String DELETION_COOLING_DAYS         = "deletion.cooling_days";
    public static final String GATE_REVIEW_MIN_SIGNERS       = "gate.review_min_signers";
    public static final String GATE_SCORE_METHOD             = "gate.score_method";
    public static final String DEMO_MODE_ISOLATION           = "demo.mode_isolation";
}
```

**字面量替换范围**（最小爆炸半径，3 个高 ROI 文件）：

| 文件 | 当前字面量 | 替换为 |
| --- | --- | --- |
| `BonusPoolService.java:210` | `0.0500` | `businessConfigService.getNumber(BONUS_POOL_BASE_RATE, new BigDecimal("0.0500"))` |
| `BonusPoolService.java:tierCoefficientOf` | 硬编码 S/A/B 三档 | 查 `BONUS_POOL_TIER_COEFFICIENTS` 五档配置 |
| `GateElementResultService.java:259` | `SIGN_DEADLINE_KEY = 3` 字面量 | `businessConfigService.getNumber(DELETION_COOLING_DAYS, 3)`（按语义复用） |

**不替换范围**（保持稳定，避免爆炸）：

- `@Value("${...}")` 配置项 → 走 application.yml，不归本卡
- 算法魔数（如 BigDecimal.ROUND_HALF_UP 的 scale=2）→ 与业务规则无关
- 测试 fixture 字面量（如 `@Tag("dev")` 测试断言里的固定值）→ 测试稳定优先

### 步骤 4：缓存策略（4 道防线）

1. **L1 进程内 Caffeine**（可选）：5 分钟 TTL，扛单实例高频读
2. **L2 Redis**（必须）：30 分钟 TTL，跨实例共享
3. **降级直读 DB**：Redis 故障时 `RedissonClient.isShutdown()` 检测后走 DB
4. **热更新通知**：写 `update()` 时 `RedisPubSub` 广播 `evict:<scope>:<key>`，所有实例失效本地缓存

**缓存击穿防御**：DB 加载用 `synchronized(key)` 双检锁，防止雪崩时同一 key 击穿 DB。

## 7. 风险与回退

### 7.1 与 SystemConfig 并存策略

- **不删 SystemConfig**（B-CONS-03 单独 P1-9 治理，本卡不动）
- **并存关系**：`SystemConfig` = 系统级配置（如加密密钥、外部端点）；`BusinessConfig` = 业务规则参数（如奖金系数、KPI 阈值）
- **互斥边界**：未来 `hardcoded-config-guard.cjs` 落地后，`SystemConfig` 改的字段不会被误报；`BusinessConfig` 接管后 `SystemConfig` 的相关 key 标注 `@Deprecated`

### 7.2 缓存击穿防御

- **风险**：Redis 启动失败时首次全量读穿透 DB，可能打挂 DB
- **缓解**：`BusinessConfigServiceImpl` 启动时 `warmUp()` 主动加载高频 key（BONUS_POOL_BASE_RATE / KPI_PAYOUT_SCORE_THRESHOLD 等 4 个）
- **降级**：Redis 不可用 → `RedissonClient.isShutdown() || !isConnected()` 检测 → 直读 DB + 本地 Caffeine L1（5 分钟 TTL）
- **熔断**：`@SentinelResource` 或 `ruoyi-common-ratelimiter` 限流（>100 QPS 触发熔断 10s）

### 7.3 字面量替换遗漏

- **风险**：P0-7 最小爆炸半径仅 3 个文件，其他 Service 可能仍残留字面量
- **兜底 1**：`hardcoded-config-guard.cjs` hook（详见 §7）启动后，遗留字面量会在提交时 stderr 警告
- **兜底 2**：周治理卡纳入「业务参数字面量覆盖率」指标，目标是 30 天内从当前 ≈40% 提升至 ≥90%
- **兜底 3**：`BonusPoolService.java:210` 的「0.0500」改为 `businessConfigService.getNumber(...)`，但保留本地 fallback 默认值，双保险

### 7.4 演示/生产隔离失效

- **风险**：`demo.enabled=false` 但 `scope=demo` 数据仍可能参与读路径
- **治理**：`BusinessConfigServiceImpl.getString(key, default, scope)` 入参 scope 默认 `global`；调用方按需显式传 `tenant:<id>` 或 `demo`
- **测试**：`BusinessConfigServiceTest#scopeIsolation` 断言 demo 行在 `demo.enabled=false` 时不返回
