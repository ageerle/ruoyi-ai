## 一、DoD 硬规则（PR 完成标准，2026-09-08 起）

### DoD-1 数据访问 / 契约 / 时间语义改造的测试同步义务

凡 PR 涉及以下三类改动之一，必须**同 PR** 跑受影响测试类并同步修改测试，缺任一不合 DoD：

1. **数据访问路径**：换 mapper 方法、改 SQL 形态（如 `selectById` → `selectChain`、单段 CTE → 两段 CTE）
2. **契约**：字段名 / 键名 / 枚举值 / 错误码 / 语言文案
3. **时间语义**：时钟注入改造、撤回窗口 / 逾期扫描的时间推演逻辑

判定标准：受影响测试类 = 直接 stub / 断言该 mapper 方法、字段、枚举或 Clock 的测试类。
证据要求：PR 描述列出「改动面 → 受影响测试类 → 全绿结果」三行。CI 能抓编译红；
本规则防的是「测试还在、但断言写的是旧契约」的静默漂移（本仓 671 处 selectById stub
是最大暴露面，任何实现侧访问形态改造都会成片引爆）。

## 三、断言写契约不写现状

确需固化「现状分歧」的断言（如旧 Qa04 的并发行为分歧），必须同注释登记三要素：
**分歧编号（DEF-xx）+ 收口条件 + 登记日期**。
先例：DEF-04 靠登记 3 分钟追到引入提交；未登记的现状断言 = 下一次假绿的种子。

## 四、红名单有价（软约束）

红名单基线已清零（2026-09-08，PR #15，1938 tests / 0 红）。此后任何新进红名单的条目，
