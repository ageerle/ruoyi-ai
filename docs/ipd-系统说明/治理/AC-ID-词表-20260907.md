# AC ID 词表与 lint 规则（OD-AM-01 决策落地）

> **决策日期**：2026-09-07
> **决策主题**：DisplayName 命名规范化
> **决策状态**：✅ 已决策（半自动——维护 AC ID 词表，grep 识别未注册 ID 并 WARN）

## 1. 背景

`acceptance-matrix.json` 当前 10/237 样板已落地。`@DisplayName` 注解散落在 `ruoyi-modules/ruoyi-ipd/src/test/java/` 各测试类中，部分含 `AC-INC-NN` 编号、部分不含。三种 owner 候选路径：

| 路径 | 优点 | 缺点 |
|---|---|---|
| ① 逆向扫描 DisplayName 文本回填 ac_id | 自动 | 命中模糊（DisplayName 可能用空格 / 中文连接 AC 编号），易误判 |
| ② 按测试类批量加 @DisplayName | 强制 | 改动面大（约 30+ 测试类），需逐条对齐 matrix 中的 unitTestClass |
| ③ 维持现状 + grep 反查 | 零侵入 | 全靠人工 |

## 2. 决策

**采纳方案 ③ + 配套 lint 规则**：

- 不批量加 `@DisplayName`，不主动改测试源代码
- 维护本词表作为「AC ID 单一真相源」（single source of truth）
- `.claude/helpers/acceptance-matrix-validate.cjs` 已经在 `checkReverse()` 中实现：
  - 扫描所有 `.java` 测试类的 `@DisplayName("…")`
  - 提取其中 `AC-(INC|EXT|MIN)-\d+[a-z]?` 模式
  - 若 matrix 未收录 → **WARN**（退出码 2，非阻断）
- 词表随 matrix 增量更新时自动扩大白名单

**owner 后续动作**：
- 每周日 CI (`docs-link-check.yml`) 触发后人工 review `WARN` 列表
- 若确认 `@DisplayName` 是真实 AC 引用 → 在 matrix 添加该条
- 若非（如引用旧 AC-XXX-NN 或注释）→ 在测试类改为 `// AC-XXX-NN 注释`

## 4. lint 规则（已存在，本决策正式采纳）

### 4.1 正向校验（matrix 内）

`.claude/helpers/acceptance-matrix-validate.cjs` 已实现的 7 条：

1. ac_id 唯一
2. ac_id 格式 `^AC-(INC|EXT|MIN|AUTH|AUD|ENV|GATE|GLB|CFG|PROD)-\d+[a-z]?$` ⚠️ **缺失 7 个前缀**（AI/DEL/HAND/HR/IPD/KPI/REQ/TEAM），待 OD-AM-02 批量导入时一并扩充
3. category 与 ac_id 前缀一致
4. unitTestClass 文件存在
5. docRef 文件存在（缺失 WARN）
6. status=covered 必须有 linkedCommits
7. linkedCommits 格式（7-40 位 hex）

### 4.2 反向校验（matrix 外）

- 软反向：扫描 `@DisplayName("...")` 中 `AC-(INC|EXT|MIN)-\d+[a-z]?` 模式
- 不在 matrix → **WARN**
- 退出码 0 / 1 / 2 已有（0=全绿，1=硬错，2=软警）
