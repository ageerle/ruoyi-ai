# IPD 测试编写三禁（2026-09-08 根除轮）

> 沉淀背景：基线红 20 条清零（PR #15，main=a219dde5）+ 蜂群扫描发现同残留机制后，根除建议文档 §四 层 1 提出三禁沉淀为 review checklist。本文独立成文供评审对照使用。
> 适用范围：`ruoyi-modules/ruoyi-ipd/src/test/java/**` 所有测试代码（包括将来 PR 新增与既有改造）。
> 强制级别：review checklist 软约束；新代码硬性，老代码按 PR 范围最小化逐步收口。

## 为什么需要三禁

20 条基线红无一是业务缺陷，全是「实现正确演进、测试无人跟随」的欠账。三类腐化模式反复出现：

1. **时钟债**：测试断言依赖真实时钟摇摆（`new Date()` / `System.currentTimeMillis()` / `Instant.now()`），运行结果随机器时间漂移导致假红。
2. **helper 陷阱**：测试 helper 用「缺省补 PASS」类语法（`getOrDefault(code,"PASS")`），看似宽容实则把「未断言」洗成「PASS」，缺判陷阱被掩盖（547ba9f3 同款历史已两次出现）。
3. **守卫腐化**：守卫测试对整文件裸 contains/doesNotContain 断言，注释里的形态相近字面量会触发误伤（本仓已三起：P343 注释、LaunchDate accessor、ActuatorNarrow 注释）。

三禁直接对应这三类腐化模式。

## 禁一：被测类业务时钟必须走注入 Clock

### 禁什么

被测类（含 service / guard / validator / util）若在业务方法体内使用 `new Date()` / `System.currentTimeMillis()` / `Instant.now()` / `LocalDateTime.now()` 等"裸时钟"调用构造业务时间值（如 deadline / expireAt / ttl / 窗口起点），**禁止**直接这么写。

### 必须怎么写

被测类必须提供 `java.time.Clock clock` 字段（仿 `DefaultStateMachineGuard` 模式）：

```java
/** 可注入时钟（仿 stateMachineGuard 模式；测试固定时刻消除真实时钟摇摆，生产零影响）。 */
private java.time.Clock clock = java.time.Clock.systemDefaultZone();
public void setClock(java.time.Clock clock) {
    this.clock = (clock == null) ? java.time.Clock.systemDefaultZone() : clock;
}
private Date now() { return Date.from(clock.instant()); }
```

业务方法体内一律用 `this.now()` / `Date.from(clock.instant())` 替代 `new Date()`。

测试代码用 `Clock.fixed(...)` 注入：

```java
svc.setClock(Clock.fixed(Instant.parse("2026-09-08T10:00:00Z"), ZoneOffset.UTC));
```

### 例外（白名单）

仅以下场景保留 `System.currentTimeMillis()`：

1. **静态方法**（`static` 关键字修饰）：不能调实例字段 `clock`，保留 `System.currentTimeMillis()`。
2. **静态嵌套类**（`static final class` 内部成员类）：不持有外层实例引用，clock 缝不可达。

注意：上述例外场景的"业务时钟"语义在 PR review 时应特别标注——若测试断言依赖该静态方法的返回值，仍属时钟债未还。

### 历史范本

- `DefaultStateMachineGuard`：最早范本，缝已带 setClock/now。
- `DeletionRequestService`（L77-84）：本轮 11 类 Clock 缝模板（其他 10 类复制此模式）。
- 本轮改造清单：HandoverService / BidInvitationService / GateReviewService / GateElementResultService / BidScanService / GuestDemandService / ProjectService / GateCreationService / BidP231Validator / KpiSharedCollectionService。

## 禁二：测试 helper 禁用「缺省伪造」

### 禁什么

测试 helper（含 `@BeforeEach` / 私有 builder / 共享 util）禁止用「缺省补 PASS / 缺省补 false / 缺省补空集合」类宽容写法。例如：

```java
// 反例：缺省伪造
String withJudgedForGate(Gate gate, Map<String, String> codeToResult) {
    for (String code : gate.getCodes()) {
        resultMap.putIfAbsent(code, "PASS");  // 缺省补 PASS——掩盖缺判
    }
    return resultMap.get(code);
}
```

这种写法的危险在于：测试用例忘标某 gate code 的判定结果时，自动用 PASS 兜底，使"未断言"被洗成"PASS"，缺判陷阱永远抓不出来（547ba9f3 同款历史已两次出现）。

### 必须怎么写

需要"两种语义"就写两个**显式命名**的 helper，让语义自暴露：

```java
// 正例 A：全部缺省补 PASS（语义自暴露）
Map<String, String> withAllJudgedDefaultPass(Gate gate, Map<String, String> codeToResult) {
    Map<String, String> result = new EnumMap<>(String.class);
    for (String code : gate.getCodes()) {
        result.put(code, codeToResult.getOrDefault(code, "PASS"));
    }
    return result;
}

// 正例 B：只填显式标过的（其他留空，由被判定逻辑走缺判拒绝路径）
Map<String, String> withOnlyJudged(Gate gate, Map<String, String> codeToResult) {
    return new EnumMap<>(codeToResult);  // 不补缺省
}
```

调用点必须挑一个显式命名的 helper，IDE 自带提示会强迫测试作者想清楚语义。

### 历史范本

- `P162AcceptanceTest#withJudgedForGate`（旧名）→ 本轮改名 `withAllJudgedDefaultPass`（2026-09-08 AM-HELPER 收口）：11 处出现（1 定义 + 1 javadoc + 9 调用点）机械替换为 `withAllJudgedDefaultPass`，让"缺省补 PASS"语义在名字里自暴露。
- 同款历史 `547ba9f3`：见 `docs/ipd-系统说明/治理/测试债务根除与守卫加固建议-20260908.md` §二 同残留描述。

## 禁三：守卫测试禁止对整文件裸文本扫描

### 禁什么

守卫测试（含「禁止某 API 调用」/「禁止某字段写入」/「禁止某 key 出现」类断言）禁止对整文件裸 contains / doesNotContain 断言。例如：

```java
// 反例：注释里的 ".launchDate(" 也会触发
String src = Files.readString(Path.of("src/main/java/.../ProjectService.java"));
assertThat(src).doesNotContain(".launchDate(");  // 注释里出现该字面量即假红
```

本仓已三起误伤：P343 注释、LaunchDate accessor、ActuatorNarrow 注释——守卫自身的腐化就是下一个误伤候选。

### 必须怎么写

守卫断言前**必须先剔除注释**，必要时再区分"读 vs 写"形态：

```java
import org.ruoyi.ipd.qa.GuardSourceUtils;

String src = Files.readString(path);
String codeOnly = GuardSourceUtils.stripComments(src);  // 块/行注释一律剥掉
assertThat(codeOnly).doesNotContain(".launchDate(");   // 仅代码文本断言
```

读 / 写语义模糊时（如 record accessor vs builder），用带参正则区分：

```java
// 区分"带参调用=写"与"空参 accessor=读"
assertThat(codeOnly).doesNotMatch(".*\\.launchDate\\([^)]");  // 禁止带参
```

yml 守卫优先用 snakeyaml 真解析（对齐 `ProdHikariConfigTest`），否则用 `GuardSourceUtils.stripYamlComments` 过滤 `#` 注释行后再断言。

### 历史范本

- 金标准 `PermissionAdviceCoverageTest`（L71 findGitRoot + L92 stripComments）：块注释 `(?s)/\\*.*?\\*/` 先剥，再 `//[^\n]*` 行注释。本轮抽出公共工具 `org.ruoyi.ipd.qa.GuardSourceUtils`（`ruoyi-modules/ruoyi-ipd/src/test/java/org/ruoyi/ipd/qa/GuardSourceUtils.java`），含 4 个静态方法（findGitRoot / stripComments / stripYamlComments / findGitRootFromCwd）。
- 同款历史 `P063Acceptance#mockKeyNamesMatchProductionSource` / `ActuatorNarrowTest#1` / `ProdConfigDeltaGuard#2`：见根除建议文档 §3.2 A 类裸文本守卫清单。本轮仅完成工具抽取（AM-GUARD 第一阶段），6 处 A 类守卫改造延后。

## 三禁速查（review checklist 摘录）

| # | 禁 | 必 | 例外 |
|---|---|---|---|
| 1 | 业务方法体内裸 `new Date()` / `System.currentTimeMillis()` / `Instant.now()` | 走 `clock` 字段 + `setClock()` 注入 + 测试用 `Clock.fixed()` 固定 | static 方法 / static nested class（保留 `System.currentTimeMillis()` + PR 标注） |
