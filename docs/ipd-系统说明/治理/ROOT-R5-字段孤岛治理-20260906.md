## 2. 根因详述

DDL 已加字段（如 `audit_chain_hash`、`project_member.role_ext`、`bonus_pool.frozen_at`），但消费链路 4 层未同时就位：① Entity 加字段 ✓ ② Mapper XML 未引用（索引浪费）③ DTO 未透出（前端拿不到）④ Controller 仍收 Entity 而非 DTO（B-CONS-04 同源）。跨 18 commit 反复发生「建而不接」事故，跨漏洞叠加：性能浪费（索引空挂）/ 前端体验空缺（看不到字段）/ 命名风格混用（snake vs camel）。3 Agent 同源检出：B-CROSS-02（业务维度）/ V3（前端维度）/ ZK-09（ZK-IPD 一致性维度）。

## 4. 根治方案（3 步骤）

### 步骤 1：新增 lint hook（DDL 新增字段 7 天内必须 ≥3 处 Java 引用）

- 落点：`.claude/helpers/ddl-field-usage-lint.cjs`（草案见交付 2）
- 触发：PostToolUse 命中 `**/sql/**/*.sql` 或 `**/migration/**/*.sql`（CREATE TABLE / ALTER TABLE 新增字段）
- 逻辑：解析 DDL 增量字段名 → 跑 `git grep -c "<field_name>" -- '*.java'` 计数 → 7 天内 < 3 处引用则 stderr 警告「字段 X 在 DDL 中已加但 Java 引用 < 3，建议检查 Entity / Mapper / DTO / Controller 4 层消费链路」
- 模式：**WARN 级**（exit 0，不阻断；与 sensitive-field-guard 的 ERROR 阻断区分；与 pom-edit-hint 的 WARN 同档位）
- 注册：owner 决定；本会话**不修改** `.claude/settings.json`

### 步骤 2：DTO 字段命名统一 camelCase + DB 列名 snake_case（MyBatis-Plus `@TableField` 映射）

- 约定入口：`docs/ipd-系统说明/naming-convention.md`（已存在，本卡引用而非新增）
- 执行入口：所有新加 DTO 字段一律 camelCase；对应 DB 列 snake_case 必须显式 `@TableField("snake_name")` 标注
- 校验：CI 阶段用 `entity-field-usage-lint.cjs` 钩出的「Entity 字段无 @TableField」情况作为 lint 二次触发

### 步骤 3：字段孤岛报告纳入周治理卡

- 触发：每周一次（建议与周一对齐），跑 `node .claude/helpers/ddl-field-usage-lint.cjs --report=weekly`（待 owner 扩展）
- 输出：JSON 报告 + stderr 人读摘要
- 归档：`docs/ipd-系统说明/治理/周报/`（待 owner 决定目录）
