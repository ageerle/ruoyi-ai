# ZK-IPD 一致性红线与前端差距根因（2026-09-06）

> **红线声明**：用户指令（2026-09-06 原话）——「**严格禁止和ZK-IPD不一致**」。
> 自本时刻起，任何页面、接口、规格、数据与 ZK-IPD 原始内容的偏离，未经用户明确裁决一律视为缺陷，不得当作「工程自由度」处理。本文档是该红线的执行细则与差距底账。

---

## 1. ZK-IPD 资产全景：三层结构

用户所说「ZK-IPD」（`/Users/mac/Documents/ZK-IPD/`）不是一份文档，是**三层互相有出入的资产**：

| 层 | 资产 | 内容 | fork 进本仓的情况 |
|---|---|---|---|
| ① 制度层 | `产品流程细化管理工具 2/双PM绩效考核制度.pdf`（311 行提取文本） | 五阶段并行双轨、**五个联合决策 Gate**、双PM 责任链、KPI/奖金/评级制度 | **从未纳入对照体系** |
| ② 文档层 | `开发说明/spec/`（49 页规格）+ `产品流程细化管理工具/` 下 7 件核心文档（主Prompt v3、动作清单 v3、五大Gate v1 等） | 49 页、69 动作、五节点角色、11 个一级导航入口 | 已忠实复制：7 件外部资源正文逐字一致、spec 正文一致（本日机械 diff 复核），是仓内「圣经」 |
| ③ 原型层 | `产品流程细化管理工具 2/`（React 19 壳 + Fastify server 5422 行 + SQLite + 场景数据 + `design-reference.png` 视觉真值 + `design-qa.md` 像素级验收记录） | **能跑的完整系统**：15 个导航项、Cookie 会话、13 个姓名账号、3 个完整演示项目、全功能 | **从未纳入对照体系**，且被 ruoyi-ipd-web AGENTS.md 判为「不得用旧React原型」 |

**结论：本仓从 fork 第一天起就只对齐了三层中的一层（文档层），制度层与原型层从未参与任何对照。前端差距大的根源在此，不在某个具体页面写得不好。**

## 2. 事实源裁决序（红线怎么执行）

ZK-IPD 内部三层彼此冲突时，按以下顺序裁决；**每发现一处冲突必须登记到本文档 §7，禁止私自选边**：

1. **制度层（PDF）** —— 业务数值与规则的终审基准（Gate 数量、KPI 权重、评级机制）。
2. **文档层（spec + 外部资源 7 件）** —— 页面清单、流程、术语、动作清单的基准（即仓内 G-04 圣经，内容与 ZK-IPD 文档层逐字一致）。
3. **原型层（代码）** —— **交互行为、UI 结构、信息架构细节、演示数据**的对照基准。不能拿来当代码库用（AGENTS.md「不得代替 IPD 实现」仍然有效），但**必须拿来当对照物**：每一页开发前对照它的路由与组件，验收时对照它的运行状态。

已完成的裁决（无需再议）：
- **五个联合 Gate**：制度 PDF（「Go/No-Go、差异化确认、双周评审、GTM就绪、90天复盘」）、文档层（五大Gate评审要素 v1）、原型 final-rules.mjs（key_gates 表、market_lead/rd_lead 双组长签署）三方一致。原型 `db.mjs` STAGES 里 6 个「阶段尾 gate」字符串是**旧层残留**，不算数。
- **五节点角色**（市场PM/研发PM/双组长/超管）：制度层与文档层一致；原型 final-rules.mjs 已按 market_lead/rd_lead/super_admin 演化到同构。原型 `App.jsx` 壳层 `roleNames` 只剩 3 角色是原型自己的旧壳，不算数。

## 3. 差距矩阵（全部有实证）

### A. 覆盖度：成品 vs 工地
- ZK-IPD 原型：全功能可运行（README「当前能力」清单 15 大项：六阶段动作、密封应标、协作圈、绩效 V3.1 回款台账、批量移交、超管交接、退市归档、企微 OAuth、第三方人员同步…）。
- 本项目：49 页中已实现约 26 页；`apps/web-antd/src/router/routes/modules/ipd.ts` 中 `pending()` 挂 `backend-pending.vue` 的还有 12+ 页（项目移交、KPI×4、激励×4、人员管理、超管移交等，对应 P2-7/P3 后端未开工）。
- 定性：**计划内未完成**，不是漂移——但从未向用户交付过「完工度坐标」，导致拿成品比工地。

### B. 信息架构：11 入口 vs 15 导航项
- 文档层（导航地图）：11 个一级入口（工作台/我的项目/产品管理/需求池/招标组队/项目移交/KPI考核/激励管理/AI文档助手/删除审核/系统管理）。
- 原型层（App.jsx navItems）：15 项 = 12 全员项（我的工作台/项目空间/需求管理/产品空间/研发招募/变更管理/资料库/阶段确认/协同绩效/全流程轨迹/报表分析/项目移交）+ 3 超管项（产品目录/人员同步/超级管理）。
- 具体出入：原型把「产品空间与项目空间分离」作为一级概念（README 明言核心设计），导航地图没有独立「产品空间」；原型有「全流程轨迹」「报表分析」「资料库」「变更管理」一级入口，导航地图分别并入项目详情页签或缺失；导航地图的「删除审核」「AI 文档助手」一级入口在原型中不是独立路由。
- 定性：**文档层与原型层的结构性分歧**，待裁决（§7-D2）。

### C. 品牌与视觉：完全两套语言
- 原型：品牌「IPD 工作台 / 澄明产品创新中心 / 全球市场及产品共享中心」，专属 logo（public/assets/ipd-logo.png），288 行定制 styles.css，登录页双栏品牌叙事（「让每一个产品决策都有方法、有证据、有沉淀」）+ 六阶段圆点 + 演示账号快捷选择；**有 design-reference.png 视觉真值，design-qa.md 记录了多轮像素级对照直到 P0/P1/P2 全无差异**。
- 本项目：标题「IPD 管理后台」（.env.local VITE_APP_TITLE），登录页一行标题「登录 IPD 管理系统」，AntD 管理后台皮肤，无视觉真值、无品牌资产。
- 定性：**漂移**。原型的视觉验收标准（source visual truth + 逐轮对照）本项目一次都没执行过。

### D. 机制契约：同一件事三层三个样（已发生一次事故）
- 原型：Cookie 会话（httpOnly / sameSite=strict / 8 小时 / 服务端 sessions 表存 sha256）。
- 本项目后端：Sa-Token JWT Bearer，900 秒超时 + `/auth/refresh` 单 token 轮换。
- 本项目 Wave2 规格包：自创 `refreshToken/refreshExpiresIn` 双 token——原型没有、49 页 spec 没规定，纯转述自创；前端照规格实现后**登录页直接崩**（「登录响应格式异常」，2026-09-06 已修，改回对齐后端）。
- 定性：**二次转述自创字段是已验证的事故模式**，红线 G2 门禁（§5）由此而来。

### E. 演示数据语境
- 原型：13 个中文姓名账号（傅志谦=超管，杨波/文元彪/陈泽鹏=市场组长，肖敬龙/杨志君/上官志昌=研发组长，段进科/胡蛟露/陈必勤=市场PM，程龙/林立杰/方武略=研发PM），统一初始密码，3 个六阶段全链路完整项目（ENT-AC-100 门禁 / ZK-IAT-ATT 熵基考勤 / VIS-RD-100 访客机），scenario.mjs 可重置。
- 本项目：ipd-admin + 900101-900104 QA 账号 + 少量中文种子账号，无完整链路演示项目。
- 定性：**数据层漂移**，用户体验差距的直接放大器（功能一样，原型有血有肉，新系统空壳）。

### F. 动作模型：37 vs 69（最重要的待裁决项）
- 原型 db.mjs STAGES 实测 **37** 个动作条目（README 也自称「固定 37 个动作及版本化 SOP V2」）。
- 文档层动作清单 v3：**69** 个（深管 42 / 轻管 27，阻断 38 / 非阻断 31）+ 5 联合 Gate，且注明「64 → 69」的演化。
- 制度层对动作总数沉默（只定五 Gate 与双PM 责任）。
- 本项目后端按 69 落地。
- 定性：**ZK-IPD 内部两代口径**（原型代码停在旧代，文档层演化到新代）。按裁决序默认取文档层 69，但必须用户确认（§7-D1）。

## 4. 根因反思：差距为什么会累积到今天

1. **R1 事实源断层**：fork 时只复制了文档层；「旧React原型不得用」的本意是「不得拿它当正式实现」，实际效果却是把原型整个逐出对照体系——UI、交互、数据、品牌从此**没有任何基准**，漂移合法化。
2. **R2 二次转述自创**：工程规格包（Wave2 等 8Agent 并行包）在无原型、无制度 PDF 对照的情况下编写，自创字段与机制（refreshToken 是实锤事故，登录页崩过一次才暴露）。
3. **R3 验收标准错位**：卡片验收 = HTTP 探针 + 真库 + 单测，全部在接口层以下；原型自己的交付标准却是 design-qa.md 那种**像素级视觉真值对照 + 交互闭环验证**。本项目从未给任何一页做过视觉对照。
4. **R4 进度断层无坐标**：P2/P3 后端未开工，前端只能挂占位页——这是计划内状态，但从没有人把「49 页完成度地图」摆到用户面前，用户拿原型成品一比，自然得出「做的是什么东西」的结论。
5. **R5 ZK-IPD 自身多层漂移未识别**：fork 时没人发现 ZK-IPD 是三层资产且互相冲突（37/69、6 阶段尾 Gate/5 联合 Gate、3 角色壳/五节点），也就谈不上裁决序——错误从第一份对照文档就埋下。
