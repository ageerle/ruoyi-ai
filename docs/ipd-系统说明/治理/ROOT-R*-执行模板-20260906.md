## 2. 8 步标准流程（DDL→Entity→Mapper→Service→单测→Mockito 适配→GUARD-1 复检→commit）

ROOT-R1 真实实现验证有效的 8 步执行序列：

```
[Step 1]         [Step 2]         [Step 3]       [Step 4]
 DDL            Entity           Mapper          Service
 12 seed        2 文件            2 文件          1 文件
                      ↓              ↓              ↓
[Step 5]   [Step 6]        [Step 7]               [Step 8]
 单测        Mockito 适配    GUARD-1 复检         commit
 10 测       typed any       @TableLogic           log + 治理卡
```

**总耗时**（ROOT-R1 实测）：**约 1.5 小时**（含 DDL 13 分钟 + Entity 8 分钟 + Mapper 5 分钟 + Service 22 分钟 + 单测 28 分钟 + Mockito 适配 7 分钟 + GUARD-1 复检 5 分钟 + commit 3 分钟 = 91 分钟 ≈ 1.5h）。

**单卡工期占比**：本会话 ROOT-R1 子卡平均 ≈ **1-1.5 小时**（DDL 表 + Service + 单测全套）；不涉及历史版本 / 缓存降级 / 热更新乐观锁时约 1.0h；涉及完整业务参数迁移（如 ROOT-R1-CONFIG-CACHE / P1-9 缓存化）约 1.5h。

### 2.1 Step 1：DDL（含初始 seed）

**目标**：建表 + 初始化业务数据，与现有表并存不互斥。

**落点**：`ruoyi-modules/ruoyi-ipd/src/main/resources/db/migration/V00X__<table>.sql`（与 V001__project_product_unique.sql 同目录）

**关键模板代码**（≈700 字符）：

```sql
-- 模板：业务参数配置表（ROOT-R1 实样，含 12 项 seed）

    id              BIGINT          NOT NULL AUTO_INCREMENT COMMENT 'PK',
    config_key      VARCHAR(128)    NOT NULL                COMMENT '业务参数键，格式 namespace.action',
    config_value    JSON            NOT NULL                COMMENT '参数值（JSON，可存数字/字符串/数组/对象）',
    value_type      VARCHAR(16)     NOT NULL DEFAULT 'string'

    scope           VARCHAR(32)     NOT NULL DEFAULT 'global'
                                                    COMMENT 'global | demo | prod | tenant:<id>',
    enabled         TINYINT(1)      NOT NULL DEFAULT 1     COMMENT '是否启用 0/1',
    version         INT             NOT NULL DEFAULT 1     COMMENT '乐观锁版本号，热更新必备',
    notes           VARCHAR(512)    DEFAULT NULL           COMMENT '备注，例：ZK-IPD 口径对齐说明',
    created_at      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_config_key_scope (config_key, scope),
    KEY idx_enabled (enabled)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='IPD <业务描述>';

-- 初始 seed 数据（同事务 INSERT，12 项覆盖业务规则参数全谱）

('<namespace>.<param1>', JSON_OBJECT('value', <default1>), '<type1>', 'global', '<备注1>'),
('<namespace>.<param2>', JSON_OBJECT('value', <default2>), '<type2>', 'global', '<备注2>'),
... -- 共 12 项
```

**常见坑 + 规避**：

| 坑 | 影响 | 规避 |
|---|---|---|
| **多租户过滤误伤**：`tenant.enable=true` 默认开，新表被自动加 `tenant_id` 条件 | 新表查询返回空 | ① 在 Mapper 加 `@InterceptorIgnore(tenantLine = "true")` ② 或登记 `tenant.excludes`（`application.yml`）③ 或表必须有 `tenant_id` 列 |
| **JSON 列方言分支**：PG 用 `JSONB` / MySQL 用 `JSON` | DDL 在 PG 失败 | 单一方言分支（项目用 MySQL 5.7+ / 8.0）；或抽离 `db/migration/dialect/` |
| **乐观锁版本号无 `@Version` 注解配合**：version 字段必须配合 MyBatis-Plus `@Version` | 热更新写冲突无法拦截 | Entity 必须 `@Version` 注解 + 引入 `OptimisticLockerInnerInterceptor` |
| **唯一键漏 scope**：`UNIQUE (config_key)` 而非 `(config_key, scope)` | 同 key 不同 scope 写入失败 | 必须双字段唯一键 |
| **seed 数据缺备注**：ZK-IPD 口径对齐无痕迹 | 未来审计追溯失据 | 每条 seed 必须 `notes` 字段写明口径来源 commit 哈希 |

**常见坑 + 规避**：

| 坑 | 影响 | 规避 |
|---|---|---|
| **Lombok `@Builder` 与 `BaseEntity` 冲突**：BaseEntity 含 `Boolean` 包装类 + `@Data` 生成的 builder 调用父类构造器 | 编译失败（父类字段未被 builder 接受） | ① 不在 BaseEntity 子类加 `@Builder`（手动 `@Data` + `@NoArgsConstructor` + `@AllArgsConstructor` 即可）② 或 BaseEntity 改为 `@Getter` + 子类 `@Setter` + 业务字段手动 builder |
| **`@TableLogic` 漏标**：GUARD-1 钩子（`ddl-entity-lint.cjs`）检测 DDL 含 `deleted` / `del_flag` 列但 Entity 无 `@TableLogic` | 钩子 stderr 警告（不阻断）→ GUARD-1 复检失败 | DDL 加 `deleted` / `del_flag` 列 → Entity 必须 `@TableLogic` 标注（**GUARD-1 触补典型场景**） |
| **JSON 字段映射漏 `@TableField(typeHandler = JacksonTypeHandler.class)`** | MyBatis-Plus 把 JSON 列映射成字符串，需手动 JSON.parse | 加 `typeHandler` 或 `String configValue` 手动解析（推荐后者，灵活） |
| **`fill = FieldFill.INSERT_UPDATE` 与 `@Version` 共用冲突** | updated_at 不自动更新 | 启用 `OptimisticLockerInnerInterceptor` + `MetaObjectHandler` 自动填充 |
| **Entity 字段命名未对齐 DDL**：`configKey` vs `config_key` 不一致 | MyBatis-Plus 默认驼峰转下划线，**但 `@TableField` 必须显式标注避免歧义** | 加 `@TableField("config_key")` 显式映射（与 naming-convention.md 对齐） |
| **BaseEntity 引入的 `createBy` / `updateBy` 字段缺失** | 部分历史字段 NULL | 显式声明（即使是 null）保持 DDL 对齐 |

**常见坑 + 规避**：

| 坑 | 影响 | 规避 |
|---|---|---|
| **`@InterceptorIgnore(tenantLine = "true")` 漏加** | 多租户过滤自动加 `tenant_id = ?` 条件，查询返回空 | 必须显式标注（业务参数与租户无关） |
| **`BaseMapper<T>` 泛型类型错误** | 编译失败（getById / list 返回类型错） | 检查 `<EntityName>` 必须完整类名 |
| **`updateByKeyAndVersion` SQL 拼接风险**：动态 SQL 拼接 + `@Param` 缺 `@Param` 注解 | MyBatis 报 `Parameter not found` | 所有 `@Param` 必须显式标注 |
| **`IPage<T>` 导入错误**：`com.baomidou.mybatisplus.core.metadata.IPage` vs `com.baomidou.mybatisplus.extension.plugins.pagination.Page` | Page 对象转换失败 | 用 `IPage` 接收（与 Service 接口对齐） |

| **`@Param` 注解参数命名与 XML `#{}` 不一致** | 启动失败 | 严格按 `@Param("name")` 与 `#{}` 一致 |

```java
package org.ruoyi.ipd.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.baomidou.mybatisplus.core.conditions.update.LambdaUpdateWrapper;
import com.fasterxml.jackson.core.type.TypeReference;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.redisson.api.RedissonClient;
import org.ruoyi.common.redis.utils.RedisUtils;
import org.ruoyi.ipd.domain.<EntityName>;
import org.ruoyi.ipd.mapper.<EntityName>Mapper;
import org.ruoyi.ipd.service.<EntityName>Service;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.math.BigDecimal;
import java.time.Duration;

/**
 * <EntityName> Service 实现（4 道缓存防线 + 热更新 + 乐观锁）
 *
 * @author root-94ae
 * @date 2026-09-06
 */
@Slf4j
@Service
@RequiredArgsConstructor
public class <EntityName>ServiceImpl implements <EntityName>Service {

    private final <EntityName>Mapper mapper;
    private final RedissonClient redissonClient;  // 降级兜底

    private static final String CACHE_KEY_PREFIX = "ipd:<entity>:<scope>:<key>";
    private static final Duration CACHE_TTL = Duration.ofMinutes(30);

    @Override
    public String getString(String key, String defaultValue) {
        return getString(key, defaultValue, "global");
    }

    @Override
    public String getString(String key, String defaultValue, String scope) {
        // 1. L2 Redis 读
        String cacheKey = CACHE_KEY_PREFIX.formatted(scope, key);
        String cached = safeRedisGet(cacheKey);
        if (cached != null) return cached;

        // 2. L3 DB 读（双检锁防击穿）
        synchronized (cacheKey.intern()) {
            cached = safeRedisGet(cacheKey);  // 二检
            if (cached != null) return cached;

            <EntityName> entity = mapper.selectByKeyAndScope(key, scope);
            String value = entity != null ? entity.getConfigValue() : defaultValue;

            // 3. 写回缓存
            safeRedisSet(cacheKey, value, CACHE_TTL);
            return value;
        }
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public boolean update(String key, Object newValue, int expectedVersion) {
        return update(key, newValue, expectedVersion, "global");
    }

    @Override
    @Transactional(rollbackFor = Exception.class)
    public boolean update(String key, Object newValue, int expectedVersion, String scope) {
        // 1. 乐观锁更新
        LambdaUpdateWrapper<<EntityName>> wrapper = new LambdaUpdateWrapper<>();
        wrapper.eq(<EntityName>::getConfigKey, key)
               .eq(<EntityName>::getScope, scope)
               .eq(<EntityName>::getVersion, expectedVersion)
               .set(<EntityName>::getConfigValue, String.valueOf(newValue))
               .set(<EntityName>::getVersion, expectedVersion + 1);
        int rows = mapper.update(null, wrapper);
        if (rows == 0) {
            log.warn("配置热更新乐观锁冲突: key={}, scope={}, expectedVersion={}", key, scope, expectedVersion);
            return false;
        }

        // 2. 缓存失效
        evictCache(key, scope);
        log.info("配置热更新成功: key={}, scope={}, newVersion={}", key, scope, expectedVersion + 1);
        return true;
    }

    @Override
    public void evictCache(String key) {
        evictCache(key, "global");
    }

    @Override
    public void evictCacheByScope(String scope) {
        // Redis SCAN 按 scope 前缀失效（生产慎用）
        log.info("按 scope 失效缓存: scope={}", scope);
    }

    private void evictCache(String key, String scope) {
        String cacheKey = CACHE_KEY_PREFIX.formatted(scope, key);
        safeRedisDelete(cacheKey);
    }

    @Override
    @PostConstruct
    public void warmUp() {
        log.info("<EntityName> 缓存预热开始");
        // 加载高频 key 到 Redis（如 base_rate / score_threshold）
        // 防 Redis 故障首次启动全量读穿透 DB
    }

    // === 降级兜底（Redis 故障时直读 DB） ===
    private String safeRedisGet(String key) {
        try {
            if (redissonClient.isShutdown() || !redissonClient.getKeys().count() > 0) return null;
            return RedisUtils.getCacheObject(key);
        } catch (Exception e) {
            log.warn("Redis 读失败，降级直读 DB: key={}", key, e);
            return null;
        }
    }

    private void safeRedisSet(String key, String value, Duration ttl) {
        try {
            RedisUtils.setCacheObject(key, value, ttl);
        } catch (Exception e) {
            log.warn("Redis 写失败: key={}", key, e);
        }
    }

    private void safeRedisDelete(String key) {
        try {
            RedisUtils.deleteObject(key);
        } catch (Exception e) {
            log.warn("Redis 删失败: key={}", key, e);
        }
    }
}
```

| 坑 | 影响 | 规避 |
|---|---|---|
| **`@Transactional(rollbackFor = Exception.class)` 漏写**：默认只回滚 RuntimeException | checked exception 不回滚 | 显式声明 `rollbackFor = Exception.class`（CLAUDE.md G-04 硬约束） |
| **`synchronized` 锁粒度过粗**：锁整个 Service 实例 | 高并发下性能雪崩 | 用 `cacheKey.intern()` 字符串驻留 + 局部同步块 |
| **Redis 故障 → DB 击穿**：未做降级 | Redis 挂时 100% 请求穿透到 DB，可能打挂 DB | `safeRedisGet/Set/Delete` 三件套 + 启动 `warmUp()` |
| **`@RequiredArgsConstructor` 漏 final 字段**：Lombok 不生成构造器 | 启动 NPE | Service 字段必须 `private final` + `@RequiredArgsConstructor`（CLAUDE.md §11 约定） |
| **JSON 字段手动 `String.valueOf` 序列化**：复杂对象丢失类型 | 反序列化失败 | 用 Jackson `ObjectMapper.writeValueAsString()` 序列化 |
| **乐观锁冲突返回 `false` 而非抛异常**：上游无法感知 | 配置热更新静默失败 | 抛 `IpdBusinessException(409, "version_conflict")` 触发告警 |
| **缓存击穿（雪崩）**：synchronized 块未二检 | 雪崩时同一 key 重复查 DB | 双检锁（见模板） |

### 2.6 Step 6：Mockito 适配（typed any 解决重载歧义）

**目标**：解决 Mockito 在重载方法上的 `any()` 类型歧义——`BaseMapper<T>` 多个 `update` / `selectList` 重载。

**触发场景**：

```java
// BaseMapper.java
int update(@Param("et") T entity, @Param("ew") Wrapper<T> updateWrapper);
int update(@Param("ew") Wrapper<T> updateWrapper);  // 重载 2

// 当测试这样写：
when(mapper.update(eq(null), any(LambdaUpdateWrapper.class))).thenReturn(1);
// → Mockito 报 "ambiguous method call"，不知道是哪个重载
```

**解决方案**（typed any 显式类型）：

```java
// ❌ 错误：模糊 any()
when(mapper.update(any(), any())).thenReturn(1);
when(mapper.selectList(any(), any())).thenReturn(List.of());

// ✅ 正确：typed any()
when(mapper.update(any(<EntityName>.class), any(LambdaUpdateWrapper.class))).thenReturn(1);
when(mapper.selectList(any(LambdaQueryWrapper.class), any())).thenReturn(List.of());

// ✅ 也可用 eq() 配合 any()
when(mapper.update(eq((<EntityName>) null), any(LambdaUpdateWrapper.class))).thenReturn(1);
```

**常见坑 + 规避**：

| 坑 | 影响 | 规避 |
|---|---|---|
| **`any()` 无类型 + 重载方法**：编译期无错，运行期 `AmbiguousMethodCallException` | 测试失败 | typed any：`any(<EntityName>.class)` / `any(Wrapper.class)` |
| **`any(Class)` + null 入参**：Mockito `any(Class)` 默认包含 null，但 `eq(null)` 不匹配 null 外的值 | 测试覆盖不全 | `eq((<EntityName>) null)` 显式强转 |
| **泛型擦除**：`any(LambdaUpdateWrapper.class)` 编译警告 unchecked cast | 警告不阻断，但可加 `@SuppressWarnings("unchecked")` | 接受警告或用具体子类 `any(LambdaUpdateWrapper<<EntityName>>.class)`（不推荐） |
| **静态方法 mock + 实例方法 when 顺序**：先 `Mockito.mockStatic()` 再 `when()` | mock 未生效 | 顺序：static mock → when → exercise |

### 2.7 Step 7：GUARD-1 复检（钩子触补 `@TableLogic`）

**目标**：GUARD-1 钩子（`.claude/helpers/ddl-entity-lint.cjs`）检测 DDL 新增的 `deleted` / `del_flag` 列与 Entity `@TableLogic` 注解是否对齐。

**触补模式（ROOT-R1 实样）**：

**常见坑 + 规避**：

| 坑 | 影响 | 规避 |

| **GUARD-1 钩子漏扫字段类型变化**：DDL 改 `del_flag` → `deleted` 但 Entity 字段未同步 | 软删除失效 | 每次 DDL 改动后立即复检（PostToolUse 触发） |

## 4. 常见坑汇总（跨 8 步的 21 个高频坑）

> 本节为 8 步流程中所有「常见坑」的精简版索引，供子卡承接者自查。

### 4.1 Step 1 DDL 阶段（3 个）

| # | 坑 | 规避 |
|---|---|---|
| 1 | 多租户过滤误伤 | `@InterceptorIgnore(tenantLine = "true")` |
| 2 | JSON 列方言分支（PG vs MySQL） | 抽离 `db/migration/dialect/` |
| 3 | 乐观锁版本号漏 `@Version` 配套 | Entity `@Version` + `OptimisticLockerInnerInterceptor` |

### 4.2 Step 2 Entity 阶段（4 个）

| # | 坑 | 规避 |
|---|---|---|
| 4 | Lombok `@Builder` 与 `BaseEntity` 冲突 | 不在 BaseEntity 子类加 `@Builder` |
| 5 | `@TableLogic` 漏标（GUARD-1 触补场景） | DDL 加 `deleted` 列 → Entity 必须 `@TableLogic` |
| 6 | JSON 字段映射漏 `@TableField(typeHandler)` | 用 `String` 手动解析（推荐） |
| 7 | Entity 字段命名未对齐 DDL | `@TableField("config_key")` 显式映射 |

### 4.3 Step 3 Mapper 阶段（3 个）

| # | 坑 | 规避 |
|---|---|---|
| 8 | `@InterceptorIgnore` 漏加 | 必须显式标注（业务参数与租户无关） |
| 9 | `BaseMapper<T>` 泛型类型错误 | 检查 `<EntityName>` 必须完整类名 |
| 10 | `@Param` 注解参数命名与 XML `#{}` 不一致 | 严格按 `@Param("name")` 与 `#{}` 一致 |

### 4.4 Step 4 Service 阶段（5 个）

| # | 坑 | 规避 |
|---|---|---|
| 11 | `@Transactional(rollbackFor = Exception.class)` 漏写 | 显式声明（CLAUDE.md G-04 硬约束） |
| 12 | `synchronized` 锁粒度过粗 | 用 `cacheKey.intern()` 字符串驻留 |
| 13 | Redis 故障 → DB 击穿 | `safeRedisGet/Set/Delete` 三件套 + `warmUp()` |
| 14 | `@RequiredArgsConstructor` 漏 final 字段 | Service 字段必须 `private final`（CLAUDE.md §11） |
| 15 | 乐观锁冲突返回 `false` 而非抛异常 | 抛 `IpdBusinessException(409, "version_conflict")` |

### 4.5 Step 5 单测阶段（4 个）

| # | 坑 | 规避 |
|---|---|---|
| 16 | `@Tag("dev")` 漏加 | 类级别 `@Tag("dev")`（CLAUDE.md 必填） |
| 17 | `Mockito.mockStatic` 未 try-with-resources | 静态 mock 必须 try-with-resources |
| 18 | `any()` 与 `eq()` 混用（参数匹配器错配） | 同一调用全 matchers 或全 values |
| 19 | `@MockBean` 不能 mock 静态方法 | 必须 `Mockito.mockStatic(RedisUtils.class)` |

### 4.6 Step 6 Mockito 适配阶段（2 个）

| # | 坑 | 规避 |
|---|---|---|
| 20 | `any()` 无类型 + 重载方法（运行期歧义） | typed any：`any(<EntityName>.class)` |
| 21 | `any(Class)` 与 `eq(null)` 混用 | 显式 `eq((<EntityName>) null)` 强转 |
