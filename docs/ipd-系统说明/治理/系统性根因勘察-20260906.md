## 2. 5 大系统性根因

### R1 业务架构师缺失（参数应可配置未配置）

**根因**：业务规则参数（如奖金池基数 5%、KPI 阈值 60 分、删项冷静期 3 天、Gate 双签人数 ≥3）目前以字面量 / 注释形式散落在 Service 层与 PRD 中，无独立 Config 表或枚举固化。Agent2 检出 B-CONS-03 / B-RULE-01 / B-RULE-05，Agent3 检出 V5 / V8，Agent1 检出 ZK-05 / ZK-13 / ZK-14 / ZK-17，均同源。

**跨漏洞影响**：

- 同一参数在不同 Service 用不同字面量（奖金池 Q2 口径回款 vs 合同）
- 演示模式与生产模式无代码级隔离（demo.enabled=false 但语料含演示）
- 业务规则调整需改代码 + 重新部署，无法热更新

**根治建议**：

1. 新增 `ipd_business_config` 表（key / value / scope / enabled / version），迁移 8 类参数
2. 新增 `BusinessConfigService`（带缓存，与 SystemConfig 解耦）
3. 字面量替换为 `BusinessConfigKeys` 常量类

**归属卡**：B-CONS-03 + B-RULE-01 + B-RULE-05 + V5 + V8 + ZK-05/13/14/17 = 9 子项

---

### R2 通知链路覆盖不全

**根因**：通知（IM/邮件/站内信）目前以"Service 间直接调用"实现，无统一 NotificationService、无中间件抽象、无重试/降级/聚合。Agent2 检出 B-NOTI-01 / B-NOTI-02，Agent3 检出 V8（同源），Agent1 检出 ZK-10。

**跨漏洞影响**：

- 同一事件 9 种通知模板，但缺 3 种（ZK-IPD 对比发现）
- 通知文案硬编码中文，无法 i18n
- 发送失败无重试，主流程已 commit 但用户未感知

**根治建议**：

1. 新增 `NotificationService`（中间件化：站内信/邮件/WebSocket 三通道）
2. 新增 `NotificationTemplate` 表（key / channel / locale / version）
3. 集成 Redisson 延迟队列做重试与聚合

**归属卡**：B-NOTI-01 + B-NOTI-02 + V8 + ZK-10 = 4 子项

---

### R3 跨状态机/跨域联动守卫缺失

**根因**：6 阶段 7 状态机间存在跨域联动（如删除请求 ↔ 项目状态机、KPI 60 天无产出 ↔ 奖金发放），但联动仅靠 Service 调用顺序保证，无统一的"状态机守卫"层。Agent2 检出 B-STAT-01 / B-STAT-02 / B-STAT-04，Agent3 检出 V2 / V6，Agent1 检出 ZK-04。

**跨漏洞影响**：

- 项目已删除但子状态机仍可触发（联动断点）
- nextCode 并发竞态（前缀生成非原子）
- "驳回"路径实现与文档不一致（仅允许上一阶段 vs 任意阶段）

**根治建议**：

1. 新增 `StateMachineGuard` 抽象（pre-check / post-commit 两阶段）
2. nextCode 改用 `DistributedLock` + DB sequence 双保险
3. 状态机迁移图导出为 JSON（供前端 V6 与文档 ZK-04 共用）

**归属卡**：B-STAT-01 + B-STAT-02 + B-STAT-04 + B-STAT-05 + V2 + V6 + ZK-04 = 7 子项

---

### R4 文档承诺与代码实现口径漂移

**根因**：ZK-IPD 业务参考 + 本仓库 PRD + 代码实现 三者口径不一致，且无自动校验。Agent2 检出 B-RULE-02 / B-CONS-05，Agent3 检出 V1 / V3 / V4 / V7，Agent1 检出 ZK-01~ZK-18 共 18 项中 14 项属此类。

**跨漏洞影响**：

- 文档说"5 Gate 33 要素"，代码只渲染 19 项（V4）
- 表单 schema 与 DTO 字段命名混用（V3）
- 评审人数、驳回路径、删项冷静期等文档与代码不一致
- 验收清单 237 条 AC 编号漂移

**根治建议**：

1. 新增 `docs-link-check.yml`（CI 钩子，文档中引用的字段/枚举必须存在于代码）
2. 新增 `acceptance-matrix.json`（237 条 AC ↔ 自动化用例 ↔ 文档三向关联）
3. PRD 修订走 PR + 评审（与代码同流程）

**归属卡**：V1 + V3 + V4 + V7 + B-RULE-02 + B-CONS-05 + ZK-01/02/03/06/07/08/11/12/15/16/18 = 18 子项

---

### R5 强类型字段孤岛（字段定义就位但消费链路未完成）

**根因**：DDL 已加字段（如 audit_chain_hash、project_member.role_ext、bonus_pool.frozen_at），但 Entity / DTO / Mapper / Service / Controller 消费链路未完整跑通。Agent2 检出 B-CROSS-02，Agent3 检出 V3（同源），Agent1 检出 ZK-09。

**跨漏洞影响**：

- 字段已建索引但查询未用（性能浪费）
- 字段已加 Entity 但 Controller / DTO 未透出（前端拿不到）
- 字段命名风格混用（snake/camel）

**根治建议**：

1. 新增 `entity-field-usage-lint.cjs`（Hook 工具，DDL 新增字段后 7 天内必须出现在 ≥3 处使用）
2. DTO 字段命名统一为 camelCase，DB 列名 snake_case（MyBatis-Plus `@TableField` 映射）
3. 字段孤岛报告纳入周治理卡

**归属卡**：B-CROSS-02 + V3 + ZK-09 = 3 子项
