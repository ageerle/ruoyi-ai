## 5. 5 大根因的根治性方案（不是逐项打补丁）

### 5.1 R1 业务架构师缺失——配置化扫描 + 硬编码阻断

**根治目标**：业务规则参数（金额阈值 / 天数 / 系数 / 人数）100% 走 `system_configs` 表 + `SystemConfigService.get(key)`，Service 层禁止硬编码字面量。

**根治步骤**：
1. **建立 system_configs 配置化扫描脚本**（`.claude/helpers/config-usage-lint.cjs`）——PostToolUse 命中 `**/service/**/*Service.java`，扫描常见业务参数硬编码模式（`0.05` / `60` / `7` / `3` / `5`），stderr 警告。
2. **每张配置相关卡必须走 system_configs 默认值链**——`ConfigMigration` 工具类（`@PostConstruct` 启动时校验所有 `SystemConfigKey` enum 对应值在表中存在，缺失则自动 INSERT 默认值）。
3. **加 PreToolUse hook 阻断硬编码**——写 `Service.java` 时若包含 `0.05` / `0.6` 等字面量，stderr 警告但不阻断（与 sensitive-field-guard 的 ERROR 区分）。
4. **加 `@ConfigValue(key = "...")` 注解**——Service 方法参数注入，编译期类型校验。
5. **季度审计**：每季度跑 `node .claude/helpers/config-usage-lint.cjs --report=quarterly` 输出「硬编码 Top 10」。

**关联卡**：P0-4（主犯）+ P1-9（落地）。

### 5.2 R2 通知链路覆盖不全——NotificationService Observer 中间件

**根治目标**：实体状态变更自动触发通知清单，开发者只需加 `@NotifyOnChange` 注解，无需手动调 `NotificationService.notify()`。

**根治步骤**：
1. **建立 NotificationService Observer 模式中间件**——`NotificationPublisher.publish(NotifyEvent)` + `NotifyListener` 接口。
2. **实体状态变更 → 自动通知清单**——`@NotifyOnChange(entity = "Project", field = "status", channel = "IN_APP", template = "project.status.changed")` 注解处理器在 Entity setter / Service 写方法后触发事件。
3. **通知中间件化（统一重试 / 降级 / 去重）**：
   - 重试：最多 3 次指数退避（1s / 4s / 16s）。
   - 降级：失败 3 次后写入 `notification_dead_letter` 表，人工排查。
   - 去重：Redis `SETNX notify:dedup:<eventId>` TTL 24h。
4. **12 种通知模板**（ZK-10）全部登记 `system_configs.notification_templates` JSON 字段，可热更新。
5. **通知渠道抽象**：`NotificationChannel` 接口（`InAppChannel` / `EmailChannel` / `SmsChannel` / `WebhookChannel`），默认实现 `InAppChannel`，其余按需实现。

**关联卡**：P0-2（主犯）+ P1-10（文案字典化）。

### 5.3 R3 跨状态机联动守卫缺失——StateDependencyRegistry 全局注册表

**根治目标**：状态机迁移前自动查询依赖，依赖不满足 → 拒绝迁移 + 明确错误消息。

**根治步骤**：
1. **建立 StateDependencyRegistry 全局注册表**——`Map<EntityType, List<DependencyRule>>`，规则形如 `(targetState, requiresEntity, requiresStatus)`。
2. **状态机迁移前查询依赖**——`StateTransitionService.transition(entityId, fromState, toState)` 前置查询注册表，依赖不满足抛 `IpdBusinessException(409, "transition blocked: requires gates=APPROVED but current=PENDING")`。
3. **提供 `@RequiresState(of = "gates", status = "APPROVED")` 注解**——方法级别约束，由 `RequiresStateAspect`（BeanPostProcessor 织入）执行。
4. **驳回路径任意阶段**（对齐 ZK-04）：`@RequiresState(of = "current_state", notEquals = "ARCHIVED")` 允许任意阶段驳回，但禁止已归档。
5. **回退路径说明**：3 个无回退的状态机（项目删除 / 删项审批 / KPI 停发）补 `transition_failure_message` 字段。

**关联卡**：P0-1（主犯）+ P2-2（回退路径文档化）。
