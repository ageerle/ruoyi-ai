# 事实源五必现查规约（2026-09-08 R13 立）

> 触发：R12.1 收口轮同一轮发生 3 项输出异常——marker 凭记忆写错 hash（136ef385 vs e8eb3136）+ shell cwd 漂到前端仓导致 git log 显示错误 hash + 看板 updated_at PUT 后不刷新。
> 目标：把「凭记忆写事实」升级为「现查现写」，根除事实源引用错位类事故。
> 适用于：所有会话（主协调 / 兄弟 / 蜂群 subagent），所有仓（ruoyi-ai / ruoyi-ipd-web / ZK-IPD）。

## 五必现查

### 1. commit / PR hash 必现查
- 任何 message / marker / 看板注记 / 镜像段里写 hash 前：`git log --oneline -5` 现查现复制
- **禁止**：从上一轮输出或记忆里复制 hash 拼进本轮 marker
- 实测教训：R12.1 marker 写了 R11 的 136ef385（正确应为 R12 的 e8eb3136），需要追加修正段才能闭环

### 2. 端口 / 库名 / socket / 字段名 / 枚举值必现查
- 真库探针：`SHOW TABLES` / `DESCRIBE <table>` / `SELECT ... FROM information_schema.COLUMNS WHERE TABLE_NAME='<t>'`
- 应用配置：按**键名** grep（不用行号，行号分钟级漂移）
- **禁止**：凭文档或记忆写端口号（3306 vs 13306 事故）/ 字段名（persons.role vs person_type 事故）/ 列存在性（proposer_group_id / project_members.group_id 不存在事故）

### 3. 镜像 / 文档段号必现查
- 引用段号前：`grep -n '^## ' <file>` 现查
- **推荐**：只写「R12 段」这类轮次标识，不带 L 号（段号随追加必漂）
- **禁止**：随手写 L658-684 这类区间（下一轮追加后即失效）
- 历史事故：application.yml `demo:` 段 20:56 在 :396、21:10 已到 :400；tenant.excludes 从 :148 漂到 :198

### 4. 看板写入后必 fresh 读回（GET + LIST 双复核）
- PUT 后：独立 GET `/api/tasks/<id>` + 独立 LIST `/api/tasks?project_id=<pid>`，对比 **desc_len + marker content**
- **不依赖**：`updated_at` 字段（实测 PUT 后不刷新，停在 created_at 时刻）
- **禁止**：只看 PUT 返回 200 / success=true 就判成功（该看板 PUT 有静默失败前科）
- 单卡 GET 偶发返回空描述 → PUT 整体替换会清空 content：**取基文用 LIST 端点**

### 5. 跨仓命令必 `cd 绝对路径 &&` 开头
- 多仓工作区（ruoyi-ai / ruoyi-ipd-web / ZK-IPD）里每条 git / mvn / pnpm 命令：`cd /Users/mac/Documents/<repo> && <cmd>`
- **禁止**：依赖 shell 会话残留 cwd（实测 Node fallback 后 cwd 漂到 ruoyi-ipd-web，导致 `git log` 显示前端仓 hash、`bd8b3bd3` 被报 unknown revision）
- 兄弟症状：同一条验证命令跑错仓 → 结论全错还自以为验证过了
