### F-1 [CRITICAL] `kpi/functional/index.vue` L76 + L105：`isTransportError` 收错误参数

```vue
<!-- L76：永远 false，「重试」按钮永远不出现 -->
<Button v-if="errorMsg && isTransportError({ message: errorMsg })" :loading="loading" @click="load">重试</Button>
<!-- L105：永远 true，错误永远以普通红字呈现，不会走"断网"形态 -->
<div v-if="errorMsg && !isTransportError({ message: errorMsg })" class="mt-2 text-xs text-red-600">{{ errorMsg }}</div>
```

**症状**：`isTransportError` 定义在 `_shared/ipd-error-text.ts:140-142`，签名要求 `error instanceof IpdRequestError && error.kind === 'transport'`。但调用点传的是**字面量对象** `{ message: errorMsg }`（一个普通对象，无 `.kind`、不是 `IpdRequestError` 实例）。因此：
- `v-if` 条件恒为 `false` → 传输异常时**无重试按钮**
- `v-else` 条件恒为 `true` → 所有错误都走普通红字，丢失"断网请重试"的明确语义

**建议修复**：

```diff
- <Button v-if="errorMsg && isTransportError({ message: errorMsg })" :loading="loading" @click="load">重试</Button>
+ <Button v-if="errorMsg && loadErrorCause && isTransportError(loadErrorCause)" :loading="loading" @click="load">重试</Button>
- <div v-if="errorMsg && !isTransportError({ message: errorMsg })" class="mt-2 text-xs text-red-600">{{ errorMsg }}</div>
+ <div v-if="errorMsg && !(loadErrorCause && isTransportError(loadErrorCause))" class="mt-2 text-xs text-red-600">{{ errorMsg }}</div>
```

需在 script 里新增 `const loadErrorCause = ref<unknown>(null)`，catch 时 `loadErrorCause.value = cause`。  
这与 sibling 文件 `kpi/index.vue`（L100-107）的实现形态完全对齐——后者直接传 `cause` 进 `isTransportError`，工作正常。

### F-3 [WARNING] `project-score/index.vue` L62-101：`load()` 覆盖 `tasks` 字段语义

```ts
async function load() {
  // ...
  const [listResult, taskResult] = await Promise.all([
    listProjectScores(projectId.value.trim(), period.value.trim()),
    listMyScoreTasks().catch(() => [] as ProjectScore[]),  // ← 注意：这里无视 projectId/period
  ]);
  scores.value = listResult;
  tasks.value = taskResult;  // ← 但仍写回 tasks
  // ...
}
```

**症状**：表头第二张"我的评分任务"卡片显示「待我评分的项目/动作」。它由 `tasks.value` 驱动：
- onMounted 调 `loadTasks()` → 写 `tasks.value = await listMyScoreTasks()`（不带过滤，正确）
- 用户输入 projectId+period 后点「查询评分」→ 调 `load()` → **重写** `tasks.value = await listMyScoreTasks()`（不带过滤，但用户期望看到的是"该项目的"任务）

实际结果：用户**永远看不到**「按项目过滤后的待评分任务」，`tasks` 卡片永远显示「我全部的待评分任务」。这与「项目评分明细」上方的 `scores` 卡片无任何过滤关系——**两张卡片展示同一份数据**。

**建议修复**：

```diff
-    tasks.value = taskResult;
+    // 「我的评分任务」是用户级，与项目/周期无关，load() 不要重写。
+    // 仅在第一次进入时由 loadTasks() 填充；后续按「查询评分」不应清空。
+    if (!tasks.value.length) tasks.value = taskResult;
```

或更彻底：在 `load()` 中**不调用** `listMyScoreTasks()`，把它的初始加载职责完全交给 `loadTasks()`。

### F-4 [WARNING] `action-detail/index.vue` L491-493：`v-bind:disabled` 复杂表达式优先级可疑

```vue
<Button
  ...
  :disabled="isBlocking && showCert && (!action.certNo || !action.certPassedAt)
    && !(fields.certNo && fields.certPassedAt)"
  @click="askTransit('DONE')"
>
  切到「已完成」
</Button>
```

**症状**：表达式按 JS 优先级解析为 `(isBlocking && showCert && (!certNo || !certPassedAt)) && !(fields.certNo && fields.certPassedAt)`。
- 分支 A：`isBlocking && showCert && 缺前置` → 真
- 分支 B：`fields` 已填 → 真
- 两者都真才 disabled（双重否定）

`v-bind:disabled` 没有显式小括号，依赖 `&&` 左结合 + 单目 `!` 高优先级。作者意图看起来是"前置缺 + 本次也未补 → 阻断"，但写成 `A && !(B)` 在多读者环境下极易误读为 `A && !B`（DE Morgan 等价但语义反转）。

**建议修复**：加显式小括号或拆成 computed：

```ts
const cannotTransitToDone = computed(() =>
  isBlocking.value && showCert.value && (!action.value?.certNo || !action.value?.certPassedAt) &&
  !(fields.certNo && fields.certPassedAt),
);
```
