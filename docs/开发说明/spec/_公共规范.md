# IPD 产品经理管理系统 — 项目公共规范

> **拼装来源**：`assets/公共规范-通用.md`（token 骨架）+ `design-specs/后台-RuoYi-AI.md`（类型规范）+ 本项目色板与签名。
> **视觉基准**：RuoYi-AI 官方前端栈 `Vue 3 + Vben Admin + element-plus-x`（用户 2026-09-04 决策：二次开发基于 https://github.com/wilson323/ruoyi-ai，规范与之一致）。
> **需求基准**：`IPD系统_AI开发主Prompt_v3.md`（唯一权威规格，硬约束 G-04）。
> **本文件是全部页面的"宪法"**：所有页面从这里取样式，不得另起炉灶。

## 一、目标形态

- **桌面优先**的企业内网后台，设计视口 **1440 × 1024**
- 响应式适配即可，**不做移动端原生 App**（v3 第 10 节明确不做）
- **全中文界面**（硬约束 G-07），文案抽离 i18n，一期只填 `zh-CN`
- 浏览器：Chrome / Edge 最新两个大版本（TS-14）

| 组件 | 本项目强制规格 |
|---|---|
| **六阶段流程条** | 横向 6 段：概念 / 计划 / 开发 / 验证 / 发布 / 生命周期。已完成主色实心、当前主色描边、未开始灰色；**阻断未过时下一阶段置灰且 Tooltip 说明卡在哪个动作** |
| **深管动作卡片** | 白卡片 + 主色左边框 4px，展示：动作编号+名称 / 状态徽标 / 主责人 / 到期日 / 交付物数量图标 / SOP 入口 |
| **轻管动作行** | 单行紧凑，**仅显示动作名 / 状态徽标 / 完成日期**，不占视觉权重，**无附件上传入口**（G-10、BR-IPD-04） |
| **D11 特例行** | 轻管行式基础上额外显示 `FAR` / `FRR` 两个数值（BR-IPD-05 例外二） |
| **Gate 要素判定表** | 每行一个要素：要素名 / 通过标准 / 三态单选（✅通过 ⚠️带条件 ❌不通过）/ 否决项红色徽标；⚠️ 选中后**必填责任人 + 关闭期限**；命中 ❌ 时**提交按钮置灰 + 高亮命中项** |
| **双签状态条** | 两列并排（市场PM / 研发PM），**双方都提交前互相显示"对方尚未提交"，不泄露结论**（BR-GATE-04）；显示 3 天倒计时 |
| **审批链步骤条** | 用于删除审核（组长初审 2 工作日 → 超级管理员终审 2 工作日）、需求变更双签 |
| **台账表格** | 津贴/奖金台账，金额右对齐、tabular-nums、合计行加粗置底 |
| **禁用态** | **权限不足不隐藏入口**，展示禁用态 + Tooltip 说明原因（便于评审时看清权限边界） |
| **归档只读态** | 归档项目全页只读：所有编辑按钮禁用 + 顶部黄色条"本项目已归档，仅可查看与导出" |

## 八、文案基调（术语表，全站强制统一）

来源：v3 第 3.0 节术语表。**以下措辞不得替换**：

| 必须使用 | 禁止使用 | 依据 |
|---|---|---|
| 深管动作 / 轻管动作 | 重点动作 / 普通动作 | 3.0 术语表 |
| 阻断性动作 | 必做动作 / 卡点 | 3.0 术语表 |
| 产品组长 | 直接上级 / 评审上级 / 代理组长 / 代审人 | **G-09**（系统内无此角色） |
| 市场PM / 研发PM | 产品经理甲乙 / 主PM 副PM | 3.0 术语表 |
| 回款 | 销售额 / 出库额 / 开票额（达成率语境下） | **Q2 决策** |
| 项目绩效综合得分 | 季度考核分 | **Q3 决策**（评定对象是项目不是季度） |
| L1–L5 能力等级 | 职级 / 评级分 | BR-KPI-08 需与项目绩效得分严格区分 |
| 双签 / 双签否决 | 会签 / 联审 | BR-GATE-03 |
| 超级管理员 | 超管 / 系统管理员 | 正文用语（代码 enum 仍为 `super_admin`） |
| 待补充 / 未配置 | 暂无 / — / 空白 | **G-06** |

**补充术语（字段与实体命名边界，全站强制统一）**

- **`deadline`（业务级截止）**：如提交评审意见、招标截止、任务到期。挂在业务实体上，语义是"这件事最晚什么时候要做完"。
- **`dueAt`（动作级时间戳）**：如签署到期（按 `gate.signDeadlineDays` 计算）、审批超时、cron 扫描判定。语义是"这个动作节点在哪个时刻失效"，由系统参数推算而非人工填写。
- **`revisionId`（SOP 版本号字段）**：SOP 发布版本的唯一标识，全站统一此名；`work_items.revision`（工作项修订号，v3 模型定义）是另一个概念，不得混用。
- **`demand`**：游客通过需求门户（`/public/demands`）提报的外部需求；code 形如 `D-2026-XXX`，未立项前不挂 project。
- **`requirement`**：内部立项后的需求单，挂在 project 下，路径 `/api/requirements/:id`。
- **`guest_demand`**：审计日志 `entityType`，专指游客需求归档后写入审计。
- **`阻断性动作`**：指被标记为"必须完成才能放行阶段出口"的动作对象（如 P10 / V02），是名词性修饰语。当"阻断"作动词单独使用（如"系统阻断写入""阻断提交"）时保留原写法，不加"性动作"。
- **审计 `entityType` 边界**：`gate` = 整张门禁单的状态流转（`action=create|submit|arbitrate|waive|sign`）；`gate_element_result` = 单个要素的三态判定结果（`action=judge`）。**不使用 `gate_review` 作为 entityType**（其语义并入 `gate` 的 `action=sign|arbitrate`）；`gate_review_material` / `gate_review_element` 是表名与实体名，保留 snake_case，不受此约束。

**写法规则**

- 主动语态：按钮写"提交评审意见""发起删除申请""确认停发"
- 错误 / 空态写方向：`暂无待办。从「我的项目」进入 IPD 流程开始执行深管动作。`
- 同一动作全流程同名：按钮"提交评审意见" → 状态"待对方签署" → 提示"已提交，等待对方签署"
- **禁止出现"100% 闭环""无遗留疑问""完全自动"等绝对化文案**（G-06，硬约束）
- 未知状态一律显式写「待补充」或「未配置」，不留空白

## 九、涉钱与合规展示规则（硬约束落到 UI）

1. **所有系数、阈值、期限、额度在界面上必须标注来源为"系统参数"**，并在超级管理员参数配置页可改（G-05 / G-08）。原型中这些数值从 `mock-data.js` 的 `systemConfigs` 取，**不写死在页面 HTML 里**
2. 达成率阶梯按 **6 档区间制**展示：`>120%→1.2`｜`100%–120%（含）→1.0`｜`85%–99.99%→0.8`｜`70%–84.99%→0.6`｜`50%–69.99%→0.3`｜`<50%→0`
3. 奖金公式必须在页面上完整展示：`奖金池 = 目标销售额 × 5% × 差异化系数`，`每人奖金 = 奖金池 × 达成率阶梯系数 × 贡献度比例 × 绩效系数`
4. 贡献度：市场PM 40%–65%、研发PM 35%–60%，**两者之和恒为 100%**，前端联动校验
5. 项目绩效评定权重：自评 20% + 市场侧组长 40% + 研发侧组长 40%，**三者和恒为 100%**，前端联动校验
6. **删除无直接入口**：全站任何"删除"按钮都跳转到"发起删除申请"，不做即时删除（G-02 / BR-DEL-06）
