## D.6.1 7 态需求状态机迁移触发器

需求状态机：`SUBMITTED → ACCEPTED → EVALUATING → SCHEDULED → PROCESSING → CLOSED → ARCHIVED`，旁路态 `WITHDRAWN`（限 24h 撤回）。

| 起始态 | 触发动作 | 目标态 | 触发者 | 关联页面 |
|---|---|---|---|---|
| SUBMITTED | PM 点"受理" | ACCEPTED | product_manager | 40 / 41 |
| ACCEPTED | PM 点"评估" | EVALUATING | product_manager | 40 / 41 |
| EVALUATING | PM 录入评估结论 | SCHEDULED | product_manager | 40 / 41 |
| SCHEDULED | PM 关联 workItemId | PROCESSING | product_manager | 40 / 41 |
| PROCESSING | 关闭确认 | CLOSED | product_manager | 40 / 41 |
| CLOSED | 归档操作 | ARCHIVED | super_admin | 40 / 41 |
| 任意 → WITHDRAWN | 游客撤回（限 24h） | WITHDRAWN | guest | 39 |

**关键约束**

- 7 态迁移只允许上表逐条触发；任意越级或回退须经 super_admin 介入并写 `audit / state_force_change`。
- WITHDRAWN 仅对 `SUBMITTED → EVALUATING` 期间开放，PROCESSING 之后不可撤回，只能走关闭/归档。
- 每条迁移写 `audit / requirement_state_transition`：起始态、目标态、触发者 userId、触发时间、workItemId（若已绑定）。

## D.6.2 4 态删除申请迁移与双层审核计时

删除申请状态机：`DRAFT → LEADER_REVIEW → ADMIN_REVIEW → DELETED`，旁路态 `REJECTED`、`DRAFT 撤回`。

| 起始 | 触发 | 目标 | 期限 | 触发者 | 关联页面 |
|---|---|---|---|---|---|
| DRAFT | 提交删除申请 | LEADER_REVIEW | 2 工作日 | 任意 | 04 |
| LEADER_REVIEW | 产品组长通过 | ADMIN_REVIEW | 2 工作日 | product_lead | 05 |
| LEADER_REVIEW | 产品组长驳回 | REJECTED | — | product_lead | 05 |
| ADMIN_REVIEW | 超管通过 | DELETED | — | super_admin | 05 |
| ADMIN_REVIEW | 超管驳回 | REJECTED | — | super_admin | 05 |
| 任意（未超 24h） | 申请人撤回 | DRAFT 撤回 | 24h | 申请人 | 04 |

**关键约束**

- 双层审核合计最长 4 工作日（第 2 工作日未结自动升级提醒组长 + 超管）。
- `REJECTED` 后须由申请人新建一条 DRAFT，原单号归档保留。
- DRAFT 撤回后数据保留 30 天便于审计查询，到期清理。

## D.6.3 4 态人员状态联动 FROZEN_PENDING_HANDOVER 流程

人员状态机：`ACTIVE ↔ FROZEN_PENDING_HANDOVER → DISABLED`，旁路态 `FROZEN_PENDING_HANDOVER → ACTIVE`（复活）。

**完整流程（HR API 识别 RESIGNED 起，至 ACTIVE 复活或 DISABLED 终止止）**

1. **触发**：HR API 识别人员状态 = `RESIGNED`。
2. **账户冻结**：`accountStatus → FROZEN_PENDING_HANDOVER`，仅保留"移交"权限，所有业务模块只读。
3. **待移交任务生成**：系统生成 N 条 `pending_handover_task` 记录（一个 workItem 一条），同时推送本人 + 双方组长 + 超管（在企微卡片中显示 @所有人）。
4. **一键移交**：本人或组长/超管代操作（HR-USER-06 关键闭环）。
   - 本人操作：进入 `/handover` 页面勾选目标承接人 → 系统改写 workItem owner。
   - 代操作：组长/超管进入代移交面板，选承接人 + 备注后批量改写。
5. **账户失效**：所有 workItem 完成 owner 变更后，`accountStatus → DISABLED` + 解绑企微。
6. **逾期升级**：15 自然日内未完成移交 → 升级超管并每日提醒（含企微 + 邮件 + 待办红点）。
7. **复活路径**：若 HR API 在 DISABLED 前撤销 RESIGNED 信号（即"复活"），则 `DISABLED → ACTIVE`，所有 workItem 保持原 owner 不动（避免回滚混乱）。
8. **津贴结算**：移交生效日所在月初，PM 领取当月全额津贴（BR-INC-11）——即"按月结算，不按在岗日折算"。

**关联页面**：08 人员列表、09 移交面板、15 项目日志（移交事件）、33 津贴台账。

## D.6.4 5 态 Gate 评审双签与弃权规则

Gate 评审状态机：`DRAFT → PENDING → APPROVED / REJECTED / ABSTAINED_TIMEOUT → DRAFT（整改后重发）`。

| 起始 | 触发 | 目标 | 期限 | 备注 |
|---|---|---|---|---|
| DRAFT | 提交评审 | PENDING | 3 个自然日 | 双方独立 |
| PENDING | 双方均通过 | APPROVED | — | 双方都提交前互不可见 |
| PENDING | 任一方驳回 | REJECTED | — | — |
| PENDING | 任一方超期未签 | ABSTAINED_TIMEOUT | 3 日 | 按主导方意见执行 |
| REJECTED | 整改后重新发起 | DRAFT | 第 3 轮起组长列席 | 第 5 轮超管介入 |
| 双 PM 不一致 → 双方产品组长仲裁 → 不一致 → 超管终裁 | | | | |

**关键约束**

- **互不可见**：双方都提交前，对方的 `decision` / `opinion` / `signedAt` 字段在 API 层强制过滤（详见 24 页 D 节 BR-GATE-04 API 实现）。
- **超期处理**：3 个自然日到期后，cron 扫描 `dueAt < now() AND signedAt IS NULL` → 状态转 `ABSTAINED_TIMEOUT`，按主导方（先提交方）的意见执行；若双方均未提交，整门 `ABSTAINED_TIMEOUT` 不影响阶段推进，但写"双超时"标记待超管复核。
- **第 3 轮升级**：连续第 3 次重发自动加挂双方产品组长为必列席角色；连续第 5 次升级超管直接终裁。

## D.6.5 奖金公式 4 算例交叉引用矩阵

奖金公式（成功奖金 = 奖金池基数 × 达成率阶梯 × 回款比例 × 双PM绩效系数）。以下 4 个算例作为所有相关页面的"必现"验收标准。

| 算例 | 必现页面 | 必现场景 |
|---|---|---|
| A：池 37.5 万 / 市场 13.2 万 / 研发 10.8 万 | 34 / 31 / 37 / 35 | 任何出现"成功奖金"数字的页面都必须能复算 |
| B：130% 达成 → 24.75 万 | 34 / 37 | 阶梯 1.2 档验证 |
| C：回款 70% → 阶梯 0.6 | 34 / 37 / 30 | 回款口径验证 |
| D：120% / 120.1% / 99.99% 端点 | 34 / 37 | **边界裁定必现**（100%–120% 含端点 →1.0；>120% →1.2；99.99% →0.8） |

**端点规则（算例 D 必背）**

- 达成率 ∈ [0%, 100%) → 阶梯 0.8（但 99.99% 仍按 0.8，因为未达 100% 端点）。
- 达成率 ∈ [100%, 120%] → 阶梯 1.0（端点含 100% 与 120%，即 ≤ 120% 都按 1.0）。
- 达成率 > 120% → 阶梯 1.2。
- 任何页面写出"成功奖金"金额时，必须能给出达成率输入值和当前使用的阶梯系数。

## D.6.6 跨页面联动 5 条守护规则

### 守护规则 1：需求变更未闭环阻断阶段出口（BR-GATE-07）

阶段跳转 API 必须先校验本阶段未闭环变更单数量 = 0，否则返回 40910 `BLOCKED_BY_OPEN_CHANGE`。

### 守护规则 2：在研项目 14 天场景定义复核倒计时（BR-PROD-04）

`project.status = IN_PROGRESS AND stage = CONCEPT` 时，catch-up 路径生成 14 天倒计时待办；超期升级组长（同时企微 + 待办红点）。

### 守护规则 3：连续 60 天无产出 → 停发津贴（BR-INC-11）

月度扫描 → 生成"待确认停发单" → 管理员确认 → 停发（写 `allowance / suspend` 审计）。连续 60 天的口径：连续 60 自然日 `workItem.owner = u AND status IN (DONE, ARCHIVED) AND updatedAt within window` 计数 = 0。

### 守护规则 4：共担 KPI 月度归集（BR-KPI-05）

次月第 5 工作日 18:00 截止；逾期第 1 天提醒组长，第 3 天升级超管，第 5 天自动关闭本期共担 KPI。

### 守护规则 5：Gate 评审要素 ⚠️ 项（BR-GATE-01b）

未填责任人和关闭期限禁止提交；逾期未关闭不允许进入下一 Gate（系统层硬校验）。
