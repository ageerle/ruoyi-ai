# 页级规格统一模板

> **用途**：本文件是开发说明书附录 D 的统一输出格式，所有 agent 必须按本模板产出每个页面的规格。
> **基线**：现有代码 `产品流程细化管理工具 2/src/App.jsx` + `ClosurePages.jsx` + `FinalRulesPages.jsx` + `server/server.mjs`（命名沿用）。
> **不重命名**：规格中的组件名 / 字段名 / API 路径必须与现有代码一致或明确标注「新增」。

---

## 每个页面的标准输出格式（7 节）

### 1. 页面元信息
- 编号 / 名称 / URL 路径（一级/子页）
- 主用角色 / 可见角色 / 优先级（P0–P4）
- 关联 BR-xxx 规则编号
- 现有实现：完整 / 部分（仅面板） / 仅有占位 / **新增**

### 2. 页面布局（基于现有代码）
- 区块顺序：顶栏 → 面包屑 → 主内容 → 操作按钮（如有）
- 主要组件名（**沿用现有命名**）：`<Frame>` / `<PageFrame>` / `<WorkflowCenter>` / `<StageConfirmPage>` / `<PerformancePage>` / 等
- 关键视觉元素：列表 / 卡片 / 弹窗 / 抽屉 / 表单 / 看板
- 数据范围 banner / 只读 banner / 错误 banner

### 3. 字段模型（每页一张表）
列：`字段名 | 类型 | 必填 | 取值/枚举 | 数据源 | 默认 | 校验`
- **【现状 vs v3 差距】** 单独列出 v3 要求但现状缺失的字段（红色标记 "🔴 缺失"）

### 4. API 接口清单
- **接口路径**：`METHOD /api/path`
- **用途**：一句话
- **请求体**：字段表（字段名 / 类型 / 必填）
- **响应体**：结构 + 字段说明
- **错误码**：可能的 4xxxx
- **权限要求**：角色 + 数据范围
- **审计写入**：`entityType` + `action`
- **【现状 vs v3 差距】** 标记缺失接口（🔴 缺失：应新增 POST /api/xxx）

### 5. 闭环剧本（6 环节）— **必须按 v3 完整 6 环节写**
| 环节 | 内容 |
|---|---|
| ① 发起 | 谁在哪个页面/接口触发，校验什么 |
| ② 处理 | 状态机流转，每步校验 + 入库 |
| ③ 审核 | 谁审 / 期限 / 审批意见结构 / 否决/通过的副作用 |
| ④ 结果 | 成功后状态变更 + 通知 + 落库字段 |
| ⑤ 记录 | 审计日志的 entityType / action / before / after |
| ⑥ 归档 | 软删除 / 状态终结 / 可追溯路径 |

### 6. 现状 vs v3 差距（**新增必填节**）
明确列出本页：
- v3 要求但现状缺失的字段（数量 + 列表）
- v3 要求但现状缺失的接口（数量 + 列表）
- v3 要求但现状未实现的状态机环节（数量 + 列表）
- 验收覆盖度（现状 X / v3 应有 Y 条 AC）

### 7. 验收用例（Given-When-Then，3-5 条）
例：
```
Given 当前用户为产品组长，所属组内有项目处于"概念阶段已就绪"
When 进入阶段确认页并提交阶段确认
Then 系统应发起五节点确认链（市场PM→研发PM→市场组长→研发组长→超管）
And 写入审计日志 entityType=stage_review, action=submit
And 在工作台投递给下一节点的签署任务
```
