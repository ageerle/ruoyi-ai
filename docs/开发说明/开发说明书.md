## 1. 项目背景与定位

面向单企业私有部署的中文 IPD（Integrated Product Development）产品工作平台。系统将**长期产品**、**具体 IPD 项目**、**六阶段 69 动作**、**双PM（市场PM + 研发PM）协同**、**跨角色审批**、**绩效核算**、**资料审计**串成一条可追溯业务链。

**目标用户**：熵基科技内部的市场PM、研发PM、市场组长、研发组长、超级管理员，以及免登录提交需求的外部/内部游客。

**部署形态**：Docker Compose 一键启动（web / api / postgres / redis / minio）；本机开发不装 Docker，用免安装二进制。

**核心信念**：**业务规则高于文档惯例，文档惯例高于系统实现**——v3 第 0 节硬约束 G-04。

### 2.2 v3 主 Prompt 写的目标栈（与 RuoYi-AI 不同，需替换）

| 层 | v3 指定 | 与 RuoYi-AI 差异 | 二开策略 |
|---|---|---|---|
| 前端 | React 18 + TS 5 + Ant Design 5 + Vite + React Router 6 + TanStack Query | Vben + element-plus-x → React + AntD | **保留 RuoYi 的 Vben + element-plus-x**，把 AntD 组件库风格替换为 element-plus-x 风格 |
| 状态 | Zustand + TanStack Query | RuoYi 用 Pinia | **保留 Pinia**，TanStack Query 改为对应 RuoYi 工具 |
| 后端 | NestJS 10 + Prisma | RuoYi Spring Boot + Langchain4j | **保留 Spring Boot**，NestJS 控制器层改写为 Spring 控制器；Prisma → MyBatis-Plus 或 JPA |
| 数据库 | PostgreSQL 15 | RuoYi MySQL 8.0 | **保留 MySQL 8**，所有 JSONB 字段改用 MySQL JSON 列 |
| 缓存/队列 | Redis 7 + BullMQ | RuoYi Redis | **保留 Redis**，BullMQ → Redisson DelayedQueue 或 XXL-Job |
| 文件 | MinIO（Docker） | RuoYi MinIO | **复用 MinIO**，抽象 StorageService 接口 |
| 认证 | JWT（Access 15min + Refresh 7d）+ 企微 OAuth | RuoYi Sa-Token + JWT | **复用 Sa-Token 双层**，企微 OAuth 一期 Mock |
| 定时任务 | BullMQ + cron | RuoYi 用 XXL-Job 或 Spring Scheduler | 沿用 RuoYi 方案 |

### 2.3 替换项的迁移检查清单

| v3 要求 | RuoYi-AI 默认 | 二开处理 |
|---|---|---|
| Prisma `REVOKE UPDATE/DELETE ON audit_logs FROM ipd_app` | MySQL 用户权限 | 用 MySQL `REVOKE UPDATE, DELETE ON ipd.audit_logs FROM 'ipd_app'@'%'` + `审计表只允许 INSERT` |
| TS-01b Redis 5.0（开发）/7.x（生产）版本差异 | RuoYi Redis 6/7 | 验证所有用到 Redis 命令的兼容性；本机开发 Redis 5.0.14.1 免安装版 |

| Hash 链审计 | 无现成组件 | 自实现 `AuditHashChainService`，每次写入计算 `SHA256(prevHash + JSON(本条))` |

## 3. 全局硬约束 11 条（**违反即返工**）

> 来源：`IPD系统_开发执行规则_AI必读.md` 第 2 节。每条都有界面/接口/测试层面的落地点。

| 编号 | 规则 | 落地点 |
|---|---|---|
| **G-01** | 业务闭环：所有流程必须有发起、处理、审核、结果、记录、归档六环节 | 任何流程页必须有出口按钮和归档区入口；不可有"完成后无操作"的死页 |
| **G-02** | 权限隔离：三层角色（超管/产品组长/普通PM）严格隔离；**编辑可自主，删除必须走申请审核** | 删除按钮全部跳转到"发起删除申请"，不做即时删除；权限不足不隐藏入口（禁用态 + Tooltip） |
| **G-03** | 审计留痕：新增/编辑/审核/驳回/删除/移交/参数修改/人员同步/登录凭证变更全部写审计；日志只追加、不可改、不可删 | 后端用 `@Audit()` 装饰器/切面，DB 层 `REVOKE UPDATE, DELETE`；前端不做"查看审计"按钮仅在系统管理显示 |
| **G-04** | 制度优先：本规则与主 Prompt v3 冲突时，以 v3 为准 | 第 7 节"已知待决项"列出的所有冲突均已按 v3 裁定 |
| **G-05** | 参数可配置：所有系数/阈值/期限/额度落库为参数表，**禁止硬编码** | 第 8 节参数表共 ~50 项，全部走 `system_configs` 表 + `ConfigService` 取值 |
| **G-06** | 无绝对化承诺：禁止"100% 闭环""无遗留疑问"文案；未知状态显式展示"待补充""未配置" | 文案审查清单；UI 走 `el-empty` 组件 + 方向性提示 |
| **G-07** | 中文界面：全中文，文案抽离 i18n，DB 文本字段预留多语言 JSONB 扩展，一期只填 `zh-CN` | 前端 `locales/zh-CN.ts`；后端 DB JSON 字段统一结构 `{"zh-CN": "...", "en-US": null}` |
| **G-08** | **涉钱参数必须可切换**（虽已裁定，仍禁止硬编码）：奖金池基数/销售额口径/绩效系数取值/系数定值主体/池分摊/上市锚点共 6 项已由 v3 裁定，仍必须实现为后台配置开关 | `bonus.poolBase` / `bonus.salesSource` / `bonus.performanceScoreStrategy` / `bonus.coefficientDecider` / `bonus.multiProjectSplit` / `bonus.launchAnchor` 6 个配置项 |
| **G-09** | 角色体系不扩展：仅普通PM/产品组长/超级管理员 + 游客；**不新增**「评审上级」「代理组长」「代审人」；V3.1"直接上级" = 产品组长 | 不提供"代理审批""委托"功能；离职交接由组长/超管代操作但不产生新角色 |
| **G-10** | 市场PM 视角优先：研发PM 主导阶段（开发/验证）**默认轻管**；界面只保留「完成状态 / 实际完成日期 / 备注」三个字段；**禁止加执行记录、SOP 强制展示、交付物校验** | 23 个轻管动作详情页只用 3 个输入框，**无附件上传按钮**；例外见 §5.4 |
| **G-11** | 数据库双账号分离：`DATABASE_URL` 用 `ipd_app`（非超级用户，运行时读写）；`DIRECT_URL` 用 `postgres`/迁移专用超级用户（仅迁移） | RuoYi-AI 用 MySQL：`jdbc:mysql://...?user=ipd_app`（运行时）+ 迁移专用账号（仅 flyway/liquibase） |
| **G-12** | 测试同步义务（DoD 硬规则）：凡 PR 改动数据访问路径（换 mapper 方法 / SQL 形态）、契约（字段名 / 键名 / 枚举 / 错误码 / 文案）、时间语义（时钟注入 / 窗口推演），必须**同 PR** 跑受影响测试类并同步修改测试；PR 描述列出「改动面 → 受影响测试类 → 全绿结果」 | 完整条款与判定标准见 `docs/ipd-系统说明/治理/工程DoD与测试纪律-20260908.md`；配套自动化：`ServiceBareClockGuardTest` 时钟白名单只减不增 + GRANT 登记件 CI 门禁（2026-09-08 owner 授权升格，勘误登记 log.md R11-续4） |

## 4. 术语表与文案红线

> 来源：v3 第 3.0 节术语表 + 开发铁律第 4 节。

### 4.1 必须使用 vs 禁止使用

| 必须使用 | 禁止使用 | 依据 |
|---|---|---|
| 深管动作 / 轻管动作 | 重点动作 / 普通动作 | 3.0 术语表 |
| 阻断性动作 | 必做动作 / 卡点 | 3.0 术语表 |
| 产品组长 | 直接上级 / 评审上级 / 代理组长 / 代审人 | **G-09** |
| 市场PM / 研发PM | 产品经理甲乙 / 主PM 副PM | 3.0 术语表 |
| 回款（达成率语境下） | 销售额 / 出库额 / 开票额 | **Q2 决策** |
| 项目绩效综合得分 | 季度考核分 | **Q3 决策** |
| L1–L5 能力等级 | 职级 / 评级分 | 与项目绩效得分严格区分（BR-KPI-08） |
| 双签 / 双签否决 | 会签 / 联审 | BR-GATE-03 |
| 待补充 / 未配置 | 暂无 / — / 空白 | **G-06** |

### 4.2 文案规则

- **主动语态**：按钮写"提交评审意见""发起删除申请""确认停发"
- **错误/空态写方向**：`暂无待办。从「我的项目」进入 IPD 流程开始执行深管动作。`
- **同流程同名**：按钮"提交评审意见" → 状态"待对方签署" → 提示"已提交，等待对方签署"
- **禁止绝对化**："100% 闭环""无遗留疑问""完全自动"
- **未知状态显式**：待补充 / 未配置 / 不适用

### 8.2 完整公式

```
奖金池        = 目标销售额 × 5% × 差异化系数（S=1.5/A=1.0/B=0.8）
达成率        = 上市后 6 个月实际回款 ÷ 目标销售额 × 100%
阶梯系数      = 匹配 bonus.achievementTiers（6 档区间制，按阈值从高到低逐档匹配）
绩效系数      = 匹配 bonus.performanceTiers（按综合得分）
贡献度        = 市场 40%–65% / 研发 35%–60%（和恒 100%，前端联动校验）
每人成功奖金  = 奖金池 × 阶梯系数 × 贡献度比例 × 绩效系数
综合得分      = 功能KPI × 60% + 共担KPI × 40%
项目绩效评定  = 自评 20% + 市场PM 所属组长 40% + 研发PM 所属组长 40%（和恒 100%）
津贴          = L1–L5 映射表（1000/1500/2000/2500/3000），评级锁定
多项目津贴    = 各项目津贴叠加 ≤ 个人当前评级额度 × 2
```

### 8.3 达成率阶梯（**禁止 `===` 与浮点容差**）

```js
// 按阈值从高到低逐档匹配，左闭右开
const tiers = [
  { threshold: 120,  multiplier: 1.2, inclusiveRight: false },  // r > 120
  { threshold: 100,  multiplier: 1.0, inclusiveRight: true },   // 100 ≤ r ≤ 120
  { threshold: 85,   multiplier: 0.8, inclusiveRight: false },  // 85 ≤ r < 100
  { threshold: 70,   multiplier: 0.6, inclusiveRight: false },
  { threshold: 50,   multiplier: 0.3, inclusiveRight: false },
  { threshold: 0,    multiplier: 0,   inclusiveRight: false }
];
function tierMultiplier(r) {
  for (const t of tiers) {
    if (t.inclusiveRight ? r >= t.threshold && r < next(t) : r >= t.threshold && r < next(t)) {
      return t.multiplier;
    }
  }
}
```

### 8.4 四个算例（P3 阶段必须手工核对通过）

**算例 A**：目标销售额 ¥500 万 / S 级系数 1.5 / 回款达成率 90% / 市场贡献 55% / 绩效系数 0.8
→ 奖金池 = 500 × 5% × 1.5 = **37.5 万**
→ 阶梯（85–99.99%）= 0.8
→ 市场PM = 37.5 × 0.8 × 55% × 0.8 = **13.2 万**
→ 研发PM = 37.5 × 0.8 × 45% × 0.8 = **10.8 万**

**算例 B**（验证 1.2 档）：达成率 130%
→ 阶梯 = 1.2
→ 市场PM = 37.5 × 1.2 × 55% × 1.0 = **24.75 万**

**算例 C**（验证回款口径）：目标 500 万，区间内回款 350 万
→ 达成率 = 70%
→ 阶梯 = 0.6

**算例 D**（验证 120% 端点）：
- 达成率 **120%** → 阶梯 **1.0**（含端点）→ 市场PM = 37.5 × 1.0 × 55% × 1.0 = **20.625 万**
- 达成率 **120.1%** → 阶梯 **1.2** → 市场PM = 37.5 × 1.2 × 55% × 1.0 = **24.75 万**
- 达成率 **99.99%** → 阶梯 **0.8**（校验 1.0 档下界为 100%，不含 99.99%）
